Page 07 / 10 — Building it yourself

Build It Yourself: A Toy Q-Learning and SARSA, Side by Side

Six stages: a tiny world small enough to reason about by hand, a shared learner shell, an off-policy learner, an on-policy learner, a run that reproduces page 4's divergence for real, and a bug you deliberately cause yourself.

Every name below (TinyStrategyWorld, OffPolicyLearner, _pending_action, and so on) is invented for this page and deliberately does not match q_learning_agent.py. The goal, same as every prior toy-build in this project's prerequisite sets, is to arrive at the same shape of solution independently, so the real file reads as familiar structure rather than new material when page 9 opens it.

Stage 1 — a tiny world with a genuine risky-shortcut-vs-safe-route contrast

The exact toy from page 4, made runnable. State 0 is the opening decision; state 1 is reached only by the risky choice; both terminate:

class TinyStrategyWorld:
    """
    State 0: opening decision.
      action 0 (BOX_NOW)  -> reward -12, done          (safe, known cost)
      action 1 (STRETCH)  -> reward  -1, state -> 1     (cheap now, risk later)
    State 1: reached only after STRETCH.
      action 0 (BOX)         -> reward  -8, done        (clean recovery)
      action 1 (OVERSTRETCH) -> reward -30, done        (the cliff)
    """
    N_ACTIONS = 2

    def reset(self):
        self._state = 0
        return self._state

    def legal_actions(self, state: int) -> list[int]:
        return [0, 1]   # both actions legal in both states, in this toy

    def step(self, action: int):
        if self._state == 0:
            if action == 0:
                return None, -12.0, True
            self._state = 1
            return 1, -1.0, False
        else:
            reward = -8.0 if action == 0 else -30.0
            return None, reward, True

Stage 2 — a shared TD-learner shell

A dict-based table (defaultdict pattern, matching what page 5's arithmetic already justified for a sparsely-visited state space), ε-greedy action selection respecting a supplied legal-action list, and page 3's linear decay schedule — sized for a toy that trains in thousands, not millions, of steps:

from collections import defaultdict
import numpy as np

class TDLearnerShell:
    def __init__(self, n_actions, alpha=0.5, gamma=1.0,
                 eps_start=1.0, eps_end=0.05, decay_steps=2_000):
        self.n_actions = n_actions
        self.alpha, self.gamma = alpha, gamma
        self.eps_start, self.eps_end, self.decay_steps = eps_start, eps_end, decay_steps
        self.epsilon = eps_start
        self._step = 0
        self.table = defaultdict(lambda: np.zeros(n_actions))

    def pick_action(self, state, legal, rng):
        if rng.random() < self.epsilon:
            return int(rng.choice(legal))
        q = self.table[state].copy()
        mask = np.full(self.n_actions, -np.inf)
        mask[legal] = 0
        return int(np.argmax(q + mask))

    def decay(self):
        self._step += 1
        step_size = (self.eps_start - self.eps_end) / self.decay_steps
        self.epsilon = max(self.eps_end, self.epsilon - step_size)

Stage 3 — OffPolicyLearner: page 2's target

class OffPolicyLearner(TDLearnerShell):
    def learn(self, state, action, reward, next_state, done, legal_next, rng):
        if done:
            target = reward
        else:
            q_next = self.table[next_state].copy()
            mask = np.full(self.n_actions, -np.inf)
            mask[legal_next] = 0
            target = reward + self.gamma * np.max(q_next + mask)
        td_error = target - self.table[state][action]
        self.table[state][action] += self.alpha * td_error
        self.decay()

Stage 4 — OnPolicyLearner: page 4's target, with the pre-commit mechanic

The real SARSAAgent has to know a' before it can compute this step's target — but the natural training loop only asks for the next action after stepping the environment. The fix, built here first in miniature: pick a' during learn(), stash it, and hand it back out on the very next call to pick_action:

class OnPolicyLearner(TDLearnerShell):
    def __init__(self, *args, **kwargs):
        super().__init__(*args, **kwargs)
        self._pending_action = None

    def pick_action(self, state, legal, rng):
        if self._pending_action is not None:
            action, self._pending_action = self._pending_action, None
            return action
        return super().pick_action(state, legal, rng)

    def learn(self, state, action, reward, next_state, done, legal_next, rng):
        if done:
            target = reward
        else:
            self._pending_action = super().pick_action(next_state, legal_next, rng)
            target = reward + self.gamma * self.table[next_state][self._pending_action]
        td_error = target - self.table[state][action]
        self.table[state][action] += self.alpha * td_error
        self.decay()

Stage 5 — run both, identical seeds, watch them diverge for real

def run_episodes(learner, world, n_episodes, seed):
    rng = np.random.default_rng(seed)
    for _ in range(n_episodes):
        state = world.reset()
        done = False
        while not done:
            legal = world.legal_actions(state)
            action = learner.pick_action(state, legal, rng)
            next_state, reward, done = world.step(action)
            legal_next = [] if done else world.legal_actions(next_state)
            learner.learn(state, action, reward, next_state, done, legal_next, rng)
            state = next_state

off_policy = OffPolicyLearner(TinyStrategyWorld.N_ACTIONS)
on_policy  = OnPolicyLearner(TinyStrategyWorld.N_ACTIONS)
world = TinyStrategyWorld()

run_episodes(off_policy, world, n_episodes=3000, seed=0)
run_episodes(on_policy,  world, n_episodes=3000, seed=0)

print("Off-policy Q(state 0):", off_policy.table[0])
print("On-policy  Q(state 0):", on_policy.table[0])
print("Off-policy prefers:", "STRETCH" if np.argmax(off_policy.table[0]) else "BOX_NOW")
print("On-policy  prefers:", "STRETCH" if np.argmax(on_policy.table[0]) else "BOX_NOW")

Confirm page 4's hand-worked trend actually holds up over thousands of steps, not just the four hand-run episodes: the off-policy learner's Q(0, STRETCH) should sit close to the true greedy-optimal value of −9, largely indifferent to the 5% exploration floor still occasionally sampling OVERSTRETCH. The on-policy learner's Q(0, STRETCH) should sit noticeably lower — still pulled toward a more cautious estimate by the real, nonzero chance its own future exploration lands on the cliff. Depending on the exact numbers, the on-policy learner may even end up preferring BOX_NOW outright, exactly the "more cautious" outcome page 4 described in the abstract.

Stage 6 — catch the leak

Deliberately reproduce the bug page 8 and page 9 name against the real SARSAAgent: forget to clear _pending_action between episodes. Comment out (or never implement) a reset() call between calls to world.reset() in the training loop, and run OnPolicyLearner for a few hundred episodes:

# Buggy loop: state resets, but the learner's pending action does not.
rng = np.random.default_rng(1)
buggy_learner = OnPolicyLearner(TinyStrategyWorld.N_ACTIONS)
for ep in range(500):
    state = world.reset()
    done = False
    while not done:
        legal = world.legal_actions(state)
        action = buggy_learner.pick_action(state, legal, rng)   # no reset() call anywhere
        next_state, reward, done = world.step(action)
        legal_next = [] if done else world.legal_actions(next_state)
        buggy_learner.learn(state, action, reward, next_state, done, legal_next, rng)
        state = next_state

In this particular toy the leak is easy to miss, because every episode always starts at state 0 and both actions are always legal — a stale _pending_action from the end of one episode gets silently returned as the first action of the next episode, applied to a completely different situation than the one it was actually chosen for. Print buggy_learner._pending_action right after each episode ends and watch it carry a non-None value across the reset boundary whenever the previous episode ended by reaching state 1 and picking an action there. In a toy this small the corrupted behaviour mostly just adds noise to the learned table; in the real environment (page 8, page 9), the same leak can apply a stale pre-committed action to an observation from an entirely different race scenario, since the real environment's states are far more varied than this toy's two.

That's the full toy pair: a world with a genuine risk-vs-safety contrast, a shared TD shell, off-policy and on-policy learners implementing exactly page 2 and page 4's update rules, a run that reproduces the hand-worked divergence at scale, and the specific on-policy bug class a reader who built _pending_action here will recognize immediately in the real code. Page 8 doesn't repeat this code — it names which piece of the real state design and reward shaping corresponds to what you just built.
