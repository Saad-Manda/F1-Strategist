Why this matters

In the previous reading, the agent chose an action and the environment responded. To debug that exchange, you must know which observation came before the action and which came after it. A clear transition record will later also provide the data that learning algorithms use.

Continue with our delivery chain: start at 0, move LEFT or RIGHT, and finish at 2. A move into 2 gives +5; every other move gives −1. We will trace the first RIGHT move before writing a loop.

One action, one response

Gymnasium is a Python library that gives environments a common interface. An interface is an agreed set of calls and returned values, so the same agent loop can work with different environments.

observation, info = env.reset()
# observation is 0 in our chain

action = policy(observation)
# policy returns RIGHT, encoded as 1

next_observation, reward, terminated, truncated, info = env.step(action)
# first RIGHT move: (1, -1.0, False, False, {"steps": 1})

env is the environment object. Calling its step method asks it to apply one action. Python unpacks the returned tuple into five named variables, in exactly this order. Reset gives two values; step gives five. Reset initializes a run and supplies the first observation without taking an action or awarding a step reward.

We will examine both ending flags in the next reading. For now, notice that they describe what happened after this action. They are not instructions for choosing the action.

Keep both sides of the transition

A transition is the change caused by one action, together with its returned results. Do not overwrite the old observation before saving it. The following record uses the same field names as the Python exercise:

before = observation
action = policy(before)
observation, reward, terminated, truncated, info = env.step(action)

record = dict(
    before=before,
    action=action,
    observation=observation,
    reward=float(reward),
    terminated=bool(terminated),
    truncated=bool(truncated),
    info=info,
)

The record's observation field is the returned, next observation. before preserves the observation used to choose the action. The conversions make the reward a Python floating-point number and the flags Python booleans; they do not change the event being recorded. A list of these dictionaries is a trace: a record of the episode's moves in order.

The second record starts where the first record ended. This continuity is a useful debugging check. After the second record, you stop the episode; its final observation is 2, not the 0 that a future reset will return.

Diagnostics are useful, but separate from the policy input

The chain returns a fresh info dictionary on each call, with the number of moves executed in the current episode. Reset returns {"steps": 0}. A later call must not mutate a dictionary already saved in the trace. Mutable observations, such as arrays, need the same care.

Our policy reads the observation, not info. Other environments may put hidden simulator details in diagnostic information. Giving those details to a policy would change what information the agent is allowed to use. The next lesson will distinguish the underlying state from its observation more carefully.

Common mistake: storing the running score as each record's reward. For RIGHT, RIGHT, the records must contain −1 and +5. A separate running total can be −1 after the first move and +4 after the second.

Recap and a self-check

Step consumes one action and returns the next observation, one reward, two ending flags and diagnostics. Store the old observation before stepping. A trace keeps transitions separate from accumulated scores and from the next episode's reset.

Self-check: LEFT from location 0 returns observation 0. What belongs in the record's before and observation fields?

Explanation: both are 0. The action is still LEFT, the reward is −1, and the step counter increases. Equal observations are a valid result; they do not justify dropping the record.
