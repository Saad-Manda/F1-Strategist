F1PettingZooEnv as a direct instantiation of the Parallel API

possible_agents = ["agent_0", ..., "agent_N"], per page 04. Each agent's observation is N_MULTI_OBS = 19 — Phase 6's own multi-car dimension (assumed background), unchanged: every agent still sees its own car's 19-dimensional state, not a joint observation of every car at once. reset() and step(actions: dict) both return per-agent dicts, exactly the shared surface page 04 set up generically. _extend_obs computes exactly Phase 6's own gap-ahead/gap-behind/position features, now recomputed per-agent inside a multi-agent wrapper rather than against Phase 6's fixed-script rivals.

The independent-learner training loop, against page 01's paradigm choice

One DuelingDoubleDQNAgent instance plays the role of agent_0, the learner — the only agent whose replay buffer is updated and whose weights actually change during training (learner.store(...) and learner.update() are called only for agent_0 inside the episode's step loop). Every other agent (agent_1, ...) is sampled fresh each episode from the CheckpointPool, with epsilon = 0.0 once page 05's fix is applied to the pool's seeding logic. This is page 01's "independent learners" paradigm exactly: no shared network, no centralized critic, each agent's own DQN (or, for the opponents, a frozen snapshot of one) acting purely on its own local 19-dimensional observation.

CheckpointPool's parameters, mapped to page 03's math

ParameterValueRole (page 03)
recency_bias0.7Probability of sampling from the most recent 20% of the pool — the practical approximation of favoring recent history over page 02's full running average
max_pool_size50A sliding window over fictitious-play history, not an unbounded archive — oldest checkpoint evicted on overflow
checkpoint_freq1000 episodesHow often a new snapshot is added to the pool during train_self_play

The page 05 fix is a concrete, required change to one specific line: pool.add(learner, episode=0)'s seeding call currently stores an untrained network and relies on the sampler's epsilon = 0.0 to make it "greedy" — per page 05, this needs to be replaced with either an explicitly stochastic seed (epsilon = 1.0) or, preferably, Phase 3's rule-based agents (assumed background), before any training run's early episodes are trustworthy.

Definition-of-Done items that exist because of pages 03–07

Several of the real plan's Definition-of-Done items are there specifically because of the mechanisms and findings this set spent several pages on, not because they're generic "does the feature work" checks:

  • Recency-bias sampling test (page 03) — confirms the pool's most-recent-20% slice is actually sampled roughly 70% of the time, not merely that sample() runs without error.
  • "Learner's mean finishing position < random agent's" (page 03's evaluation-trap argument) — the one Definition-of-Done item that evaluates the learner outside the self-play loop, precisely because a rising self-play reward curve on its own proves nothing about skill against an opponent the learner never trained against.
  • The bimodal pit-timing histogram (page 06's precondition) — the item that cannot pass at all until Phase 6's blocking constraint exists, independent of how well every other item on this list passes.
  • The analysis notebook's interpretation section (page 07) — should report the shuffled null-baseline comparison alongside the raw histogram, not the histogram alone.
