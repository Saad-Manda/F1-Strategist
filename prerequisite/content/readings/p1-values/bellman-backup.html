Why this matters

Returns relate neighboring decisions. If we know how valuable the successor situations are, we can calculate a current value from immediate reward plus discounted continuation. That calculation is a Bellman backup.

Derive the decomposition

The discounted return is G_t = r_t + γ r_(t+1) + γ² r_(t+2) + …. Factor one gamma out of all terms after the first. The remaining bracket is exactly the return from t+1:

G_t = r_t + γ [r_(t+1) + γ r_(t+2) + …] = r_t + γ G_(t+1)

Taking an expectation conditional on the state and first action gives Q^π(s,a) = E[r_t + γ V^π(S_(t+1)) | s,a], with zero continuation on true termination. This uses a sufficient state and the policy π for later choices. It is a relationship between expected values, not a rule for selecting the most favorable random outcome.

One deterministic backup

At B, FINISH returns 4 and enters terminal state Z, whose continuation value is 0. Its backup is 4 + γ × 0 = 4. From A, DIRECT has backup 3 + γ × 0 = 3; VIA has backup 1 + γ × 4. At gamma 1 that is 5; at gamma 0.5 it is 3.

A backup using provisional successor estimates produces a provisional current estimate. It need not equal the correct task value after just one pass. Planning algorithms later repeat or order backups appropriately.

Two possible successors

Now use a separate uncertain route with gamma 0.5. Probability 0.8 leads to reward 2 and a successor value 4. Probability 0.2 leads to reward −1 and a successor value 1. The backup is 0.8(2 + 0.5×4) + 0.2(−1 + 0.5×1) = 3.1, exactly the expectation calculated in lesson 1.4.

def outcome_backup(outcomes, gamma):
    # Each row: probability, reward, successor value, true termination.
    probabilities = [row[0] for row in outcomes]
    validate_distribution(probabilities)
    return sum(p * (reward + gamma * (0 if terminated else value))
               for p, reward, value, terminated in outcomes)

assert outcome_backup([(0.8, 2, 4, False), (0.2, -1, 1, False)], 0.5) == 3.1
assert outcome_backup([(1.0, 5, 999, True)], 1.0) == 5

The helper reuses the probability validator from lesson 1.4. In ordinary floating-point checks, use a small tolerance instead of exact equality when roundoff can matter. The terminal example deliberately supplies an irrelevant successor estimate 999: termination removes its continuation, not its reward.

Boundaries and assumptions

A truncation or batch cutoff can leave genuine future rewards. In that case a continuation estimate may remain appropriate even though this collector stops. The code's boolean is true termination, not a combined “stopped somehow” flag. Do not conflate them.

Gamma 1 is valid for the finite A/B task. For indefinitely continuing discounted backups, use gamma below 1 with bounded rewards; the optional depth page explains one convergence guarantee. Finite-horizon values may also need a remaining-decisions index.

Common mistake: adding the terminal reward a second time as the terminal state's value, or zeroing both reward and continuation.

A transition terminates with reward −7 and the table says next value 10. What is its backup?

−7. The terminal reward counts once and the continuation is zero, regardless of gamma.
