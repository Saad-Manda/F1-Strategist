How the course works

The sets are cumulative: each assumes every set above it and nothing later. Read top to bottom on a first pass, and jump straight to a phase only once the sets it lists under "Assumes" are behind you.

Every set has the same three parts, marked in the sidebar. Concepts build one continuous argument and are read in order, with the F1 examples inside them as illustration. Capstone is the hands-on page: you build a small toy version of the phase's technique yourself, one complication at a time, under names that deliberately do not match the real project. This project then maps the same ideas onto the real design and gives a reading guide to the phase's implementation plan. Terms from every set are collected in the glossary.

Labs. Where a set has labs, every page ends in one: a hand calculation or quiz checked in the page, or a notebook or code exercise in prerequisites/labs/, opened and checked with python -m labs from inside the prerequisites/ folder (see prerequisites/README.md). The capstone page is the brief for a longer staged build. Every set has labs.

Points. A page read is 1 point, a cold-open call 1, an in-page lab 3, a code lab 5, a capstone 10, a case closed 10, and a Pit Wall race within a second of the oracle 5 per mode. Every phase is built as a case: a mystery opened on its first page and closed on its last.

The sidebar marks a page as opened when you visit it and as finished when you reach its end, and ticks in-page labs as you complete them. That record lives in this browser only. Code labs are ticked by running python -m labs status and reloading.

Where things stand

Read before relying on these pages

Only Phase 0 of the project is implemented. Every phase's "Back to the plan" page is a reading guide to files that are planned, not yet present in src/.

Not covered yet

Phases 2, 7, and any phase after 9 have no prerequisite set here. A new set is a new phase folder plus one entry in assets/course.js.
