Further depth: why repetition can help

This reading is optional. Core practice already has everything needed to calculate the A/B values. Here we examine one reason repeated discounted backups can converge, and why that reason does not cover every problem.

A fixed point of an update is a value that the update leaves unchanged. A correct Bellman value satisfies its own backup equation, so it is a fixed point. Repeatedly applying a backup can approach that value when the operator shrinks differences.

One continuing state

Consider a state that always returns to itself with reward 1. At gamma 0.5, its value equation is v = 1 + 0.5v. Moving 0.5v to the left gives 0.5v=1, so the fixed point is 2.

Start with estimate v=0. Successive backups give 1, 1.5, 1.75 and 1.875. Their errors relative to 2 are 1, 0.5, 0.25 and 0.125 in magnitude. Each backup halves the error because the continuation is multiplied by gamma.

estimate = 0.0
trace = []
for _ in range(4):
    estimate = 1 + 0.5 * estimate
    trace.append(estimate)
assert trace == [1.0, 1.5, 1.75, 1.875]

The underscore is a loop variable whose value is unused. This code updates a known model's value; it is not a training experiment or a sampled gradient update.

The largest-error argument

Suppose two value tables differ by at most d at any state. A normalized probability-weighted average of their successor differences also has magnitude at most d. Multiplication by gamma makes the difference between their backups at most γd. Taking maxima over the same legal actions cannot enlarge that bound either: every candidate action score moved by at most γd.

For gamma below 1, this is a contraction: an update shrinks the largest difference by a factor less than one. In finite discounted MDPs with bounded rewards, this gives a unique fixed point and convergence of exact repeated Bellman updates. The same bound explains why gamma near 1 can require more iterations for a comparable error reduction.

The residual is the largest absolute difference between a table and one backup of it. Under these contraction assumptions, value error is bounded by residual divided by 1−γ. A residual of 0.01 at gamma 0.9 gives a bound of 0.1; at gamma 0.99 it gives 1. A small residual needs interpretation in the context of gamma.

Where this argument stops

At gamma 1 the factor does not shrink. In the continuing reward-1 example, backups grow 1, 2, 3 and so on, with no finite fixed point. A finite-horizon task at gamma 1 instead works backward from its known terminal horizon; the h index decreases until a boundary value is reached.

Approximate function updates, changing models, sampling errors and neural training are not the exact table operator used in this argument. Convergence of the ideal operator is not a general guarantee that a particular training run succeeds.

Common mistake: claiming “Bellman always converges” while omitting discount, finite-model and bounded-reward assumptions.

Does failure of this gamma-one contraction argument make the finite delivery task invalid?

No. A finite terminal or horizon boundary supports different reasoning. The argument's assumptions limit the proof, not all valid objectives.
