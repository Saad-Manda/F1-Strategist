Neural Networks in Four Steps: Forward Pass, Loss, Backward Pass, Update

Scoped tightly to what DuelingDQN.forward() and its training step actually do. No convolutions, no architecture survey, no loss functions this project doesn't use.

Scope note

This page teaches exactly four mechanics — a layer's forward computation, a loss, backpropagation, and a gradient-descent step — at the depth needed to read and trust dqn_agent.py. It is not a general deep-learning introduction, and it stops as soon as those four mechanics are covered.

A layer as a function

A linear layer computes y = Wx + b: a matrix multiply of the input vector x by a weight matrix W, plus a bias vector b. On its own this is just an affine function — stacking several of them would collapse back into one big affine function, which can't represent anything more expressive than a straight line through the input space. A nonlinearity after each linear layer is what prevents that collapse; this project uses ReLU, max(0, y), applied elementwise.

Traced to the real network's exact shape (Linear(16→128) → ReLU → Linear(128→128) → ReLU, the shared trunk of DuelingDQN): the 16 is Phase 1's normalized observation vector's dimension — nothing new is being invented here, this is the same 16 numbers page 08's discretization used, just fed to a different kind of consumer. The 128 hidden width is a design choice, not derived from anything; it just needs to be large enough for the network to represent the function it's trying to learn without being so large that it trains slower than necessary on a state space this small.

Worked forward pass on a tiny network

A network far smaller than the real one, small enough to run by hand: 2 inputs, 1 hidden layer of 2 units with ReLU, 1 output, no bias terms (to keep the arithmetic short):

W1 = [[ 1.0, -1.0], x = [2.0, 1.0] [0.5, 0.5]] h_pre = W1 · x = [1.0(2.0) + (-1.0)(1.0), 0.5(2.0) + 0.5(1.0)] = [2.0 - 1.0, 1.0 + 0.5] = [1.0, 1.5] h = ReLU(h_pre) = [max(0, 1.0), max(0, 1.5)] = [1.0, 1.5] W2 = [2.0, -1.0] (output layer, 2 -> 1) y = W2 · h = 2.0(1.0) + (-1.0)(1.5) = 2.0 - 1.5 = 0.5

Every step above is exactly what self.trunk(x) followed by one output head does in the real network, just at a size that fits on paper: a matrix multiply, a ReLU that zeroes out any negative pre-activation (here, nothing needed zeroing — both pre-activations happened to be positive), and a second matrix multiply into the output.

Loss: how wrong is the prediction, as one number

Given a prediction ŷ and a target y*, a loss function collapses "how wrong" into a single scalar to minimize. Mean-squared error: L = (ŷ − y*)². The real agent uses smooth L1 / Huber loss instead — quadratic for small errors, linear beyond |error| = 1 — for reasons page 08 covers once there's a concrete number to explain. For now, either one plays the same role: a differentiable scalar that's small when the prediction is close and large when it isn't.

DQN's specific case (developed fully on page 03 and after): ŷ = Q(s,a;θ), the network's current prediction; y* = target, the Bellman-derived TD target. The loss is exactly "how far is the current Q-value estimate from where the Bellman equation says it should be" — the same quantity Phase 4's δ measured, now expressed as a loss to be minimized by gradient descent rather than a nudge applied by hand to one table cell.

Backpropagation, at the level this project needs

Backpropagation computes ∂L/∂θ for every weight in θ — how much, and in which direction, nudging that one weight would change the loss — by applying the chain rule layer by layer, working backward from the output. This page states that fact and works one small piece of it by hand; it does not derive the full chain-rule proof for an arbitrary network, which the real project never needs to do since PyTorch's autograd computes it automatically.

One weight's gradient, worked on the tiny network above: take W2's first entry (the weight connecting hidden unit 1 to the output), currently 2.0. If the loss is L = (y − y*)² with y* = 0 (target) and y = 0.5 (this network's output, computed above):

∂L/∂y = 2(y - y*) = 2(0.5 - 0) = 1.0 ∂y/∂W2[0] = h[0] = 1.0 (y = W2[0]·h[0] + W2[1]·h[1], so ∂y/∂W2[0] = h[0]) ∂L/∂W2[0] = ∂L/∂y · ∂y/∂W2[0] = 1.0 · 1.0 = 1.0

Read directly: increasing W2[0] by a small amount would increase the loss (the gradient is positive), so a gradient-descent step should decrease W2[0] a little. That single number, 1.0, is exactly the kind of quantity backpropagation computes for every one of θ's entries — this page only carries the chain rule back one layer; the real network's trunk has several more, each contributing one more application of the same rule.

Gradient descent: the same nudge, computed automatically

The update rule: θ ← θ − lr · ∂L/∂θ, applied to every entry of θ at once. This is worth reading side by side with Phase 4's tabular update, because it is the same idea, not a different one:

Tabular (Phase 4)Function approximation (this page)
Q(s,a) ← Q(s,a) + α·δθ ← θ − lr·∂L/∂θ
One number, one table cellEvery entry of a (possibly large) weight vector
δ: how wrong the current cell's estimate is∂L/∂θ: how wrong the current prediction is, and how each weight contributed to that
α: how far one sampled transition can move one celllr: how far one sampled transition (via its gradient) can move every weight

This is the page's payoff line, and it's worth carrying forward explicitly: DQN is not a different learning idea from Phase 4's Q-learning. It is the exact same "nudge toward a Bellman-derived target" update rule, with the table cell replaced by a gradient step on a shared function. Every technique from page 03 onward exists to make that gradient step trainable in practice, not to change what it's trying to accomplish.

Adam, named but not derived

Plain gradient descent uses the same step size (lr) for every weight, every step. Adam is an optimizer that adapts the effective step size per-parameter based on that parameter's recent gradient history, converging faster and more reliably in practice for the kind of noisy, mini-batch gradients this project computes. Nothing here derives Adam's update rule — it's enough to recognize torch.optim.Adam(self.online_net.parameters(), lr=lr) in the code walkthrough (page 11) as "gradient descent, with a per-parameter adaptive step size," and to know that lr still means the same thing it meant in the table above — the base step size Adam adapts around.
