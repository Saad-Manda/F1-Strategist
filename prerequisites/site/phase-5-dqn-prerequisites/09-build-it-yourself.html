Build It Yourself: A Toy DQN, One Technique at a Time

Six stages: a small world with a continuous observation and an exact answer to measure against, a bare network learner, then a target network and replay, then the dueling head and the Double DQN target, then prioritized replay, and last a bug you plant yourself.

Every name below (StintWorld, ToyLearner, SplitNet, RankedMemory and the rest) is invented for this page and deliberately does not match dqn_agent.py. The aim is the same as in every earlier toy build: arrive at the same shape of solution yourself, so the real file reads as familiar when page 11 opens it. You need numpy and torch. Put everything in one file. Each training run takes a minute or two on a laptop CPU.

Stage 0 — a world with a continuous observation, and its exact answer

A 12-lap stint with one decision per lap: carry on, or fit fresh tyres. The observation is two decimals, the fraction of the race left and the tyre wear. Wear is the kind of quantity Phase 4 had to cut into bins. Here it goes to the network as it is.

Reference snippet (a last-resort hint: the lab uses a different world and different names) 
import numpy as np
import torch
import torch.nn as nn
import torch.nn.functional as F

torch.set_num_threads(1)   # tiny networks run faster on one thread

class StintWorld:
    """
    A 12-lap stint. Observation: [laps_left / 12, wear], both in [0, 1].
      action 0 (PUSH_ON):      cost 1 + 6 * wear^2, then wear grows by 0.08
      action 1 (FRESH_RUBBER): cost 3 flat, then wear returns to 0
    Reward is minus the cost. FRESH_RUBBER is illegal on brand-new tyres.
    """
    LAPS, N_ACTIONS, STEP = 12, 2, 0.08

    def reset(self):
        self.lap, self.age = 0, 0
        return self._obs()

    def _obs(self):
        return np.array([(self.LAPS - self.lap) / self.LAPS, self.age * self.STEP], dtype=np.float32)

    def legal(self):
        return np.array([True, self.age > 0])

    def step(self, action):
        wear = self.age * self.STEP
        if action == 0:
            reward, self.age = -(1.0 + 6.0 * wear ** 2), self.age + 1
        else:
            reward, self.age = -3.0, 0
        self.lap += 1
        return self._obs(), reward, self.lap == self.LAPS

Underneath, the world is small enough to solve exactly with the backward induction from Phase 3.5 page 02. This is the ruler for every stage that follows:

Reference snippet (a last-resort hint: the lab uses a different world and different names) 
def exact_q():
    """Backward induction over (lap, tyre age)."""
    W = StintWorld
    q = np.full((W.LAPS + 1, W.LAPS + 1, 2), -np.inf)
    v = np.zeros((W.LAPS + 1, W.LAPS + 1))
    for lap in range(W.LAPS - 1, -1, -1):
        for age in range(lap + 1):
            wear = age * W.STEP
            q[lap, age, 0] = -(1.0 + 6.0 * wear ** 2) + v[lap + 1, age + 1]
            if age > 0:
                q[lap, age, 1] = -3.0 + v[lap + 1, 0]
            v[lap, age] = q[lap, age].max()
    return q

q_star = exact_q()
print(q_star[0, 0].max())     # -16.9216

Check: the best total is −16.92, reached by fitting fresh tyres twice, for example on the 4th and the 9th lap (three two-stop plans tie for best). The next-best plan stops one lap early and scores −17.11. A learner that reports −17.11 has found a good race and missed the best one by one lap of timing, which is the same kind of miss Phase 4 page 06 was about.

Stage 1 — a bare network learner

First the network: page 02's layers, two inputs in, one Q-value per action out.

Reference snippet (a last-resort hint: the lab uses a different world and different names) 
class PlainNet(nn.Module):
    def __init__(self, n_obs=2, n_actions=2, width=32):
        super().__init__()
        self.body = nn.Sequential(nn.Linear(n_obs, width), nn.ReLU(),
                                  nn.Linear(width, width), nn.ReLU(),
                                  nn.Linear(width, n_actions))

    def forward(self, x):
        return self.body(x)

Then the learner. It is written once, with three switches that later stages turn on: replay, lag_rate and decoupled. With all three off, it trains on the single transition that just happened, and it builds the target from the same network it is training. That is the naive idea page 03 opened with.

Reference snippet (a last-resort hint: the lab uses a different world and different names) 
class ToyLearner:
    def __init__(self, net_cls, seed, lr=1e-3, replay=None, batch=32, lag_rate=None,
                 decoupled=False, warmup=200, eps_steps=6000):
        torch.manual_seed(seed)
        self.rng = np.random.default_rng(seed)
        self.live = net_cls()
        self.lagged = net_cls() if lag_rate is not None else self.live   # off: one network does both jobs
        if lag_rate is not None:
            self.lagged.load_state_dict(self.live.state_dict())
        self.opt = torch.optim.Adam(self.live.parameters(), lr=lr)
        self.replay, self.batch, self.lag_rate, self.decoupled = replay, batch, lag_rate, decoupled
        self.warmup, self.eps, self.eps_end, self.eps_steps = warmup, 1.0, 0.05, eps_steps
        self.losses = []

    def act(self, obs, legal, greedy=False):
        if not greedy and self.rng.random() < self.eps:
            return int(self.rng.choice(np.flatnonzero(legal)))
        with torch.no_grad():
            q = self.live(torch.as_tensor(obs).unsqueeze(0))[0].numpy().copy()
        q[~legal] = -np.inf
        return int(np.argmax(q))

    def learn(self, transition):
        self.eps = max(self.eps_end, self.eps - (1.0 - self.eps_end) / self.eps_steps)
        if self.replay is None:
            rows, idx, weight = [transition], None, np.ones(1)
        else:
            self.replay.push(transition)
            if len(self.replay) < self.warmup:
                return
            rows, idx, weight = self.replay.draw(self.batch)

        obs  = torch.as_tensor(np.array([r[0] for r in rows]))
        act  = torch.as_tensor(np.array([r[1] for r in rows]), dtype=torch.int64)
        rew  = torch.as_tensor(np.array([r[2] for r in rows]), dtype=torch.float32)
        nxt  = torch.as_tensor(np.array([r[3] for r in rows]))
        done = torch.as_tensor(np.array([r[4] for r in rows]), dtype=torch.float32)
        legal_next = torch.as_tensor(np.array([r[5] for r in rows]))
        weight = torch.as_tensor(weight, dtype=torch.float32)

        guess = self.live(obs).gather(1, act.unsqueeze(1)).squeeze(1)
        with torch.no_grad():
            if self.decoupled:      # live network picks, lagged network scores
                pick = self.live(nxt).masked_fill(~legal_next, -torch.inf).argmax(dim=1)
                future = self.lagged(nxt).gather(1, pick.unsqueeze(1)).squeeze(1)
            else:                   # one network picks and scores
                future = self.lagged(nxt).masked_fill(~legal_next, -torch.inf).max(dim=1).values
            goal = rew + (1.0 - done) * future

        loss = (weight * F.smooth_l1_loss(guess, goal, reduction="none")).mean()
        self.opt.zero_grad()
        loss.backward()
        self.opt.step()
        self.losses.append(loss.item())

        if idx is not None:
            self.replay.reprioritise(idx, (goal - guess).detach().numpy())
        if self.lag_rate is not None:
            with torch.no_grad():
                for slow, fast in zip(self.lagged.parameters(), self.live.parameters()):
                    slow.mul_(1.0 - self.lag_rate).add_(self.lag_rate * fast)

Three lines carry ideas from earlier pages. goal = rew + (1.0 - done) * future is page 06's terminal cut-off. Both masked_fill calls are the masking rule. The closing loop is page 03's soft update. A training loop and a report finish the stage:

Reference snippet (a last-resort hint: the lab uses a different world and different names) 
def train(learner, episodes=1500):
    world = StintWorld()
    for _ in range(episodes):
        obs, done = world.reset(), False
        while not done:
            action = learner.act(obs, world.legal())
            nxt, reward, done = world.step(action)
            learner.learn((obs, action, reward, nxt, done, world.legal()))
            obs = nxt
    return learner

def report(learner):
    """Greedy race total, worst Q error over every reachable state, and how steady the loss was."""
    world = StintWorld()
    obs, done, total = world.reset(), False, 0.0
    while not done:
        obs, reward, done = world.step(learner.act(obs, world.legal(), greedy=True))
        total += reward
    worst = 0.0
    for lap in range(world.LAPS):
        for age in range(lap + 1):
            o = torch.tensor([[(world.LAPS - lap) / world.LAPS, age * world.STEP]], dtype=torch.float32)
            with torch.no_grad():
                q = learner.live(o)[0].numpy()
            for a in range(2):
                if np.isfinite(q_star[lap, age, a]):
                    worst = max(worst, abs(q[a] - q_star[lap, age, a]))
    tail = np.array(learner.losses[-2000:])
    return round(total, 2), round(float(worst), 2), round(float(tail.mean()), 4), round(float(tail.std()), 4)

for seed in (0, 1, 2):
    print("stage 1", report(train(ToyLearner(PlainNet, seed))))

What to expect. In the runs used to check this page, two of the three seeds found the best race (−16.92) and one settled on −17.11. So the bare version is not hopeless on a world this small, and you should not expect it to blow up. Look at the last two numbers instead. Over the final 2,000 updates the loss averaged 0.004 to 0.008, and its spread was 0.014 to 0.046, several times its own average. That is a learner being pulled around by whichever lap it saw last, and chasing a target that moves with every step.

Stage 2 — a lagged copy and a memory

Add page 04's minimal buffer: fixed size, overwrite the oldest, sample uniformly.

Reference snippet (a last-resort hint: the lab uses a different world and different names) 
class RingMemory:
    def __init__(self, capacity, rng):
        self.capacity, self.rng, self.items, self.pos = capacity, rng, [], 0

    def push(self, item):
        if len(self.items) < self.capacity:
            self.items.append(item)
        else:
            self.items[self.pos] = item
        self.pos = (self.pos + 1) % self.capacity

    def draw(self, n):
        idx = self.rng.integers(len(self.items), size=n)
        return [self.items[i] for i in idx], idx, np.ones(n)

    def reprioritise(self, idx, errors):
        pass                      # a uniform memory has no priorities to update

    def __len__(self):
        return len(self.items)

for seed in (0, 1, 2):
    memory = RingMemory(5000, np.random.default_rng(seed))
    print("stage 2", report(train(ToyLearner(PlainNet, seed, replay=memory, lag_rate=0.01))))

What to expect. The race totals look much the same as stage 1: two seeds at −16.92, one at −17.11. The loss does not. Its spread over the final 2,000 updates fell to 0.002 to 0.003, around a tenth of stage 1's, and it now sits below its own average. This is what the target network and the replay buffer buy: steadier training. On a world this small, steadier training does not show up as a better race. On a 16-number observation and 52 laps, it is the difference between converging and not.

Stage 3 — two heads, and a decoupled target

Page 05's network: a shared body, one head for the state's worth, one for each action's edge over the average, combined with the mean subtracted.

Reference snippet (a last-resort hint: the lab uses a different world and different names) 
class SplitNet(nn.Module):
    def __init__(self, n_obs=2, n_actions=2, width=32):
        super().__init__()
        self.body = nn.Sequential(nn.Linear(n_obs, width), nn.ReLU(),
                                  nn.Linear(width, width), nn.ReLU())
        self.worth = nn.Linear(width, 1)
        self.edge = nn.Linear(width, n_actions)

    def forward(self, x):
        h = self.body(x)
        edge = self.edge(h)
        return self.worth(h) + edge - edge.mean(dim=-1, keepdim=True)

for seed in (0, 1, 2):
    memory = RingMemory(5000, np.random.default_rng(seed))
    learner = ToyLearner(SplitNet, seed, replay=memory, lag_rate=0.01, decoupled=True)
    print("stage 3", report(train(learner)))

Setting decoupled=True switches the target to page 06's form. Find the two branches in learn() and confirm that the only difference is which network is inside the argmax.

What to expect. The learner still solves the world: two seeds at −16.92 and one at −17.11 in the checking runs, with a loss as steady as stage 2's. The worst Q error over every reachable state came out between 1.4 and 3.0. That sounds large against a best total of −16.92, and it is worth understanding why it is not alarming. The worst case is always a state the trained policy never visits, such as twelve laps on one set of tyres. The network has seen almost no data there. Its values are accurate where the data is.

Two checks to add yourself. Feed any batch through SplitNet and confirm that edge - edge.mean(...) averages to zero across the actions in every row. Then add 10 to both of the edge head's biases and confirm the Q-values do not change: the mean subtraction absorbs any shift of the edges. Last, add 10 to the worth head's bias and subtract 10 from both edge biases. Without the mean subtraction that trade would leave every Q-value as it was, which is page 05's degeneracy. With it, every Q-value rises by exactly 10: the trade is no longer free, so the split between the two heads is pinned.

Stage 4 — a memory that ranks

Page 07's sum tree in one flat array. It has the same four methods as RingMemory, so the learner needs no changes. draw now returns real weights and reprioritise does real work.

Reference snippet (a last-resort hint: the lab uses a different world and different names) 
class RankedMemory:
    """Sum tree in one array: node k has children 2k+1 and 2k+2; the last `capacity` nodes are leaves."""

    def __init__(self, capacity, rng, alpha=0.6, beta=0.4, double_exponent_bug=False):
        self.capacity, self.rng, self.alpha, self.beta = capacity, rng, alpha, beta
        self.bug = double_exponent_bug
        self.tree = np.zeros(2 * capacity - 1)
        self.items, self.pos, self.size = [None] * capacity, 0, 0

    def _set_leaf(self, i, value):
        k = i + self.capacity - 1
        change = value - self.tree[k]
        self.tree[k] = value
        while k > 0:
            k = (k - 1) // 2
            self.tree[k] += change

    def push(self, item):
        top = self.tree[self.capacity - 1:].max()      # leaves already hold p ** alpha
        if self.bug:
            leaf = max(top, 1.0) ** self.alpha         # stage 5: the exponent applied a second time
        else:
            leaf = top if top > 0 else 1.0
        self.items[self.pos] = item
        self._set_leaf(self.pos, leaf)
        self.pos = (self.pos + 1) % self.capacity
        self.size = min(self.size + 1, self.capacity)

    def _find(self, mass):
        k = 0
        while k < self.capacity - 1:
            left = 2 * k + 1
            if mass <= self.tree[left]:
                k = left
            else:
                mass -= self.tree[left]
                k = left + 1
        return k - (self.capacity - 1)

    def draw(self, n):
        total = self.tree[0]
        edges = np.linspace(0.0, total, n + 1)
        idx = np.array([self._find(self.rng.uniform(edges[j], edges[j + 1])) for j in range(n)])
        idx = np.minimum(idx, self.size - 1)
        prob = self.tree[idx + self.capacity - 1] / total
        weight = (self.size * prob) ** (-self.beta)
        return [self.items[i] for i in idx], idx, weight / weight.max()

    def reprioritise(self, idx, errors):
        for i, e in zip(idx, errors):
            self._set_leaf(int(i), (abs(float(e)) + 1e-6) ** self.alpha)

    def __len__(self):
        return self.size

Check the tree by hand first. Build RankedMemory(4, rng), push four items, and call _set_leaf to give the leaves 3, 1, 4, 2. Print tree and compare it with page 07's diagram: [10, 4, 6, 3, 1, 4, 2]. Then confirm _find(6.5) returns 2.

Then test the promise. Fill a memory with 1,000 transitions, 31 of them "rare" with |δ| = 8 and the rest "routine" with |δ| = 0.5, and count how often the rare ones turn up:

Reference snippet (a last-resort hint: the lab uses a different world and different names) 
for name, memory in (("uniform", RingMemory(1024, np.random.default_rng(0))),
                     ("ranked", RankedMemory(1024, np.random.default_rng(0)))):
    for i in range(1000):
        memory.push(("rare" if i % 33 == 0 else "routine",))
    memory.reprioritise(np.arange(1000), [8.0 if i % 33 == 0 else 0.5 for i in range(1000)])

The checking run printed 0.030 for the uniform memory and 0.148 for the ranked one. The rare transitions are 3.1% of the buffer and 14.8% of the batches, close to five times as often. That matches what page 07's formula predicts for these numbers: 31 × 3.482 / (31 × 3.482 + 969 × 0.660) = 14.4%.

Stage 5 — plant the recorded bug

Turn on double_exponent_bug=True. It reproduces the fault page 07 described: reading a leaf that already holds p^α and raising it to α again. Look at the leaves directly:

Reference snippet (a last-resort hint: the lab uses a different world and different names) 
for bug in (False, True):
    memory = RankedMemory(8, np.random.default_rng(0), double_exponent_bug=bug)
    for i in range(4):
        memory.push((i,))
    memory.reprioritise(np.arange(4), [8.0, 0.5, 0.5, 0.5])
    memory.push(("new",))
    print(bug, np.round(memory.tree[7:], 3))
False [3.482 0.66 0.66 0.66 3.482 0. 0. 0. ] new item stored at the current maximum True [3.482 0.66 0.66 0.66 2.114 0. 0. 0. ] new item stored at 3.482 ^ 0.6

Now change the four errors to [0.2, 0.1, 0.1, 0.1] and run it again. The correct version stores the new item at 0.381, the current maximum. The buggy version stores it at 1.0, more than twice the maximum, because of the max(top, 1.0) floor. So the bug has no fixed direction. When errors are large, new transitions are under-sampled. When errors are small, as they are late in training, new transitions are over-sampled.

Then train with the bug switched on, exactly as in stage 4. In the checking runs all three seeds still reported −16.92. Nothing in the final result reveals the fault. This is the most useful thing the stage teaches: some bugs in a replay buffer never show in a reward curve, and can only be caught by a test that inspects the buffer itself.
