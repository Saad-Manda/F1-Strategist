Double DQN: Removing a Bias Vanilla DQN Doesn't Know It Has

Taking the maximum of several uncertain numbers gives an answer that is too high on average. Vanilla DQN does exactly that inside every target. The fix changes which network chooses and which network scores.

The vanilla target, restated

Page 03 left the target as r + γ·max_a' Q(s',a';θ⁻). Read the max as two jobs done by one network: the target network chooses which next action looks best, and the same target network scores how good that action is. Nothing has gone wrong yet. The problem appears once you remember that every one of those Q-values is an estimate with some error in it.

Why a max over noisy estimates runs high

Suppose three next actions all have a true value of exactly 5. The network has not converged, so each estimate is off by +1 or −1, each with probability one half, independently of the others. The true value of the best action is 5. What does max report?

Each estimate is either 4 or 6. Three estimates give 2 × 2 × 2 = 8 equally likely cases. max = 4 only when all three came out low: 1 case of 8 max = 6 in every other case: 7 cases of 8 E[max] = (1/8)(4) + (7/8)(6) = 0.5 + 5.25 = 5.75 true value of the best action: 5.00 what max reports on average: 5.75 → bias of +0.75

No single estimate is biased. Each one averages to exactly 5. The bias comes from the max itself, because max always picks whichever estimate happened to land high, and it then reports that same lucky number as the value. This is called maximization bias. It has nothing to do with neural networks: the tabular max_a' in Phase 4 page 02 has it too. It matters more here for two reasons. A network's errors are larger and last longer than a table cell's, and the dueling network on page 05 scores six actions at once, so there are more chances for one of them to land high.

Why a small bias does not stay small

The inflated number does not stay in one place. It becomes part of the target for the state before it, whose inflated estimate becomes part of the target for the state before that. With γ = 1 and 52 laps, an optimism of a fraction of a second per lap can add up along the whole chain. And the bias is not even across actions: it is largest where estimates are least certain, which is exactly the rarely tried actions. For this project those are the pit stops.

The fix: one network chooses, another scores

Keep two sets of estimates with independent errors. Let estimator A choose the action, and read that action's value from estimator B. Rerun the same example:

A picks the action whose A-estimate is highest. Call it a*. B's estimate of a* is 4 or 6 with probability one half each, because B's error does not depend on anything A did. E[ B(a*) ] = (1/2)(4) + (1/2)(6) = 5.00 → bias of 0

A still tends to pick an action it overrates. That no longer matters, because A's overrated number is never used as the value. B's number is used, and B has no reason to be high on that particular action.

Double DQN applies this with the two networks the agent already has. The online network θ chooses. The target network θ⁻ scores.

Only the first row differs, and only by which weights sit inside the argmax. In code that is three lines: run the online network on s', take its argmax, and use that index to read one value out of the target network's output. This is what the real plan means when it calls Double DQN a "3-line change".

An honest limit

The worked example assumed A and B have independent errors. The online and target networks do not. Page 03 showed the target network is a slowly updated copy of the online one, so their errors overlap. Double DQN therefore reduces the bias and does not remove it. It can also tip slightly the other way and underestimate. Both are accepted, because a small error in either direction does far less harm than a steady push upward that feeds on itself.

Masking has to happen inside the choice

Phase 4 page 03 restricted exploration to legal actions, and Phase 4 page 02 restricted the tabular max the same way. The rule carries over unchanged, and it attaches to the choosing step: the online network's values for illegal next actions are set to −∞ before the argmax. A network outputs a number for every action whether it is legal or not, and the number for an action that never occurs in training is never corrected by any target. If one of those meaningless numbers wins the argmax, the target is built from an action the car could not have taken.

This is also why each stored transition carries the legal-action mask of the next state. The mask is needed when the transition is replayed, which may be thousands of steps after the environment has moved on.

The terminal cut-off

On the last lap there is no next state, so there is nothing to bootstrap from. The target is just r. Phase 4's table handled this with an if. A network trains on a batch of transitions at once, so the same rule is written as arithmetic:

target = r + γ · Q(s',a*;θ⁻) · (1 − done) done = 0 → target = r + γ·Q(s',a*;θ⁻) the usual bootstrapped target done = 1 → target = r the future term is multiplied away

Leaving this factor out is a quiet bug. The network would be asked to add a "value after the race" that it invents from an observation with zero laps remaining, and that invented number would leak backward into every earlier lap. The terminal transitions are the only targets that contain no estimate at all, so they are the anchor the whole chain of bootstrapped values hangs from.

The whole target, on a batch of three

The real agent computes 64 targets at a time. Three are enough to see every case. Take three actions instead of six to keep it short, γ = 1, and these numbers for each transition's next state:

Row 1 choose with online: argmax [−40, −38, −45] = action 1 score with target: Q(s',1;θ⁻) = −42 target = −5 + (−42)(1 − 0) = −47 (vanilla would use max [−41, −42, −44] = −41, giving −46: one unit more optimistic) Row 2 mask, then choose: argmax [−30, −∞, −35] = action 0 score with target: Q(s',0;θ⁻) = −31 target = −6 + (−31)(1 − 0) = −37 (without the mask: action 1, scored −20, target −26, built on an illegal move) Row 3 done = 1, so the future term is multiplied by 0 target = −4 + (anything)(1 − 1) = −4

Each row's loss then compares its target with Q(s,a;θ) for the action that was actually taken. The network outputs a value for every action in every row, a block of numbers with one row per transition and one column per action. Picking out "the column for the action taken, row by row" is the operation PyTorch calls gather. The same operation reads Q(s',a*;θ⁻) out of the target network's block. When page 11 points at two gather calls, these are the two.

Why this combination needs so much care

Three ingredients are now in use together: a function approximator (page 01), bootstrapping (a target built from the learner's own estimates), and off-policy learning (the max, and replaying old data). Sutton and Barto call this combination the deadly triad, because any two of the three are safe and all three together can make value estimates grow without limit. Phase 4's table had the last two and was safe. The target network, the replay buffer and Double DQN do not remove any ingredient. Each one weakens a way the three reinforce one another.
