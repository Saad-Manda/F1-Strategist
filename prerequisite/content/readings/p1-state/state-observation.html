Why this matters

The delivery chain reported its location. That was enough to predict what a RIGHT move would do. Now imagine the same robot also has a battery. Two robots can stand at location 1 while only one has enough charge to move. A location sensor alone no longer describes everything that affects the next transition.

The state is the situation used by the environment's rules. An observation is the information supplied to the agent. They can coincide, as in the simple chain, but the words describe different jobs. The simulator can store variables that the policy is never allowed to see.

The policy receives observation 1 in both rows. A function of that observation alone cannot tell which row applies. Increasing the size of the policy does not supply the missing battery measurement.

A state need not be a list of every simulator variable. A parcel's decorative color can be omitted when it never affects movement, rewards or available actions. Conversely, a small state can be insufficient if it omits one consequential variable. We want a sufficient description of the decision, not the longest possible record.

A tiny experiment with hidden information

Your next browser lab makes the same problem smaller. A switch has a mode, 0 or 1. FLIP toggles it and gives reward 0. CLAIM ends the task, giving −1 in mode 0 and +1 in mode 1. A broken sensor always reports 0.

def broken_observation(mode):
    return 0

def claim_reward(mode):
    return 1 if mode == 1 else -1

assert broken_observation(0) == broken_observation(1)
assert claim_reward(0) != claim_reward(1)

Starting in mode 0, CLAIM produces −1. FLIP followed by CLAIM produces 0 and +1. The final CLAIM was preceded by the same broken observation in both runs. The differing reward is evidence that the sensor aliases two relevant states: it maps distinct situations to one representation.

This example's modes are part of the simulator state; observation 0 is merely the broken sensor's output. A valid observation can be inside its declared space and still be inadequate for a decision. Interface validity and information sufficiency are separate questions.

Recap and self-check

Common mistake: calling the observation “the full state” without checking what the transition and reward rules depend on. Inspect two histories leading to the same observation and apply the same action. Different predictable outcomes can reveal omitted information.

Does remembering the most recent reward always repair the sensor?

No. FLIP gives reward 0 in both modes, so that reward does not identify the mode. A useful memory must preserve information that actually distinguishes the relevant situations.
