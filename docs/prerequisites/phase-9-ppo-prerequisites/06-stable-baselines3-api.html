Page 06 / 12 — Library mechanics, taught generically

Stable-Baselines3 and sb3-contrib's API Surface

Taught generically first, per this set's standing pattern, so "this project, formalized" (page 10) is a direct instantiation rather than new API surface.

VecEnv: why PPO trains against several environments at once

SB3 trains against a vectorized environment — n_envs copies running in lockstep, where a single step() call advances all of them and returns stacked arrays of observations, rewards, and done-flags. This follows directly from page 04's on-policy constraint: PPO needs a fresh, diverse batch of rollout data before every update (old data goes stale the moment the policy has changed, unlike Phase 5's replay buffer), and running several environment copies in parallel is the standard way to collect a large, diverse batch quickly without an off-policy buffer to fall back on.

Two implementations of the same interface: DummyVecEnv steps every copy sequentially inside one process — simple, no serialization needed to communicate between copies. SubprocVecEnv runs each copy in its own OS process and steps them genuinely in parallel — faster only when a single environment step is expensive enough that the added process/inter-process-communication overhead pays for itself. Which one this project should actually use is a specific, load-bearing question — deferred to page 07.

The rollout-buffer arithmetic

n_steps, n_envs, batch_size, and n_epochs relate in a fixed way worth working through numerically, using the real plan's own values:

n_steps = 256 (per env, per update) n_envs = 4 transitions collected per update = n_steps × n_envs = 256 × 4 = 1024 batch_size = 64 minibatches per update = 1024 / 64 = 16 (must divide evenly) n_epochs = 10 → each of the 16 minibatches is used for 10 separate gradient steps before the next rollout of 1024 transitions is collected

batch_size must divide n_steps × n_envs evenly, or SB3 raises a configuration error rather than silently dropping leftover transitions.

The .learn() / .predict() shape

model.learn(total_timesteps=...) internally alternates two phases, repeated until the timestep budget is exhausted: a rollout phase (run the current policy across all n_envs copies for n_steps, storing observations, actions, rewards, log-probabilities, and value estimates as it goes), and an update phase (compute GAE per page 03 over the collected rollout, then run n_epochs of clipped-objective gradient steps per page 04 over minibatches of it). This one method call encapsulates the entire pages 01–04 derivation chain — precisely what page 05 said a library buys: nobody calling .learn() has to get GAE's backward recursion or the clip's minibatch-epoch interaction right themselves. model.predict(obs, deterministic=...) is the acting side: sample (or, if deterministic=True, take the mode of) the current policy's action distribution for a given observation.

Action masking via sb3-contrib's MaskablePPO

Masking invalid actions is not a new concept here — the reader already knows from Phase 1/4 background why actions that would be illegal (like pitting again immediately after just pitting) must be masked out before an agent can choose among them. What's new is only the mechanism SB3 expects: wrap the base environment with ActionMasker(env, mask_fn), where mask_fn is a callable that returns a boolean array over the action space. MaskablePPO then applies that mask to the policy's output before sampling — zeroing out invalid actions' probability mass and renormalizing — rather than sampling freely and rejecting invalid draws after the fact. This matters for page 04's math: it guarantees the log-probabilities used in the ratio r_t(θ) are always computed over the valid-action subset only, so an action that happened to be invalid at collection time never distorts the ratio for a policy update.

Logging

tensorboard_log=... is SB3's built-in equivalent of whatever logging Phase 4/5's from-scratch training loops hand-rolled for tracking episode reward, loss, and entropy over time — one configuration line, not a new topic to learn.
