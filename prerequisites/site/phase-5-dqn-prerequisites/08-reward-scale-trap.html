Phase 5 · Page 08 · The reward-scale trap

The Reward-Scale Trap

Every safeguard that keeps a network's training stable also limits how far one update can move it. Ask that network for outputs near −5,000 and it gets there slowly, quietly, and with no error message.

Your call · a flat reward curve

A DQN trains on rewards of minus the lap time: about −95 a lap for 52 laps, so true values near −4,940. A fresh network outputs about 0. After a few hundred races nothing has errored and the loss is falling, but the race reward is flat.

What is most likely?

The numbers

A fresh network's weights are small random numbers, so its outputs are small too. A fresh copy of this project's network, on observations in the 0-to-1 range, gave outputs averaging −0.02, none further from zero than 0.11. Before it can say anything about strategy it must learn to output numbers about 5,000 from where it starts, accurate to about a second: a pit stop costs about 18 s, and good and bad calls differ by a few seconds.

Three safeguards, each a speed limit

Huber loss (page 02's choice) is ½e² for an error |e| ≤ 1 and |e| − ½ beyond. Its slope, the push on the prediction, never exceeds 1:

error e squared error's slope 2e Huber's slope 0.5 1 0.5 250 500 1 5,000 10,000 1

One early batch with a 10,000 push would throw the weights far off; Huber caps it. But an error of 250 and one of 5,000 now push equally. Gradient clipping scales the whole gradient down when its norm exceeds 10: a norm of 40 is multiplied by 0.25. Adam divides each weight's gradient by its recent typical size, so each weight moves by roughly the learning rate, 0.001, per step at most. A larger error buys no larger step from any of the three.

A fourth limit: the target starts near zero too

The target network starts as a copy of the same fresh network, so the first targets are one lap's reward plus about 0: about −95. Once the online network has learned "about −95", the target network follows slowly, and only then do targets reach about −190, a lap's worth at a time. Only the last lap's target has no estimate in it; every other value is passed backward through 52 laps by a copy that is slow by design.

The reveal · flat reward, falling loss

You calledno call made
The numbers sayStill travelling

Nothing explodes, because every safeguard exists to stop an explosion. The loss falls, because the network is getting better at its own slowly moving targets. The reward stays flat, because outputs still thousands from the truth can't rank calls that differ by a few seconds.

That looks the same on a reward curve as a real bug. The first check is the size of the network's outputs against the size the true values must have: an average Q-value moving steadily toward −4,940 is a network still travelling; a flat one far from it is broken.

The fix: change the scale of the reward

Train on the centred reward −(lap_time − base_pace), as Phase 4 did. Per-lap rewards fall from about −95 to about −5, and true values from about −4,940 to about −250:

uncentred centred distance from a fresh network: ≈ 4,940 ≈ 250 a 5-second strategy difference: 0.1% of the 2% of the output's size output's size

The speed limits still apply, over a twentieth of the distance. Centring changes no decision: every race has the same number of laps, so subtracting a constant from every lap moves every strategy's total by the same amount (Phase 1 page 03 proves it). Reported race times are always the true ones, read from info["lap_time"].

Phase 4 met the same −5,000 in a table, where each cell starts at whatever you write in it. A network has no cells, so no per-state starting value. Setting the final layer's bias to −5,000 by hand moves every output by the same amount, the right idea at the wrong end: the rewards, targets and errors stay their original size. The original DQN paper (Mnih and colleagues, Human-level control through deep reinforcement learning, 2015) handled the problem from the other side, by limiting rewards and errors to between −1 and 1.

Did the champion learn the scale?

The champion trained on centred rewards. At the start line it expects 225.94 s to the flag if it stays out, where its own strategy averages 232.20 s: about 6 s, under 3%, from the truth, and its calls rank correctly, as page 05 found. This is the third row of the table in the deep dive at most, and its strategy is 0.28 s from the optimum. It isn't the trap.

Evidence so farRuled out: the reward scale. The champion's start value is within 3% of the truth and its calls rank correctly. Every suspect in the network and its training is cleared, and the stops are still there. Next: build the learner, and look at how it is evaluated.
