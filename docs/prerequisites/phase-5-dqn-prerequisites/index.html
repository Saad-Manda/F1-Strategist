Phase 5 Dueling Double DQN Prerequisites

Everything — and only what — you need to build the Dueling Double DQN agent with prioritized experience replay described in phase-5-dueling-double-dqn.md, assuming you already have the Phase 1, Phase 3.5, and Phase 4 prerequisite sets and nothing more.

Why this phase is different from the one before it

Phase 4 page 05 already named the wall tabular methods hit: a Q-table needs a finite number of discrete states, and no binning scheme is fine enough to represent the optimal policy without exploding past what a fixed training budget can visit. Phase 4 page 06 then showed that wall isn't hypothetical — the real plan's first tire_age binning scheme was coarse enough to erase the exact decision the DP oracle could tell apart.

Phase 5 doesn't fix the binning. It removes the table. Q(s,a) stops being a lookup and becomes a function Q(s,a;θ) that a neural network computes — so two states that would never have shared a table cell can still be recognized as "similar" and share what's been learned about them. Everything else carries over unchanged: the Bellman target, the TD-error idea, even the ε-greedy exploration schedule from Phase 4 page 03. Only how the number gets stored and updated changes, and this set exists to make that change concrete rather than magical.

Scope, precisely

This set teaches value-based deep RL exactly as the real plan uses it: a small MLP replacing the Q-table, the two instabilities that come with training a network online (a moving target, correlated data) and their standard fixes (a target network, an experience replay buffer), and the three specific techniques the real agent layers on top — the dueling architecture, Double DQN, and prioritized experience replay (PER) — plus the reward-scale trap the project's own audit already flags as the most likely reason this phase looks broken when it isn't. It does not cover multi-car states, rival modeling, self-play, or anything from Phase 6 onward, even as a preview, and it does not turn into a general deep-learning course — the neural-network primer on page 1 covers exactly the mechanics DQN needs and stops there.

How this folder teaches the implementation half

Page 9 has you build a small toy DQN agent in your own names, deliberately not matching dqn_agent.py, and stage it the same way the real agent is layered: a plain toy DQN first (built to visibly misbehave), then a target network and replay buffer, then the dueling head and Double DQN's decoupled target, then a small prioritized replay buffer swapped in for the uniform one — including reproducing, and then fixing, the exact PER bug recorded against the real plan. Only page 10 names which piece of the real network shape and hyperparameters corresponds to what you built, and only page 11 walks the real files themselves.

How to use this alongside the Phase 5 plan

Read pages 1–8 once, in order — they build one continuous argument, from "why a table stops working" through the neural-network mechanics needed to replace it, the two instabilities training one online creates, the three techniques the real agent adds on top, and the one numerical trap that makes all of it look broken if skipped. Page 9 is hands-on: build the staged toy agent yourself and let the PER bug actually skew a run before reading about it in the abstract. Page 10 then re-derives the same concepts using nothing but this project's actual network shape, hyperparameters, and recorded gotchas — the abstractions from pages 1–8 should stop feeling abstract at that point. Page 11 is the closest thing to a line-by-line reading guide for dqn_agent.py itself. Keep page 12 open as a reference while you work.
