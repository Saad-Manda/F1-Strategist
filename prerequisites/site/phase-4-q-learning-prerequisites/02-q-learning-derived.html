Q-Learning: The Update Rule, Derived and Hand-Run

Page 01's update with one choice made: the target assumes the best call comes next, whatever the learner does.

Your call · lap 8, in training

The learner stayed out on lap 8. On lap 9 it explores: it boxes for A, a call its own table rates as poor. Now it updates lap 8.

Lap 8's target uses which value for lap 9?

The full update

Q(s, a) ← Q(s, a) + α [ r + γ · max_a′ Q(s′, a′) − Q(s, a) ] \______________________/ target

This is page 01's form with target = r + γ · max_a′ Q(s′, a′), the max taken over the next state's legal calls. The learner's code works in rewards, reward = −lap time, so the best call is the largest value; the oracle worked in time and took the smallest. The same calls win either way.

Why the max: off-policy

The target assumes the best call follows, whatever the learner does next. While it explores, it will sometimes do something else, and the update ignores that. Learning about one policy (the greedy one) from data made by another (the exploring one) is called off-policy. α sets how far one lap moves a cell, as on page 01. γ stays at 1, as in every phase: a race has a fixed number of laps, so a lap-40 second counts the same as a lap-5 one.

Work it: a 3-state toy by hand

Two states, s1 and s2, a terminal state, and two calls in each:

s1, a0 → r = −1, next = s2 s1, a1 → r = −3, terminal s2, a0 → r = −1, terminal s2, a1 → r = −2, terminal

Backward induction solves it at once: Q*(s2, a0) = −1, Q*(s1, a0) = −2, Q*(s1, a1) = −3. Q-learning gets four sampled transitions instead, with α = 0.5, γ = 1, every cell starting at 0:

#Sampled transitionTargetδCellNew value
1(s1, a0, r=−1, s2)−1 + max(0, 0) = −1−1Q(s1,a0)0 + 0.5(−1) = −0.5
2(s2, a0, r=−1, terminal)−1−1Q(s2,a0)0 + 0.5(−1) = −0.5
3(s1, a1, r=−3, terminal)−3−3Q(s1,a1)0 + 0.5(−3) = −1.5
4(s1, a0, r=−1, s2)−1 + max(−0.5, 0) = −1−1 − (−0.5) = −0.5Q(s1,a0)−0.5 + 0.5(−0.5) = −0.75

Every cell moves toward its true value without reaching it: four steps set the trend, not the answer. And step 4's max picked the untouched Q(s2, a1) = 0 over the updated −0.5, because nothing has pulled it down yet. A table that starts at 0 when every reward is negative is optimistic: calls it hasn't tried look best. Page 03 shows that optimism doing some of the exploring.

Deep diveConvergence: what is promised, and what isn't70 words

Q-learning provably converges to Q* if every state-action pair is visited infinitely often and α shrinks over time at the right rate. With a fixed α, as in this project's plan, the table ends up hovering near Q* rather than on it. That is one reason the Learner's gap wobbles from checkpoint to checkpoint. Nothing promises speed: only that enough visits get there. That is the theory behind the real plan's 10,000-race runs.

Evidence so farQ-learning's target is the lap time plus the best value the table holds for the next state. Every cell is only as good as the cells it borrows from. Next: is the coarse learner exploring enough?

The Q-learning update, two ways

First run four updates by hand, on the page's toy with a different sequence of transitions. Then write the update as two small functions and reproduce the page's table exactly, including the two cases that are easy to get wrong: the last transition of an episode, and a next state where some actions are illegal.

Warm-up, on paper · the page's toy, a different four transitions

Same toy as the worked example, same settings (α = 0.5, γ = 1, every cell starting at 0), but the transitions arrive in this order. Enter the value of the updated cell after each one.

Worked solution for the warm-up

1. Q(s2,a1) = 0 + 0.5(−2 − 0) = −1. 2. Target −1 + max(0, −1) = −1; Q(s1,a0) = −0.5. 3. Q(s2,a0) = 0 + 0.5(−1) = −0.5. 4. Target −1 + max(−0.5, −1) = −1.5; δ = −1; Q(s1,a0) = −0.5 + 0.5(−1) = −1.0.

The true value is Q*(s1,a0) = −2. After two visits this order has reached −1.0 and the page's order −0.75, because here the cells of s2 were corrected before s1 looked at them the second time.
