The Reward-Scale Trap: Why This Phase Can Look Like "Training But Not Learning"

Every safeguard that keeps a network's training stable also limits how far one update can move it. Ask that network for outputs near −5,000 and it gets there slowly, quietly, and with no error message.

The numbers

reward per lap: about −95 (minus the lap time, in seconds) laps: 52 discount: γ = 1 true Q-values early in the race: about −95 × 52 ≈ −4,940 a freshly built network's output: about 0

The last line is a property of how networks start. Their initial weights are small random numbers, so their initial outputs are small too. A fresh copy of this project's network, given observations in the normal 0-to-1 range, produced outputs averaging −0.02, and none further from zero than 0.11. Before the network can say anything about strategy, it has to learn to output numbers about 5,000 away from where it starts.

The strategy itself lives in much smaller numbers. A pit stop costs roughly 18 seconds, and fresh tyres win that time back gradually over the laps that follow. The difference between a good and a bad decision is a few seconds. So the network has to produce outputs near −4,940 that are accurate to about a second, which is one part in several thousand.

Three safeguards, each one a speed limit

The real training step has three mechanisms that stop a single bad batch from wrecking the weights. Each is sensible. Each also caps how much one update can do.

Huber loss

Page 02 named the loss the agent uses, smooth L1 or Huber loss, and left the reason for this page. For an error e = prediction − target:

Huber(e) = ½·e² when |e| ≤ 1 (behaves like squared error) = |e| − ½ when |e| > 1 (grows in a straight line) slope of the loss, which is the size of the push on the prediction: error e squared error: 2e Huber 0.5 1 0.5 250 500 1 5,000 10,000 1

Under squared error, a prediction that is off by 5,000 produces a gradient of 10,000. One such batch, early on, throws the weights far from anywhere useful. Huber caps the push at 1 however large the error is. That is the stability it was chosen for. Now read the last two rows again: an error of 250 and an error of 5,000 produce the same push. The network gets no extra urgency from being twenty times further away.

Gradient clipping

After backpropagation, the gradients for all the weights form one long list of numbers. Its overall size is its norm: the square root of the sum of the squares. The real agent clips that norm to 10. If the norm comes out larger, every gradient is scaled down by the same factor so that the norm is exactly 10:

norm of this batch's gradient: 40 limit: 10 every gradient is multiplied by 10 / 40 = 0.25 The direction of the update is unchanged. Only its length is cut.

This is a second guard against one unusual batch. It is also a second cap on how far one batch can move the weights.

Adam's step size

Page 02 described Adam as gradient descent with a step size adapted per weight. The adaptation divides each weight's gradient by that weight's recent typical gradient size. The practical result is that each weight moves by roughly the learning rate per step at most, here 0.001, whether its gradient is large or small. A larger error does not buy a proportionally larger step.

A fourth limit: the target starts near zero too

The target is not −4,940 from the first update. It is r + γ·Q(s',a*;θ⁻) (page 06), and the target network starts as a copy of the same fresh network, so it also outputs about zero. The first targets are therefore about −95: one lap's reward, plus nothing. Once the online network has learned "about −95", the target network has to follow it (page 03's slow Polyak update), and only then do targets move to about −190, and so on, a lap's worth at a time. Only the last lap of the race has a target with no estimate in it. Every other value is built by passing that information backward through 52 laps, through a target network that is slow by design.

Why this fails quietly

Put the four limits together. Nothing explodes, because every mechanism above exists to prevent an explosion. The loss can even fall, because the network is getting better at predicting its own slowly moving targets. Episode reward stays flat, because a network whose outputs are still hundreds or thousands away from the truth cannot yet rank "pit now" against "stay out" when the two differ by a few seconds.

A training run in this state and a training run with a real bug look the same on a reward curve. The first thing to check is the scale of the network's outputs against the scale the true values must have.

What you seeWhat it suggests
Reward flat. Average Q-value moving steadily toward the expected scale.Still travelling. The algorithm is working and has a long way to go.
Reward flat. Average Q-value flat and far from the expected scale.Something is broken: no updates are happening, or the targets are wrong.

Average Q-value far past the expected scale and still growing.Runaway estimates. Look at the target computation: the terminal cut-off, the masking, and the target network (page 06).

Why Phase 4's first instinct does not transfer

Phase 4 page 08 met the same −5,000 problem in a table, where each cell starts at whatever value you write into it. A network has no cells. Its output at a state is whatever its shared weights happen to produce, so there is no way to set a starting value state by state. One global knob does exist: the final layer's bias could be set to −5,000 by hand. That moves every output by the same amount, which is the same idea as the fix below, applied at the wrong end. It leaves the rewards, the targets and the errors at their original size.

The fix: change the scale of the reward

The fix is the one Phase 4 used, for the same reason. Train on the centred reward −(lap_time − base_pace). Per-lap rewards fall from about −95 to about −5, and true Q-values from about −4,940 to about −250.

uncentred centred distance from a fresh network: ≈ 4,940 ≈ 250 a 5-second strategy difference: 0.1% of the 2% of the output's size output's size

The speed limits are all still in force. There is now a twentieth of the distance to cover under them, and the differences that decide the strategy are no longer a tiny ripple on a very large number.

Centring does not change which policy is best. Every race has the same fixed number of laps T, so subtracting a constant c from every lap's reward changes every policy's total by the same c × T. Adding the same amount to every option never changes which one is largest. Phase 1 page 03 has the full proof. Reported race times are always the true, uncentred ones, read from info["lap_time"]. Centring changes what the network trains on and nothing that is reported.

The general lesson

A mechanism that makes training stable can make a scale problem invisible. A loud failure gets fixed the same afternoon. A quiet one costs days of tuning hyperparameters that were never the problem. Before reading anything into a flat reward curve, compare two numbers: the size of the outputs the network is producing, and the size the true values must have.
