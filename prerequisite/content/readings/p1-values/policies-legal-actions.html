Why this matters

A policy specifies what the agent does with the information it has. To calculate its expected outcome, we need its action probabilities and the set of actions it is actually allowed to take.

A deterministic policy always chooses one action in a given state. A stochastic policy gives a probability distribution over actions. Stochastic describes randomized choices; it does not necessarily mean the environment itself is random.

Specify a small policy

Our next practice world has a state A with two legal choices. DIRECT terminates for reward 3. VIA gives reward 1 and moves to B; B has one action, FINISH, which terminates for reward 4. A third stored entry has value 99 but corresponds to an illegal action.

At A, a policy might choose DIRECT half the time and VIA half the time. Write π(a | s) for the probability that policy π (pi) chooses action a given state s. The probability row is [0.5, 0.5, 0]. At B, FINISH has probability 1.

The action space describes representable action labels; a mask describes which of them are legal in the current situation. For A, [True, True, False] permits the first two labels and excludes the third. The policy must give illegal actions zero probability and sum to 1 over the legal ones.

Choose among legal actions before maximizing

def greedy_probabilities(values, legal):
    if len(values) != len(legal) or not any(legal):
        raise ValueError("matching arrays and a legal action required")
    best = max(q for q, allowed in zip(values, legal) if allowed)
    winners = [i for i, (q, allowed) in enumerate(zip(values, legal))
               if allowed and q == best]
    return [1 / len(winners) if i in winners else 0.0
            for i in range(len(values))]

assert greedy_probabilities([3, 5, 99], [True, True, False]) == [0, 1, 0]
assert greedy_probabilities([3, 3, 99], [True, True, False]) == [0.5, 0.5, 0]

This illustrative helper splits exact ties uniformly. A deterministic tie rule, such as choosing the first tied legal action, is also possible if documented. Floating-point near-ties need an explicit tolerance convention; this helper uses exact equality. Later exploration lessons introduce additional sampling rules.

The helper assumes finite numerical values. Production input validation must reject infinities, missing entries and mismatched shapes. If the mask allows nothing, a policy cannot select a legitimate action; fix or define the task's fallback instead of hiding the error in a maximum over an empty set.

A mask is part of the contract

A known constraint can be enforced by excluding an action before choice. A penalty changes the reward for taking an action. They are not interchangeable: a penalty may leave the action representable and executable, while a mask tells a compatible agent to avoid it.

Gymnasium's action space alone does not encode every state-dependent constraint. Its Taxi tutorial supplies an action mask through info. Other agents can use a separate method; the F1 application explains that project convention. Always identify how the chosen agent obtains and applies masks.

Common mistake: removing the illegal entry for a greedy maximum but leaving positive policy probability on it. Evaluation and sampling must respect the same legal set.

Can [0.4, 0.4, 0.2] be silently renormalized after excluding the illegal third action?

The practice contract rejects it. It claims an invalid policy, so fix the row deliberately rather than silently changing its meaning.
