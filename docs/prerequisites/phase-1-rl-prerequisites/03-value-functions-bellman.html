Value Functions and the Bellman Equations

"How good is this situation?" — the question nearly every RL algorithm is, in one form or another, trying to answer.

State-value function, V

V^π(s) is the expected return if you start in state s and follow policy π from then on:

V^π(s) = E_π[ G_t | S_t = s ]

In plain language: "if I'm in this situation and I play according to my current strategy, how much total (discounted) reward do I expect to get from here to the end?"

This project

V^π(s) for a given race state — say, lap 30 of 52, on a 14-lap-old MEDIUM, dry — is the expected total remaining -lap_time if the current policy is followed from here on. A better policy has a higher (less negative) value in every state, because it means less total time to the finish.

Action-value function, Q

Q^π(s, a) is one step more specific: the expected return if you take action a right now, in state s, and then follow π for everything after:

Q^π(s, a) = E_π[ G_t | S_t = s, A_t = a ]

The difference matters in practice: V tells you how good a situation is, but doesn't by itself tell you what to do — for that you need to compare Q(s, a) across all the actions available in s and pick the best one. This is exactly why Phases 4 and 5 (Q-learning and DQN) both learn Q, not V — a table or network of Q-values directly gives you a policy for free: "pick the action with the highest Q-value in this state," subject to the action mask.

This project

Q^π(s, PIT_SOFT) at lap 30 on old mediums, versus Q^π(s, STAY_OUT) in that same state, is precisely the comparison a race engineer makes in their head when deciding whether now is the moment to pit. Learning good Q-values is learning race strategy.

The Bellman equations

The Bellman equations are the recursive relationship that makes value functions tractable: the value of a state can be written in terms of the immediate reward plus the (discounted) value of wherever you end up next. It isn't an extra assumption bolted onto the return — it falls straight out of the definition of G_t from page 2, by peeling off the first term.

Deriving it, step by step

Start from the definition of the return, and split off the very first reward:

G_t = R_(t+1) + γ·R_(t+2) + γ²·R_(t+3) + ... = R_(t+1) + γ·( R_(t+2) + γ·R_(t+3) + ... ) = R_(t+1) + γ·G_(t+1)

The bracketed term is just G_(t+1) — the return starting one step later — factored out by γ. That's the whole trick: the return at any point is this step's reward plus γ times the return from the next state on. Now take the expectation of both sides, conditioned on being in state s and taking action a, which by definition is Q(s,a):

Q^π(s,a) = E[ R_(t+1) + γ·G_(t+1) | S_t=s, A_t=a ] = E[ R_(t+1) | s,a ] + γ·E[ G_(t+1) | s,a ]

The first term is just the expected immediate reward. The second term — the expected return from wherever you land next — is, by definition, the expected value of V^π(s') (or Q^π(s',a') under the next action) over the distribution of next states P(s'|s,a). Writing that out explicitly, and switching to the optimal policy (which always picks max_a' rather than averaging over π), gives the Bellman optimality equation:

Q*(s, a) = Σ_s' P(s'|s,a) · [ R(s,a,s') + γ · max_a' Q*(s', a') ]

Nothing here is a new axiom — it's the return's own recursive structure, made explicit. This equation is the engine behind almost everything downstream:

  • Q-learning makes a table of Q-values satisfy this equation approximately, by repeatedly nudging Q(s,a) toward R + γ·max Q(s',a') from observed transitions. (How to do that is Phase 4's job, not this page's — the point here is only that the equation itself comes from page 2's return, not from anywhere new.)
  • Dynamic programming (Phase 3.5's oracle) solves this equation exactly, working backward from the last lap of the race — because with a finite, fixed-length episode and a known transition model, the true optimal Q-values can be computed directly, no learning or sampling required.
This project

This is exactly why the plan insists compute_lap_time(rng=None) must return the exact expected lap time, not an approximation — the DP oracle needs a noise-free version of the transition model to plug directly into this equation.

Why γ = 1 doesn't break the Bellman equation here

The γ·V(s') term is what makes value "recursive" — it lets an agent reason about consequences several steps into the future without simulating the whole future explicitly. Setting γ = 1 (page 2) simply removes the discount: future lap-time reward counts exactly as much as the current lap's. Nothing about the equation breaks, because the episode is guaranteed finite, so the recursion still bottoms out at the last lap rather than running forever.

Why this matters for reward scale

The plan's reward centring step is a direct, practical consequence of this page.

This project

With γ = 1 and roughly 52 laps at around −95 reward per lap, V^π and Q^π for a typical state are around −5,000 — the value function literally sums up all remaining rewards to the end of the episode, undiscounted. A Q-table initialized at zero, or a freshly initialized neural network centred near zero, then has to learn a value ~5,000 away from its starting point before it represents anything useful — slow, and in practice a common reason a training run "runs but doesn't learn anything."

The centring proof, worked with numbers

Claim: subtracting a fixed constant c from every step's reward shifts every policy's return by exactly the same amount, so it cannot change which policy is optimal. Take two candidate policies over the same fixed-length, T = 52-lap race, with per-lap rewards centred around, say, −93 for the better policy and −97 for the worse one (a 4-second-per-lap difference, accumulated):

Return(better) ≈ 52 × (−93) = −4,836 Return(worse) ≈ 52 × (−97) = −5,044 Difference: Return(better) − Return(worse) = 208 (better wins, by 208)

Now centre every reward by subtracting c = base_pace = 92 from each step before summing — reward_offset="base_pace" in the plan:

Return(better)_centred ≈ 52 × (−93 − (−92)) = 52 × (−1) = −52 Return(worse)_centred ≈ 52 × (−97 − (−92)) = 52 × (−5) = −260 Difference: Return(better)_centred − Return(worse)_centred = 208

The absolute numbers shrank by roughly two orders of magnitude — exactly what makes them learnable — but the difference between the two policies, 208 in both cases, is untouched. That's the whole proof: subtracting the same constant c from every one of T equal-length episodes' rewards shifts every policy's return by exactly c × T, a term that doesn't depend on which policy you're looking at, so it cancels out of every comparison between policies. The ranking — and therefore the optimal policy — is provably unchanged. This is why the plan notes it needs no potential function and isn't reward shaping in the technical sense: it's a fixed additive constant, not something that depends on the state, and info["lap_time"] is defined to always report the true, uncentred value regardless of this setting.
