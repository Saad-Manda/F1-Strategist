This Project, Formalized

Everything above, re-derived using nothing but the real plan's own shapes, configs, and recorded strategies.

The real 19-dimensional observation

N_OBS_MULTI = N_OBS_SINGLE + N_NEW_FEATURES = 16 + 3 = 19, matching page 01 feature-by-feature: Phase 1's 16-dimensional single-car observation, plus gap_to_car_ahead (normalized by a 60s cap), gap_to_car_behind (same normalization), and position_normalized (position / n_cars).

Consequence for the DQN checkpoint

DuelingDQN's first Linear layer is sized for a 16-wide input (Phase 5 page 05). A Phase 6 agent needs a freshly constructed network with a 19-wide input layer — DuelingDoubleDQNAgent(obs_dim=19) — not a reload of any single-car checkpoint. This is a Definition-of-Done item in the real plan, not an implementation detail left implicit.

The three reward_type configs

reward_typeFormula (as written in the plan)Category (pages 02–03)
lap_time_plus_position(base_reward − dirty_air), plus position_bonus_scale × (n_total − position) only on the terminal stepDense true signal + a one-time terminal nudge — the mildest of the three
gap_change−(curr_gap − prev_gap), gap to the leader, every step; 0 during a safety carA dense proxy, with the tyre-pushing risk named on page 02
potential_shapingAs written: base_reward − dirty_air + (1/n_total if pos_norm < 1.0 else 0)Not actually potential-based shaping — this is page 06's finding E5. It's a flat bonus, not a Φ(s′) − Φ(s) difference, despite the name.

That last row is worth sitting with: the plan's own code for the reward design meant to be the "principled" one, per page 03's theorem, is the one design in the table that hasn't earned that theorem's guarantee yet. Fixing it means storing self._prev_potential and computing the real difference with Φ(s) = -position_normalized, exactly as pages 03 and 06 worked through.

Five fixed rival strategies

build_rival_strategies cycles through five pre-defined plans — each just a starting compound and a list of (pit_lap, new_compound) pairs, decided before the race and never adapted: a classic one-stop (MEDIUM → HARD), an aggressive two-stop (SOFT → MEDIUM → HARD), a conservative plan (HARD → MEDIUM), an early one-stop (SOFT → HARD), and a staggered two-stop (MEDIUM → SOFT → HARD). None of them read any information about the agent's own choices — the concrete instantiation of page 07's "stationary opponent": from the agent's point of view these five scripts are exactly as fixed and unreactive as the weather trace or the safety-car process.

Definition-of-Done items that exist because of pages 05–06

Several of the real plan's Definition-of-Done checkboxes are there specifically because of the design gap and bugs this set spent three pages on, not because they're generic "does the feature work" checks:

  • Blocking-model test (page 05) — a demonstrably faster car stuck behind a slower one gains no time until an overtake succeeds. Without this test passing, none of the rest of Phase 6's racing content means what it's supposed to.
  • Overtaking-changes-positions test (page 05) — positions differ between a run with overtaking enabled and one with it disabled. This is the direct check that E2 (page 06) is actually fixed, not just that attempt_overtake runs without crashing.
  • Exact-once rival accumulation (page 06, E1) — a regression test that each rival's total_time only ever increases by one lap's worth of time per tick.
  • Dirty air reaches lap time (page 06, E3) — checking the penalty shows up in _agent_total_time, not only in the reward.
  • Shaped-vs-unshaped optimum agreement (page 03 and page 06, E5) — a test confirming the fixed potential_shaping and the unshaped reward agree on the optimal policy for a small fixed scenario, the same kind of check stage 4 of page 08 just ran by hand.
