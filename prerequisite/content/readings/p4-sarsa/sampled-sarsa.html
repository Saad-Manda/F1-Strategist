Sample once, then execute that action

If learn() samples a next action, the next act() call must return it rather than resample from a changed table or a different epsilon. The unchanged pack stores (next_state, action) in a small memory dictionary. Reuse the epsilon-greedy selector; its legal-index and distribution validators were taught earlier.

def act(memory, state, values, legal, epsilon, rng):
    pending = memory.pop("pending", None)
    if pending is None:
        return select_action(values,legal,epsilon,rng)
    pending_state, action = pending
    if pending_state != state or action not in legal_indices(values,legal):
        raise ValueError("stale pending action")
    return action

def target(memory, reward, next_state, values, legal, gamma,
           terminated, truncated, epsilon, rng):
    import math
    validate_distribution([gamma,1-gamma])
    if not math.isfinite(reward):
        raise ValueError("reward must be finite")
    memory.pop("pending", None)
    if terminated:
        return reward
    action = select_action(values,legal,epsilon,rng)
    if not truncated:
        memory["pending"] = (next_state,action)
    return reward + gamma*values[action]

def reset(memory):
    memory.pop("pending", None)

Reset clears pending behavior, not learned Q. A truncation samples continuation from the final unfinished state but discards its pending action. It must not apply that action to the next episode's initial state.

Recap and self-check

Why can resampling after the opening update be wrong?

The backed-up action may differ from the one executed, especially if the update changes the same aliased table row or epsilon changes. Sampled SARSA requires the action in its transition to be the committed one.

Next, average over the behavior distribution instead of using one action sample.
