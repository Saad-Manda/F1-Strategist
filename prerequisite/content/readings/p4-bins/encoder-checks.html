The encoder is part of the learned policy

A saved table only has meaning with its feature order, normalization, categorical decoder, edges and action order. Reordering the eight key fields or changing age bins without translating the table silently attaches old values to different states. Save an encoder version with its configuration and reject incompatible loads.

For a small two-feature encoder, make the composition explicit rather than packing bins into an undocumented integer:

def encode_pair(observation, edge_lists):
    if len(observation) != 2 or len(edge_lists) != 2:
        raise ValueError("two features and two edge lists required")
    return tuple(bin_index(x,edges) for x,edges in zip(observation,edge_lists))

assert encode_pair([0.25,0.6],[[0,0.25,1],[0,0.5,1]]) == (1,1)

Use strategically independent witnesses

  1. Check each feature alone at its lower bound, interior edge, just below/above the edge and maximum.
  2. Check shape, dtype and finite/bounded normalized values before decoding.
  3. For one-hot categories, reject ambiguous or invalid vectors rather than letting argmax hide them.
  4. Test every bit position in the used-compound mask, and binary features at 0 and 1.
  5. Construct full-key collisions near a known action threshold; compare their physical model's action costs independently of the encoder.
  6. Check that a finer scheme separates the intended pair, and count its dense capacity and observed sparse usage.
  7. Verify save/load preserves the exact feature/edge/action schema.

Testing only that the encoder returns eight integers is insufficient. Returning the same tuple for every observation meets that superficial check while destroying the decision problem.

Quantization and missing state are different failures

Quantization merges observable values, such as two ages. Missing state means even the raw observation omits information relevant to future outcomes. Finer bins help the first issue only. If history or hidden scenario changes future weather conditional on the same raw vector, revisiting the model/state design is necessary.

Clamping at age 50 already merges all larger ages before the table sees them. Increasing bin count cannot undo that loss. Establish the reachable domain and whether merged ages affect costs. More input features also need justification: an irrelevant identifier can fragment visits without improving prediction.

Recap and self-check

Does doubling each of eight bin counts double table size?

No. Their Cartesian product grows by 2^8=256, before multiplying by the number of actions. Spend resolution deliberately where it preserves meaningful distinctions.
