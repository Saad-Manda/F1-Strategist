The Learner That Learns Nothing

Phase 9 trains PPO through a well-tested library instead of writing it. First, watch the library train.

Below is the Training room: learning runs the labs recorded, replayed. The learner is sb3-contrib's MaskablePPO, the class the plan uses, on the 20-lap toy race of the earlier capstones. The reward is the plan's: each lap pays minus its lap time. Every 100 races the run's greedy plan is scored, with no noise, against the race's optimum, 224.49 s. Press Train, then try the other seeds.

A flat line at 38.48 s, on every seed, for 2,000 races. That is the plan of a learner that never chooses to stop: it stays out until the rules force a stop for B on lap 19. Seed 1's untrained network started better, at 16.28 s, and training pushed it onto that plan. The critic's value of lap 1 is −44.9; the plan it is acting on returns −263.

Why does a well-tested PPO learn nothing here?

The library has been run by thousands of people, so the algorithm is probably not the problem. Nothing crashes, nothing warns, and the run takes the usual time. What is wrong, and what should the plan change?

What changes in Phase 9

Every learner so far learned values and acted greedily on them: a Q-table in Phase 4, a network standing in for one in Phase 5. Phase 9 learns the policy itself, a function from state to action probabilities, and uses a learned value only as a critic that steadies the training signal. The derivation runs policy gradients → actor-critic → advantage → GAE → PPO's clip, pages 01 to 04, before the library that trains it.

What Phase 9 does and does not do

This set covers what phase-9-ppo-sb3.md needs: the derivation above, why PPO is a library case when Q-learning and DQN were not, Stable-Baselines3's API, and three audit findings: processes and Windows (J1), the training budgets of the DQN comparison (J2) and the reward scale (J3). Nothing here uses Phase 8: the plan itself says Phase 9 can come first. ppo_agent.py, sb3_wrapper.py and configs/ppo.yaml are not in the repository yet, so the last page reads the plan's own pseudocode.
