Page 03 / 12 — Two instabilities, part one

The Target Network

The naive way to turn Q-learning into DQN trains a network to chase a target computed by that same network — which keeps moving every time the network gets updated. The fix is a second, slower copy.

The naive idea

Page 01 established what doesn't change: the target is still r + γ·max_a' Q(s',a'). The most direct way to use a network for this replaces the tabular lookup with the network's own prediction: target = r + γ·max_a' Q(s',a';θ), and trains the same network θ toward it using page 02's gradient-descent step.

Why that's unstable

θ is doing two jobs at once: it's the network being trained (Q(s,a;θ), the prediction the loss is computed on), and it's also the network used to compute the very target that prediction is being trained toward (Q(s',a';θ), inside the target). Every gradient step changes θ — and because both the prediction and the target are functions of the same θ, changing it to fix today's error also shifts tomorrow's target. It's chasing a target that runs away every time you get closer to it.

A tiny illustration makes this concrete. Suppose at some state-action pair the network currently predicts Q(s,a;θ) = 3.0, and the target (computed from the same weights) is target = r + γ·max_a' Q(s',a';θ) = 5.0. A gradient step moves θ to close that gap — but θ also appears inside Q(s',a';θ), so the same step that raised Q(s,a;θ) toward 5.0 can simultaneously raise Q(s',a';θ), which raises the target itself, say to 5.4. The gap the next update sees hasn't shrunk to reflect the progress just made — worse, in this example it grew. Nothing here is a bug in gradient descent; it's a direct consequence of one set of weights serving two roles that are supposed to converge toward each other.

The fix: a second, frozen-ish copy

Keep two networks with separate weights: the online network (θ), updated by gradient descent every training step, and the target network (θ⁻), used only to compute the target: target = r + γ·max_a' Q(s',a';θ⁻). Gradient steps only ever touch θ; θ⁻ never receives a gradient directly. The target stops moving out from under the update that's chasing it, because the weights computing it are no longer the same weights that update just changed.

Keeping θ⁻ from going stale forever

If θ⁻ never changed at all, the online network would eventually be training toward a target computed by an arbitrarily out-of-date network — useful for stability, useless for actually converging to anything close to correct. Two ways to update θ⁻, both named because the real agent implements one of them:

  • Hard update: every N steps, copy θ → θ⁻ directly. Simple, but causes a visible discontinuity in the target every N steps — right after a copy, every target the network is trained toward suddenly jumps to reflect however much θ had drifted since the last copy.
  • Polyak / soft update: every step, nudge θ⁻ a little toward θ: θ⁻ ← τ·θ + (1−τ)·θ⁻, with a small τ (the real agent's default: 0.005). No jumps — θ⁻ tracks θ continuously, just much more slowly.

Worked arithmetic: how slow is "slowly"?

Suppose θ jumps to a new value and then holds perfectly still (an idealization, just to isolate how fast θ⁻ catches up). After n soft-update steps with rate τ, the remaining gap between θ⁻ and θ has shrunk by a factor of (1−τ)ⁿ — each step closes a fixed fraction τ of whatever gap is left, so the untouched fraction keeps compounding. Solving for the number of steps needed to close half the gap:

(1 - τ)^n = 0.5 n = ln(0.5) / ln(1 - τ) τ = 0.005: n = ln(0.5) / ln(0.995) = -0.6931 / -0.005013 ≈ 138.2 → roughly 139 steps for θ⁻ to close half the gap to a θ that jumped and then held still.

That's the concrete meaning behind "slowly tracks": with train_freq=4 (the real agent updates every 4 environment steps), 139 training steps is roughly 556 environment steps, well under one 52-lap episode's worth of steps — so within a fraction of a single episode, the target network has already absorbed about half of any sudden shift in the online network, while still lagging enough to avoid the same-weights instability page 03 opened with.
