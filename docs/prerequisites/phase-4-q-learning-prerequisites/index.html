Phase 4 Q-Learning Prerequisites

Everything — and only what — you need to build tabular Q-learning and SARSA as described in phase-4-q-learning-sarsa.md, assuming you already have the Phase 1 and Phase 3.5 prerequisite sets and nothing more.

Why this phase is different from the one before it

Phase 3.5 computed the exact optimal strategy for the single-car race because it was handed the model: dynamics.py gave it P and R in closed form, and backward induction solved the Bellman equation directly, once, with no trial and error. That is planning.

Q-learning and SARSA get no such gift. They never see P or R written out anywhere — they only ever see one sampled transition (s, a, r, s') at a time, generated by actually playing a race and watching what happens. Discovering a good policy purely from that experience, the way an actual rookie strategist would have to, is learning. The DP oracle from Phase 3.5 doesn't disappear once this phase starts — it becomes this phase's ruler, via the optimality-gap metric that measures how close a learned policy gets to the exact answer Phase 3.5 already computed.

Scope, precisely

This set teaches tabular temporal-difference control — Q-learning and SARSA — and the state-discretization problem that representing a Q-value as a lookup table forces on this project. It does not cover neural networks, experience replay, target networks, or anything else specific to function approximation, even as a preview. That material belongs to Phase 5's own prerequisites, which this set assumes nothing from.

How this folder teaches the implementation half

Page 7 has you build a small toy Q-learning agent and a toy SARSA agent side by side, in your own names, that deliberately do not match q_learning_agent.py. You'll run them on an identical toy environment from identical seeds and watch their learned tables genuinely diverge — the same divergence page 4 works out by hand for a handful of update steps. Only page 8 names which piece of the real state design and reward shaping corresponds to what you built, and only page 9 walks the real files themselves.

How to use this alongside the Phase 4 plan

Read pages 1–6 once, in order — they build one continuous argument, from "why sampling replaces solving" through to the specific reason the real binning scheme as first drafted doesn't work. Page 7 is hands-on: build the toy agents yourself, run them, and let the SARSA leak bug actually corrupt a run before reading about it in the abstract. Page 8 then re-derives the same concepts using nothing but this project's actual state design and its recorded gotchas — the abstractions from pages 1–6 should stop feeling abstract at that point. Page 9 is the closest thing to a line-by-line reading guide for q_learning_agent.py itself. Keep page 10 open as a reference while you work.
