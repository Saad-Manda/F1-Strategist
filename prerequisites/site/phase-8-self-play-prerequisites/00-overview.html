Phase 8 · Case brief

The Run That Dies at Episode Zero

Phase 8 trains the agent against copies of itself. First, start the plan's training run.

The plan's self-play loop keeps a pool of past copies of the learner and draws each race's opponent from it with one rule: 70% of the time from the newest 20% of the pool, otherwise from the older 80%. Before the first race the pool gets one entry, the untrained learner, and the next entry arrives at episode 1,000. Below is that rule, line for line. Sample from a pool of one, then start the run a thousand times.

About seven calls in ten fail, and the run never sees episode 1,000. That is the first half of the case. The second half is what the run is for: a histogram of pit stops, the learner's stop lap minus its rival's, that should show undercuts and overcuts emerging from self-play. Suppose the crash is fixed. Would that histogram show what the plan says it shows?

What changes in Phase 8

Through Phase 6 at most one thing in the world was learning. Phase 6's rivals follow scripts, so to the agent they are part of a fixed environment, like the weather. Phase 8 removes that on purpose: the opponents are earlier copies of the learner, so the environment, from the learner's point of view, changes while it is learning about it. The Pit Wall's Duel mode is the game this set measures everything on: two equal cars, one stop each, and the question of who stops first.

What Phase 8 does and does not do

This set covers what phase-8-self-play.md needs: why a learning opponent breaks stationarity, the game self-play is chasing and the checkpoint pool that stands in for it, PettingZoo's two multi-agent APIs, the three ways to organize multi-agent training, and the audit findings against the plan, taught as core content. It doesn't cover PPO or Stable-Baselines3, which belong to Phase 9. f1_pettingzoo_env.py and self_play_trainer.py are not in the repository yet, so the last page reads the plan's own pseudocode.
