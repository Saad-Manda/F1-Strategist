Page 10 / 12 — Project-specific implementation

This Project, Formalized

Everything above, re-derived using nothing but the real plan's own classes, shapes, and parameters.

sb3_wrapper.py as a direct instantiation of page 06 and page 07's fix, applied

make_masked_env wraps a single F1StrategyEnv with ActionMasker, exposing the environment's existing action_masks() method (Phase 1, assumed background) in the format page 06's MaskablePPO expects. make_vec_masked_envs is where page 07's fix belongs concretely: the lambda in ActionMasker(env, lambda e: e.action_masks()) should become a module-level def _mask_fn(env): return env.action_masks(), and — per page 07's closing argument — DummyVecEnv is the recommended choice over SubprocVecEnv for this specific environment, given how cheap a single F1StrategyEnv.step() call is once IPC overhead is counted.

ppo_agent.py's eval-mode asymmetry, and Finding D

PPOAgent.select_action calls self.model.predict(obs, action_masks=masks, deterministic=True) — page 06's .predict() in its deterministic mode. This already does the right thing by construction. Contrast this directly against Finding D (assumed background from the eval-mode fix already required of Phase 4/5's agents): QLearningAgent and DuelingDoubleDQNAgent both still branch on self.epsilon at evaluation time, meaning roughly 5% of their "trained" actions during evaluation are still uniformly random — including occasional random pit stops. The real plan's own Risks table names this exact asymmetry. PPO's evaluation code does not need fixing; the custom DQN/Q-learning agents do, and that fix must land before this phase's comparison numbers mean anything, independent of page 08's training-budget fix.

The gamma: 1.0 row is the one place J3 (the audit's third Phase 9 finding) enters this set, and it is a cross-reference rather than new content: with γ = 1.0 and uncentred rewards, PPO's value head faces the same ≈ −5,000 target problem DQN already had (Finding C, assumed background from the Phase 4/5 sets). The fix is the same one already taught there — reward_offset: "base_pace" — and it applies here unchanged; nothing about PPO's own math (pages 01–04) requires revisiting it.

Definition-of-Done items that exist because of pages 05–08

  • "DQN vs PPO comparison runs on 100 paired seeds, with the DP oracle's optimality gap as the shared yardstick" — Phase 3.5's oracle (assumed background) as the fair common denominator both agents are measured against, which page 08's budget-matching argument still needs even after training budgets are fixed; a paired-seed evaluation on top of an unmatched training budget answers the wrong question.
  • The scheduling note to do Phase 9 before Phase 8 — page 00's independence framing: nothing here depends on self-play, so there's no reason to defer this phase behind Phase 8's genuinely open-ended one.
