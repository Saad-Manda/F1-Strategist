Page 08 / 11 — Building it yourself

Build It Yourself: A Toy Blocking Race With Shaped Rewards

Five stages: a toy race that reproduces page 5's failure for real, the one-line fix, a toy overtake model, a reward-shaping comparison built to make ad-hoc shaping visibly fail, and a bug you plant on purpose.

Every name below (TinyPaddockRace, ToyCar, try_pass, and so on) is invented for this page and deliberately does not match f1_multi_env.py, RivalState, or attempt_overtake. The point, as with every toy build in this project's prerequisite sets, is to arrive at the same shape of solution independently, so the real pseudocode in page 10 reads as familiar structure rather than new material.

Stage 0 — a toy race, deliberately built without any blocking rule

Two cars, a fixed number of ticks, each with a per-tick pace the reader scripts directly (no compound/tyre model needed — that's not what this page is teaching):

class ToyCar:
    def __init__(self, name, pace_schedule):
        self.name = name
        self.pace_schedule = pace_schedule   # list of per-tick pace, one entry per tick
        self.total_time = 0.0

    def tick_pace(self, t):
        return self.pace_schedule[t]


class TinyPaddockRace:
    """No blocking rule yet — every car's time this tick is just its own pace."""
    def __init__(self, cars):
        self.cars = cars

    def run(self, n_ticks):
        history = []
        for t in range(n_ticks):
            for car in self.cars:
                car.total_time += car.tick_pace(t)
            history.append({c.name: c.total_time for c in self.cars})
        return history

    def standings(self):
        return sorted(self.cars, key=lambda c: c.total_time)

Stage 1 — reproduce page 5's diagnosis: timing stops mattering without blocking

Script one car (FAST) to be consistently quicker per tick than another (SLOW) that starts ahead by virtue of a head start on lap 0, and model a "pit" as one tick of a large fixed penalty added to whichever car's schedule includes it. Run it twice — pit FAST early, then pit it late — and check whether when it pits changes anything about the final gap between the two cars:

def make_schedule(base_pace, n_ticks, pit_tick=None, pit_penalty=20.0):
    sched = [base_pace] * n_ticks
    if pit_tick is not None:
        sched[pit_tick] += pit_penalty
    return sched

n_ticks = 30
slow = ToyCar("SLOW", make_schedule(base_pace=5.0, n_ticks=n_ticks))
fast_pits_early = ToyCar("FAST", make_schedule(base_pace=4.5, n_ticks=n_ticks, pit_tick=5))
fast_pits_late  = ToyCar("FAST", make_schedule(base_pace=4.5, n_ticks=n_ticks, pit_tick=25))

for fast in (fast_pits_early, fast_pits_late):
    race = TinyPaddockRace([slow, fast])
    race.run(n_ticks)
    gap = fast.total_time - slow.total_time
    print(fast.total_time, slow.total_time, gap)
# Both runs land on the same gap: pit timing only ever shifts the pit tick's
# one-time penalty, never anything about how the two cars' paces interact.
# "Pitting first when you're faster" and "just being faster" are the same
# number here — exactly page 5's conclusion, now verified by running it.

Stage 2 — add the blocking constraint and rerun the identical scripts

Page 05's fix, transplanted into the toy: when two cars are within a following threshold and no pass has happened this tick, the trailing car is held to (at best) the pace of the car ahead:

FOLLOW_GAP = 1.0

class BlockingPaddockRace(TinyPaddockRace):
    def run(self, n_ticks):
        history = []
        for t in range(n_ticks):
            paces = {c.name: c.tick_pace(t) for c in self.cars}
            ordered = sorted(self.cars, key=lambda c: c.total_time)
            for i, car in enumerate(ordered):
                if i == 0:
                    continue   # leader is never blocked
                ahead = ordered[i - 1]
                gap = car.total_time - ahead.total_time
                if gap < FOLLOW_GAP:
                    paces[car.name] = max(paces[car.name], paces[ahead.name])
            for car in self.cars:
                car.total_time += paces[car.name]
            history.append({c.name: c.total_time for c in self.cars})
        return history

Rerun the exact same fast_pits_early / fast_pits_late pair against BlockingPaddockRace instead of TinyPaddockRace. Now the two runs land on different final gaps — pitting early, while still ahead of (or level with) SLOW, lets FAST build a lead before SLOW can close within the follow gap and start capping its pace; pitting late risks getting caught behind SLOW first. The undercut is now representable in a system small enough to have built and checked by hand.

Stage 3 — a toy overtake model as the only way out of blocking

def try_pass(pace_advantage, rng, base_rate=0.4):
    """Simplified stand-in for page 4's sigmoid — a flat rate scaled by advantage."""
    if pace_advantage <= 0:
        return False
    prob = min(0.95, base_rate + 0.3 * pace_advantage)
    return rng.random() < prob

Wire try_pass into BlockingPaddockRace so a trailing car within FOLLOW_GAP gets one pass attempt per tick, and — if it succeeds — is exempted from the pace cap that tick. Run many seeds of a faster car starting directly behind a slower one, and log how many ticks it takes to get clear, comparing a faster-trapped car against a same-pace-trapped car:

import numpy as np

def laps_stuck(pace_gap, n_trials=500, max_ticks=40):
    rng = np.random.default_rng(0)
    stuck_counts = []
    for _ in range(n_trials):
        stuck = 0
        for t in range(max_ticks):
            if not try_pass(pace_gap, rng):
                stuck += 1
            else:
                break
        stuck_counts.append(stuck)
    return np.mean(stuck_counts)

print("faster car, avg ticks stuck:", laps_stuck(pace_gap=0.8))
print("same-pace car, avg ticks stuck:", laps_stuck(pace_gap=0.0))
# The faster car clears in visibly fewer ticks on average; a car with no
# pace advantage essentially never gets an attempt at all (pace_advantage <= 0
# skips try_pass entirely) — grounding page 4's model in code actually run.

Stage 4 — reward-shaping comparison on a scenario built to make ad-hoc shaping fail

A tiny two-choice MDP, deliberately built so the dense proxy and the true goal disagree — reusing Phase 4's tabular update rule from its own build-it-yourself page:

# States: START -> (RISKY or SAFE) -> END
# RISKY: big proxy reward now (closes a toy "gap"), but a worse true final spot
# SAFE:  smaller proxy reward now, but the better true final spot
TRUE_REWARD  = {"RISKY": -10.0, "SAFE": -4.0}    # true goal: SAFE is better
PROXY_REWARD = {"RISKY":  +6.0, "SAFE":  +1.0}    # dense proxy: RISKY looks better

POTENTIAL = {"START": 0.0, "RISKY_DONE": -1.0, "SAFE_DONE": 2.0}  # Φ(s), SAFE has higher potential

def run_variant(reward_table, shaping=None, n_episodes=3000):
    q = {"RISKY": 0.0, "SAFE": 0.0}
    rng = np.random.default_rng(0)
    alpha, eps = 0.3, 0.2
    for _ in range(n_episodes):
        action = rng.choice(["RISKY", "SAFE"]) if rng.random() < eps else max(q, key=q.get)
        reward = reward_table[action]
        if shaping is not None:
            reward += shaping(action)
        q[action] += alpha * (reward - q[action])
    return q

q_true       = run_variant(TRUE_REWARD)
q_proxy      = run_variant(PROXY_REWARD)                                   # ad-hoc: flat, action-keyed bonus
q_shaped     = run_variant(TRUE_REWARD, shaping=lambda a:
                    POTENTIAL[f"{a}_DONE"] - POTENTIAL["START"])            # real Φ-difference, page 3's formula

for name, q in [("true reward", q_true), ("ad-hoc proxy", q_proxy), ("potential-shaped", q_shaped)]:
    print(name, q, "-> optimal:", max(q, key=q.get))
# true reward:       optimal SAFE   (matches the real goal)
# ad-hoc proxy:       optimal RISKY  (the proxy's own bonus flips the answer)
# potential-shaped:   optimal SAFE   (page 3's theorem, checked empirically:
#                                     the shaped optimum agrees with the true one)

This is page 02's tyre-pushing risk and page 03's theorem, both made concrete in code the reader ran: the ad-hoc proxy genuinely changes which action looks best, while the potential-based version — built from the exact Φ(s') − Φ(s) formula, just with an invented toy Φ — agrees with the unshaped true optimum every time.

Stage 5 — catch the leak: plant E5's bug on purpose

Reproduce the real plan's mistake directly: a reward branch that claims to be potential-based shaping but is actually a flat, state-independent-of-history bonus for "not in the worse outcome":

def mislabeled_shaping(action):
    """Looks like shaping. Is not: no Φ(s) is ever differenced, just a flat bonus."""
    return 0.5 if action == "SAFE" else 0.0

q_mislabeled = run_variant(TRUE_REWARD, shaping=mislabeled_shaping)
print("mislabeled 'shaping':", q_mislabeled, "-> optimal:", max(q_mislabeled, key=q_mislabeled.get))

Run this next to q_shaped from stage 4 on a version of the toy MDP where the true gap between RISKY and SAFE is made small enough for a flat 0.5 bonus to flip it (shrink TRUE_REWARD's gap and rerun both). The real Φ-difference shaping's optimal action tracks the true optimum no matter how the bonus is tuned, by page 3's theorem; the mislabeled version's optimal action can flip, because nothing about it was ever guaranteed not to. That's the theorem stopping being a fact taken on faith and becoming something just verified directly, on code the reader broke and then compared against code that couldn't be broken the same way.
