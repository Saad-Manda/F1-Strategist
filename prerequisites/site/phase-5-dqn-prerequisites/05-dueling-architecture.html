Phase 5 · Page 05 · Dueling

The Dueling Architecture

Staying out is the right call on most laps. A network that learns each call's value separately is solving a harder problem than it needs to.

Your call · splitting a value

Three calls at one state are worth Q = [−2, −5, −3]. You split them into one number for the state, V, plus one edge per call, A, with the edges averaging zero.

What is V?

Two questions instead of one

In this project's races, staying out is the right call on about 85% of laps, by the real plan's own estimate. A single output head must still learn a separate number for every call at every state, even when most of them are near-identical poor alternatives to the one that matters. Split the question in two:

  • V(s): how good it is to be in this state at all.
  • A(s, a): how much better or worse this call is than the state's average call.

Then Q(s, a) = V(s) + A(s, a). "Lap 15, the tyres are fine" is learned once, in V, shared by every call, and A only has to carry the much smaller "and pitting now would be a mistake".

The identifiability problem

Given only Q, the split isn't unique. Add any constant to V and subtract it from every A, and every Q is unchanged:

Q = [−2, −5, −3] V = 0, A = [−2, −5, −3] → V + A = [−2, −5, −3] V = −10, A = [8, 5, 7] → V + A = [−2, −5, −3]

The loss sees only the sum, so a network could let V drift to +1,000,000 and A to −1,000,002 and never be corrected.

The fix: pin the edges' mean to zero

Combine the heads as Q(s, a) = V(s) + (A(s, a) − mean_a A(s, ·)). The edges now average zero by construction, and only one split satisfies both rules:

from V = 0: A′ = [−2, −5, −3] − (−3.33) = [1.33, −1.67, 0.33] V′ = 0 + (−3.33) = −3.33 from V = −10: A′ = [8, 5, 7] − 6.67 = [1.33, −1.67, 0.33] V′ = −10 + 6.67 = −3.33

With the edges' mean pinned to zero, V is the average of the three values, −3.33, and the edges are each call's distance from it: [1.33, −1.67, 0.33]. Both starting splits land there.

How sure is the champion?

The edges are where a call is decided, so look at the champion's. On lap 3 of a green race, on the starting A, it expects 202.84 s to the flag if it stays out and 206.72 s if it boxes for B: a 3.88 s edge. On lap 9 of race 29 the edge is 5.29 s. These aren't near-ties that a little error could flip. A network can be wrong, and page 06 finds one that is, but here the champion's numbers and the oracle's (3.67 s and 6.28 s) agree on the call by seconds.

Evidence so farThe champion's edges against its unplanned stops are 3.88 and 5.29 s, close to the oracle's 3.67 and 6.28 s. It rates those stops worse, and by a lot. Next: the prime suspect, a network that overrates pit stops.

Lab p5-05 · Code + tests · about 15 min

Two heads, one answer

First split a new set of Q-values by hand and combine a network's two outputs. Then write the split, the combining line and a small two-headed network, with tests that check the property page 05 is about: once the mean is subtracted, shifting the advantages changes nothing, and moving value from one head to the other is no longer free.

Warm-up, on paper · a new state

A state with three actions has true Q-values Q = [−6, −2, −4]. A half-trained network happens to hold the decomposition V = 5, A = [−11, −7, −9], which adds up correctly.

Combining a network's outputs

A network's two heads output V = 1 and A = [3, 5, 1]. It computes Q = V + (A − mean(A)).

Worked solution for the warm-up

Split. mean(A) = −9; V′ = 5 − 9 = −4; A′ = [−2, 2, 0]. Check: −4 + [−2, 2, 0] = [−6, −2, −4].

Combine. mean([3, 5, 1]) = 3, Q = [1, 3, −1]. Shifting every A by 10 leaves Q alone. Moving 10 from A into V raises every Q by 10. A plain sum would treat the two the other way round: shifting A alone would change Q, and the trade between V and A would not. The code lab tests both.
