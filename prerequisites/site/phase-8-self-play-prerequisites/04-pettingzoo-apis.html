Two Ways to Say "Everyone Acts": AEC and Parallel

PettingZoo has two multi-agent APIs. F1 strategy needs one of them, and knowing both shows why.

Your call · who moves second

PettingZoo's parallel_to_aec, which the plan imports, turns a simultaneous game into a turn-based one: agents step one after the other. Wrap rock-paper-scissors this way and play many rounds.

How much does moving second win?

AEC: Agent Environment Cycle

Agents act one at a time in a cycle: env.agent_selection names whose turn it is, env.last() returns that agent's own latest observation, reward and done flags, and one step call is made per agent in turn. It is the natural shape for turn-based games.

env.reset() env.agent_selection → "player_A"; env.step("rock") env.agent_selection → "player_B"; obs_B = env.last() # what B sees is the env's choice env.step("paper")

What each agent sees on its turn is a separate question, and the environment answers it, not the API. An environment that shows B the move A made makes moving second worth something: lab p8-04 measures B winning every round.

Parallel

All agents submit actions at once; the environment resolves them together and returns observations, rewards, terminations, truncations and infos, each a dict keyed by agent id. Nobody acts second, so nobody has an information edge.

observations, infos = env.reset() actions = {"player_A": "rock", "player_B": "paper"} # chosen independently observations, rewards, terminations, truncations, infos = env.step(actions)

parallel_to_aec gives the second agent no sight of the first agent's move in the same cycle: both see “no move yet” on their first turn and only the previous round's moves after that. The second mover's edge measures 0.02, which is noise.

So AEC says who steps when. “Later agents see more” is true only of environments built to show them more.

Why F1 strategy needs Parallel

Every car makes its stay-or-pit call at the same point in the lap, without seeing what any other car decided this lap. Gaps closing, the wake, a pass: all are consequences computed after every car's action is in, by the race's dynamics. That is Parallel's shape. F1 strategy has no natural "whose turn is it".

Both APIs share one surface: possible_agents lists every agent id (["agent_0", "agent_1", …]), and observation_spaces and action_spaces are dicts keyed by agent id, identical for every car here. Page 09 shows the plan's F1PettingZooEnv as a plain instance of it.

Evidence so farThe API is the right one: the plan's env is Parallel, as the race needs. Nothing here crashes or decides what the cars can do to each other; that is inside step(). Next: the first opponent the pool hands out.
