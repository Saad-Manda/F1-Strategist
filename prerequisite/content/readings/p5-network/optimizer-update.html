Clear, calculate, differentiate, step

The training sequence is zero_grad → forward → scalar loss → backward → optimizer.step. The optimizer owns the online parameters it changes. SGD subtracts learning rate times gradient; it does not replace weights with the loss or target. The unchanged network pack asks for this complete operation:

def train_step(model, optimizer, x, labels):
    optimizer.zero_grad()
    loss = mse(model(x),labels)
    loss.backward()
    optimizer.step()
    return float(loss.detach())

The returned number is the loss computed before the parameter update. detach() removes that tensor's graph connection for reporting, and float converts a scalar to a Python number. The loss used for backward must retain its graph. Validate observations, labels, predictions and intended shapes; monitor parameter/gradient finiteness when integrating. A nonfinite loss should be investigated before updating a production learner.

Recognize Adam without requiring its derivation

Adam maintains per-parameter estimates of gradients and squared gradients and uses them to adapt the update. In torch.optim.Adam(online.parameters(),lr=0.001), lr is still a base learning rate, not a guarantee of a certain change in predicted seconds. Optimizer state is needed for faithful training resumption. Different optimizers, batches and reward scales can produce different behavior. The optional next page derives one Adam step; required later readings rely only on this optimizer contract.

API reference: PyTorch Adam. No optimizer promises a universally faster fit or higher return.

Recap and self-check

Can loss.item() be called before backward and then used as the differentiable loss?

Keep the tensor for backward. Its Python scalar is useful for logs but has no graph. Clearing gradients prevents earlier independent steps from accumulating into the next update.
