Freeze values and storage

A pool entry must remain the policy that was evaluated and named when saved. A reference to a learner array or a shallow copy of nested tensor storage is not a snapshot. The pack copies a three-probability NumPy vector and marks it read-only. Mutating the original [1,0,0] into [0,1,0] leaves the snapshot [1,0,0].

For a PyTorch policy, copy each state_dict tensor or deepcopy the model; do not retain aliased state_dict values while the live model updates. Freeze optimizer access, use eval mode for dropout/batch normalization and no_grad for forward calls. Eval mode does not itself stop gradients or make storage independent, and zero epsilon specifies an action-selection convention rather than a storage property.

Store architecture, feature/action order, normalization and reward metadata with checkpoint identity. Cache immutable loaded opponent models when useful, but ensure one caller cannot change their parameters, epsilon or normalization statistics for another.

Copying is not evaluation

The copied policy can still be inappropriate or deterministic. Independence checks establish snapshot integrity; matchup checks establish behavior. Pack snapshots describe probability vectors, not full F1 networks. A bounded FIFO pool copies the new entry and retains the last capacity entries, with associated weights/IDs kept aligned.

def snapshot(policy):
    result = np.array(policy_vector(policy),dtype=float,copy=True)
    result.setflags(write=False)
    return result

def add_snapshot(pool, policy, capacity):
    if type(capacity) is not int or capacity < 1:
        raise ValueError('positive integer capacity required')
    return [*pool,snapshot(policy)][-capacity:]

Recap and self-check

Does calling eval() turn an alias into a snapshot?

No. It changes layer behavior; independent storage requires a copy.
