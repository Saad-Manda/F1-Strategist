Build It Yourself: A Toy Blocking Race With Shaped Rewards

Five stages: a toy race that reproduces page 5's failure for real, the one-line fix, a toy overtake model, a reward-shaping comparison built to make ad-hoc shaping visibly fail, and a bug you plant on purpose.

Every name below (TinyPaddockRace, ToyCar, try_pass, and so on) is invented for this page and deliberately does not match f1_multi_env.py, RivalState, or attempt_overtake. The point, as with every toy build in this project's prerequisite sets, is to arrive at the same shape of solution independently, so the real pseudocode in page 10 reads as familiar structure rather than new material. The lab at the end of this page builds the same five ideas again on the toy race with a scripted rival; this page is its brief, and the snippets are a last-resort hint.

Stage 0 — a toy race, deliberately built without any blocking rule

Two cars, a fixed number of ticks, each with a per-tick pace the reader scripts directly (no compound or tyre model: that is not what this page is teaching). Each car's time this tick is just its own pace.

Reference snippet (a last-resort hint: the lab uses a different world and different names) 
class ToyCar:
    def __init__(self, name, pace_schedule, start=0.0):
        self.name = name
        self.pace_schedule = pace_schedule   # list of per-tick pace, one entry per tick
        self.total_time = start

    def tick_pace(self, t):
        return self.pace_schedule[t]


class TinyPaddockRace:
    """No blocking rule yet — every car's time this tick is just its own pace."""
    def __init__(self, cars):
        self.cars = cars

    def run(self, n_ticks):
        for t in range(n_ticks):
            for car in self.cars:
                car.total_time += car.tick_pace(t)

    def standings(self):
        return sorted(self.cars, key=lambda c: c.total_time)

Stage 1 — reproduce page 5's diagnosis: timing stops mattering without blocking

Script one car (FAST, 4.5 per tick) to be consistently quicker than another (SLOW, 5.0 per tick), and model a "pit" as one tick with a fixed 20-second penalty added to FAST's schedule. Run it twice, pitting early and pitting late, and check whether when it pits changes the final gap.

Reference snippet (a last-resort hint: the lab uses a different world and different names) 
def make_schedule(base_pace, n_ticks, pit_tick=None, pit_penalty=20.0):
    sched = [base_pace] * n_ticks
    if pit_tick is not None:
        sched[pit_tick] += pit_penalty
    return sched

n_ticks = 30
for pit_tick in (5, 25):
    slow = ToyCar("SLOW", make_schedule(5.0, n_ticks))
    fast = ToyCar("FAST", make_schedule(4.5, n_ticks, pit_tick=pit_tick))
    TinyPaddockRace([slow, fast]).run(n_ticks)
    print(pit_tick, fast.total_time - slow.total_time)
# 5 5.0
# 25 5.0

Both runs land on the same gap, 5.0: thirty ticks at 0.5 faster gains 15, the stop costs 20, and the pit tick only decides where the 20 is paid. "Pitting first when you're faster" and "just being faster" are the same number here: page 5's conclusion, verified by running it.

Stage 2 — add the blocking constraint and rerun the identical scripts

Page 05's fix, transplanted into the toy: order the cars by time, and a car less than FOLLOW_GAP behind the car ahead cannot be faster than it this tick.

Reference snippet (a last-resort hint: the lab uses a different world and different names) 
FOLLOW_GAP = 1.0

class BlockingPaddockRace(TinyPaddockRace):
    def run(self, n_ticks):
        for t in range(n_ticks):
            paces = {c.name: c.tick_pace(t) for c in self.cars}
            ordered = sorted(self.cars, key=lambda c: c.total_time)   # stable: a tie keeps list order
            for ahead, car in zip(ordered, ordered[1:]):
                if car.total_time - ahead.total_time < FOLLOW_GAP:
                    paces[car.name] = max(paces[car.name], paces[ahead.name])
            for car in self.cars:
                car.total_time += paces[car.name]
# with BlockingPaddockRace in place of TinyPaddockRace above:
# 5 7.5
# 25 17.5

Now the two runs land on different gaps, 7.5 and 17.5. Look at why. Both cars start at 0, the tie puts SLOW first (it comes first in the list), and FAST is less than a second behind it: from the very first tick FAST is held to SLOW's 5.0. It never builds a lead. It stays stuck until its stop drops it far enough back to run free, so every tick before the stop is a tick at the slower car's pace. The final gap is 5 + 0.5 × pit_tick, and the best stop is the earliest one.

That is the new thing the blocking line created: a pit stop now does two jobs. It costs 20 seconds, and it gets you out of traffic. The second job is the one an undercut uses, and it did not exist one stage ago. (The p6-05 widget on page 05 draws exactly these two cars.)

Stage 3 — a toy overtake model as the only way out of blocking

Reference snippet (a last-resort hint: the lab uses a different world and different names) 
import numpy as np

def try_pass(pace_advantage, rng, base_rate=0.4):
    """Simplified stand-in for page 4's sigmoid — a flat rate scaled by advantage."""
    if pace_advantage <= 0:
        return False
    prob = min(0.95, base_rate + 0.3 * pace_advantage)
    return rng.random() < prob

def ticks_stuck(pace_gap, n_trials=500, max_ticks=40):
    rng = np.random.default_rng(0)
    counts = []
    for _ in range(n_trials):
        stuck = 0
        while stuck < max_ticks and not try_pass(pace_gap, rng):
            stuck += 1
        counts.append(stuck)
    return np.mean(counts)

print(ticks_stuck(0.8), ticks_stuck(0.0))

Wire try_pass into BlockingPaddockRace so a trailing car within FOLLOW_GAP gets one attempt per tick and, if it succeeds, is exempt from the cap that tick. Run many seeds: a faster car trapped behind a slower one gets clear after about 0.6 failed ticks on average, while a car with no pace advantage never gets an attempt at all and stays stuck for the whole 40 ticks. Page 4's model, grounded in code that ran.

Stage 4 — reward shaping, on a scenario built to make ad-hoc shaping fail

A one-decision toy: from START choose RISKY or SAFE; each leads to a middle state and then to END, where the episode stops. The first step pays the true reward, the second pays nothing. A dense proxy pays something different on the first step, the way page 02's stand-ins do. Everything is deterministic, so the returns can be written down instead of learned.

Reference snippet (a last-resort hint: the lab uses a different world and different names) 
PROXY = {"RISKY": +6.0, "SAFE": +1.0}           # the dense stand-in: RISKY looks better

# Φ on every state. END is where the episode stops, so its potential is 0.
PHI = {"START": 0.0, "RISKY_MID": -1.0, "SAFE_MID": 2.0, "END": 0.0}

def shaped_return(choice, true, phi, gamma=1.0):
    mid = f"{choice}_MID"
    step1 = true[choice] + gamma * phi[mid] - phi["START"]
    step2 = 0.0 + gamma * phi["END"] - phi[mid]
    return step1 + step2

def best(scores):
    return max(scores, key=scores.get)

for true in ({"RISKY": -10.0, "SAFE": -4.0}, {"RISKY": -4.0, "SAFE": -5.0}):
    print("true best:", best(true),
          "| proxy best:", best(PROXY),
          "| shaped best:", best({c: shaped_return(c, true, PHI) for c in true}))
# true best: SAFE | proxy best: RISKY | shaped best: SAFE
# true best: RISKY | proxy best: RISKY | shaped best: RISKY

The proxy picks RISKY whatever the true rewards are: it is answering a different question. The shaped returns equal the true ones exactly, because the middle potential is added on one step and taken back on the next, and both routes end at the same END with potential 0. Swap which choice is truly better and the shaped choice follows it.

The condition that makes this work

An earlier version of this page put the potentials on two different end states (RISKY_DONE = −1, SAFE_DONE = 2) and stopped there. That looks like the same formula, but it is not safe: page 03's leftover term Φ(end) − Φ(start) then differs by route, and it simply adds 3 in favour of SAFE. With the true rewards swapped (RISKY −4, SAFE −5) that version still picks SAFE. Every state where an episode can stop needs the same potential, conventionally 0. Page 03 now says so, and the p6-03 lab tests it exactly.

Stage 5 — catch the leak: plant E5's bug on purpose

Reproduce the real plan's mistake: a reward branch that claims to be potential-based shaping but is a flat bonus for being in the better spot, with no Φ difference anywhere.

Reference snippet (a last-resort hint: the lab uses a different world and different names) 
def mislabeled_return(choice, true):
    """Looks like shaping. Is not: a flat bonus, no Φ(s') − Φ(s) anywhere."""
    return true[choice] + (0.5 if choice == "SAFE" else 0.0)

close = {"RISKY": -4.0, "SAFE": -4.3}             # RISKY truly better, by 0.3
print(best(close),
      best({c: shaped_return(c, close, PHI) for c in close}),
      best({c: mislabeled_return(c, close) for c in close}))
# RISKY RISKY SAFE

When the true gap is smaller than the bonus, the mislabelled version flips the answer; the real Φ-difference version, with its zero at the end, cannot, however the potentials are tuned. Page 03's theorem stops being a fact taken on faith and becomes something you broke and then compared against code that could not be broken the same way. The capstone does the same on the toy race, where the plan's flat bonus pays for every lap spent ahead.

Lab p6-cap · Code + tests · about 90 min

Two-car duel race

This page is the brief. You build the toy race with a rival on track in seven checked stages: two cars that each count a lap exactly once, an observation that can tell leading from trailing, a wake that slows the car instead of the score, being held up, passing, four reward designs, and a check that tells a safe shaping from an unsafe one. Every stage is compared lap for lap with a reference race on the same dice. The report then draws the undercut window and ranks every pit plan under each reward design.

Environment: an F1-flavoured mini: the 20-lap toy race of the earlier capstones with a scripted rival, 0.3 s a lap slower, starting 0.3 s ahead and stopping on lap 9. No training anywhere: plans are compared exactly, on shared seeds. About an hour and a half; the report runs in under a minute.
