Online chooses; target evaluates that choice

For a nonterminal successor, Double DQN chooses a*=argmax_(legal a) Qonline(s′,a), then uses y=r+γ Qtarget(s′,a*). Vanilla DQN instead uses the maximum legal target-network value directly. Both detach the target and keep true terminal continuation zero.

In the unchanged witness, online=[5,4,100], target=[1,7,99], legal=[true,true,false], reward 1 and gamma 0.5. Online selects action 0 because 5>4; target evaluates it as 1. The Double target is 1+0.5×1=1.5. Vanilla selects target action 1 and gives 1+0.5×7=4.5. Illegal actions 100 and 99 affect neither selection.

def double_targets(online_values, target_values, rewards, terminated, legal, gamma):
    if not math.isfinite(gamma) or not 0 <= gamma <= 1:
        raise ValueError("gamma in [0,1] required")
    if (online_values.ndim != 2 or target_values.shape != online_values.shape
        or legal.shape != online_values.shape
        or rewards.shape != (online_values.shape[0],)
        or terminated.shape != rewards.shape or legal.dtype != torch.bool
        or terminated.dtype != torch.bool):
        raise ValueError("invalid batch shapes or flags")
    if not all(finite(t) for t in (online_values,target_values,rewards)):
        raise ValueError("finite values required")
    active = ~terminated
    if bool((~legal[active].any(dim=1)).any()):
        raise ValueError("no legal next action")
    with torch.no_grad():
        result = rewards.clone()
        selected = online_values[active].masked_fill(~legal[active],-torch.inf).argmax(1)
        result[active] += gamma*target_values[active].gather(1,selected[:,None]).squeeze(1)
        return result

This is the exact pack contract. Integer selected indices have shape [active rows]; selected[:,None] makes the [active rows,1] index required by gather. Both online selection and target evaluation run without a gradient graph. In the previous dqn_step, double=True performs this same selection/evaluation inside a complete optimizer update.

PyTorch argmax chooses the first maximum in an exact tie. This target convention differs from the earlier epsilon-greedy behavior selector's uniform ties. A tie policy must be documented; equal online values can have different target estimates, so tie selection can change the Double target.

Recap and self-check

Does taking max of the target values after online argmax still implement Double DQN?

No. Evaluate the specific online-selected index. A second target maximum discards the selection/evaluation separation.
