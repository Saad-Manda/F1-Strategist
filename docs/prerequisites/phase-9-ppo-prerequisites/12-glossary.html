Glossary

Every term used across pages 1–11 — nothing beyond them. Keep this open while reading the Phase 9 plan or its eventual code.

Scope note

Terms belonging to multi-agent RL, self-play, or PettingZoo aren't listed here because Phase 9 doesn't use them — those belong to the Phase 8 prerequisites, and Phase 9 is architecturally independent of that phase.

Policy gradient
Directly parameterizing a policy π_θ(a|s) and adjusting θ to maximize expected return, rather than learning a value function and acting greedily with respect to it. See page 1.
Policy gradient theorem
The result ∇_θJ(θ) = E_π[∇_θ log π_θ(a|s)·G], derived via the log-derivative trick, which lets the gradient be estimated from sampled trajectories without differentiating through the environment's own dynamics. See page 1.
REINFORCE
The Monte Carlo algorithm built directly on the policy gradient theorem: for every visited (state, action), nudge θ in the direction of the log-probability gradient scaled by the full episode return. See page 1.
Log-derivative trick
The identity ∇_θP = P·∇_θ log P, used to rewrite a gradient of an expectation as an expectation of a gradient — the step that makes policy gradients estimable by sampling. See page 1.
Baseline
Any state-dependent function b(s) subtracted from the return before scaling the log-gradient by it; provably does not change the expected gradient, but can sharply reduce its variance. See page 2.
Actor-critic
Training a policy (the actor) using a separately-learned value function (the critic) as a variance-reducing baseline, rather than the raw episode return. See page 2.
Advantage function A(s,a)
Q(s,a) − V(s) — how much better an action was than a state's own average outcome; the natural choice of "return minus baseline." See page 2.
TD residual δ_t
r_t + γV(s_{t+1}) − V(s_t) — the 1-step advantage estimate, low-variance but biased when the critic's own estimates are inaccurate. See page 3.
Generalized Advantage Estimation (GAE-λ)
An exponentially-weighted sum of TD residuals, Σ(γλ)^l δ_{t+l}, that interpolates between the 1-step estimate (λ=0) and the full Monte Carlo advantage (λ=1). What Stable-Baselines3's MaskablePPO actually computes. See page 3.
Bias-variance tradeoff (in advantage estimation)
GAE's λ parameter trades a lower-variance, more-biased estimate at λ=0 against a higher-variance, unbiased one at λ=1 — the same dial as Sutton & Barto's TD(λ), applied to advantage estimation for a policy gradient. See page 3.
Probability ratio r_t(θ)
π_θ(a_t|s_t) / π_θ_old(a_t|s_t) — how much more or less likely the current policy makes an action the batch-collecting policy actually took. See page 4.
Clipped surrogate objective
min(r_t(θ)·A_t, clip(r_t(θ), 1−ε, 1+ε)·A_t) — PPO's mechanism for bounding how far a policy update can move probabilities away from the policy that collected the current batch. See page 4.
On-policy vs. off-policy
PPO is on-policy — its ratio is only meaningful for data collected under a policy close to the current one — unlike Phase 5's DQN, which reuses arbitrarily old off-policy transitions from a replay buffer. See page 4.
Entropy bonus
A term added to the training objective that rewards keeping the policy's action distribution spread out rather than collapsing early — the real plan's ent_coef, relevant given this project's sparse pit-stop rewards. See page 10.
Build-vs-buy (as an engineering heuristic)
Build from scratch when an algorithm's failure modes are loud (easy to catch by inspection); reach for a well-tested library when they're quiet (a plausible-looking result that's silently worse than it should be). See page 5.
VecEnv / DummyVecEnv / SubprocVecEnv
SB3's vectorized-environment abstraction for running several environment copies at once; DummyVecEnv steps them sequentially in one process, SubprocVecEnv steps them in parallel worker processes. See page 6.
ActionMasker / MaskablePPO
sb3-contrib's mechanism for exposing an environment's existing action-validity mask to a PPO policy, which applies the mask before sampling rather than rejecting invalid draws afterward. See page 6.
Rollout buffer
The store of observations, actions, rewards, log-probabilities, and value estimates collected during a rollout phase, used to compute GAE and run the clipped-objective update. See page 6.
n_steps / batch_size / n_epochs
How many transitions per environment are collected before an update (n_steps), how they're split into minibatches (batch_size), and how many gradient passes each minibatch gets (n_epochs) before the next rollout. See page 6.
Pickling / process-start method (fork vs. spawn)
Serializing an object to cross a process boundary; lambdas and closures cannot be pickled. Linux's fork can accidentally hide this bug by copying parent memory wholesale; Windows's spawn cannot, and raises PicklingError reliably. See page 7.
Paired training-budget comparison
The requirement that two algorithms being compared receive the same amount of environment interaction during training, not just the same number of paired evaluation seeds — distinct from, and just as necessary as, Phase 3's paired-seed evaluation discipline. See page 8.
