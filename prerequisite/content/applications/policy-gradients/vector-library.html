Translate between single and vector APIs

A Gymnasium environment reset returns (obs,info) and step returns five values with separate flags. SB3 VecEnv reset returns stacked obs only, with reset info stored separately; step returns obs,rewards,dones,infos. Done combines ending flags. An ended worker automatically resets, so its returned obs is the next episode’s start, while info["terminal_observation"] retains the true final successor.

DummyVecEnv steps environments sequentially in one process. SubprocVecEnv uses worker processes; speed depends on step cost, startup and communication overhead. Multiple workers do not imply independent scenario draws or faster execution. Use separate worker streams and measure the actual workload.

At n_steps=256,n_envs=4, one rollout has 1024 individual transitions. Batch 64 and ten epochs produce 160 nominal optimizer steps. Divisibility avoids a small final minibatch; SB3’s documented PPO behavior warns for nondivisibility rather than making it universally forbidden. Report actual model.num_timesteps, since a completed rollout can exceed a requested total.

Use the masked model and evaluation path

MaskablePPO("MlpPolicy",env,...) provides learn(total_timesteps=...) for collection and updates, and predict(obs,action_masks=mask,deterministic=True) for deterministic masked action selection. True mask entries mean legal. For subprocess use action_masks() inside each worker environment; the documented path excludes ActionMasker there. Use maskable evaluation helpers/callbacks or explicitly supplied masks, not the unmasked evaluator.

Collection stores action masks and old likelihoods for reevaluation. Library collection uses evaluation-mode network behavior without gradients, while optimization enables training mode. Predict’s deterministic choice is distinct from that layer mode. tensorboard_log configures logging; it does not make training rewards equal physical race time. Record library version and resolved defaults.

Recap and self-check

When done is true, is VecEnv’s returned observation the final one?

No. It is the reset observation; use terminal_observation and the ending metadata for continuation.
