Policy Gradients From Scratch: The REINFORCE Idea

Everything through Phase 8 learned a value function and acted greedily. Phase 9's whole family of algorithms starts from a different question: why not just optimize the policy directly?

A different objective

Phase 4 and Phase 5 both learn Q(s,a) and then act by taking argmax_a Q(s,a) — the policy is never a first-class object, it's a byproduct of the value function. Policy gradient methods flip this around: parameterize the policy itself, π_θ(a|s), a function of state with learnable parameters θ that outputs a probability over actions, and adjust θ directly so that actions which led to high return become more likely, and actions that led to low return become less likely. The objective is the expected return under the current policy:

J(θ) = E_τ~π_θ [ G(τ) ]

where τ is a full trajectory (state/action/reward sequence) and G(τ) is its total return. Compare this to Phase 4/5's objective, which was never phrased as maximizing anything about θ directly — it was minimizing TD error toward a bootstrapped target. Here there is one objective, J(θ), and the whole derivation below is about how to compute ∇_θ J(θ) so gradient ascent can be run on it directly.

The policy gradient theorem

The obstacle: J(θ) is an expectation over trajectories whose probabilities depend on the environment's (unknown) transition dynamics as well as on θ. Differentiating through unknown dynamics looks impossible. The policy gradient theorem shows it isn't necessary. Start by writing the expectation as a sum over trajectories weighted by their probability:

∇_θ J(θ) = ∇_θ Σ_τ P(τ; θ) · G(τ) = Σ_τ ∇_θ P(τ; θ) · G(τ)

Now apply the log-derivative trick — for any differentiable, strictly positive function P, ∇_θ P = P · ∇_θ log P (this is just the chain rule run in reverse: ∇_θ log P = ∇_θ P / P). Substituting:

∇_θ J(θ) = Σ_τ P(τ; θ) · ∇_θ log P(τ; θ) · G(τ) = E_τ~π_θ [ ∇_θ log P(τ; θ) · G(τ) ]

This is now an expectation again — exactly the form Monte Carlo sampling can estimate from trajectories actually rolled out. The last step removes the dependence on the environment's dynamics entirely: a trajectory's probability factors as P(τ;θ) = ρ(s_0) · Π_t π_θ(a_t|s_t) · P(s_{t+1}|s_t,a_t), and taking log turns the product into a sum, of which only the π_θ(a_t|s_t) terms depend on θ — every transition-probability term's gradient with respect to θ is exactly zero. What survives is:

∇_θ J(θ) = E_π [ Σ_t ∇_θ log π_θ(a_t|s_t) · G ]

The gradient of the expected return equals the expected value of the policy's own log-probability gradient, scaled by the return — computable purely from the policy's known functional form and a sampled return, with no knowledge of how the environment works required at all.

REINFORCE

Run an episode under the current policy and use realized returns to estimate the score gradient. For a sampled action, positive return increases its probability under a small ascent step; negative return reverses the direction. A low but positive return still supplies a positive sampled signal. Subtracting a baseline makes the signal relative to a state’s expected outcome. For descent, minimize −mean(log π(a|s) × detached_return). REINFORCE uses Monte Carlo returns instead of a one-step bootstrapped target; a single favorable sample does not prove that its action is optimal.

A hand-worked example: the softmax gradient

A tiny 2-action policy: two logits z_R, z_P, and π(a) = softmax(z)_a = e^{z_a} / (e^{z_R} + e^{z_P}). Suppose z_R = 1.0, z_P = 0.0:

π(R) = e^1 / (e^1 + e^0) = 2.718 / 3.718 = 0.731 π(P) = e^0 / (e^1 + e^0) = 1.000 / 3.718 = 0.269

The softmax log-gradient has a clean closed form worth deriving once: for the action actually taken, ∂ log π(a)/∂z_a = 1 − π(a); for every other action b, ∂ log π(a)/∂z_b = −π(b). Suppose action R was sampled and the episode returned G = +4:

∂ log π(R)/∂z_R = 1 − π(R) = 1 − 0.731 = 0.269 ∂ log π(R)/∂z_P = −π(P) = −0.269 Update (learning rate α = 0.1): z_R ← z_R + α · G · 0.269 = 1.0 + 0.1 · 4 · 0.269 = 1.0 + 0.1076 = 1.108 z_P ← z_P + α · G · (−0.269) = 0.0 + 0.1 · 4 · (−0.269) = 0.0 − 0.1076 = −0.108

The logit for the action that was actually taken increases, and the logit for the action not taken decreases — both because the return was positive. If G had been negative, both updates would flip sign: the action taken would become less likely. This one step is the entire content of REINFORCE, repeated over every timestep of every episode.

Why this isn't the end of the story

Raw returns G are noisy — the same action in the same state can be followed by wildly different total returns across episodes, purely from what happens later (Phase 3.5's DP oracle already showed how much variance exists across scenario draws; here the concern is variance in the training signal itself, not just in evaluation). REINFORCE as derived above is correct in expectation but can be very slow to converge in practice as a direct result. Page 02 fixes exactly this, without changing what the gradient estimator is aiming at.
