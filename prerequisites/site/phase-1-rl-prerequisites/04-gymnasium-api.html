Two methods every environment has

Gymnasium, the maintained successor to OpenAI's gym, is the standard interface for RL environments. Implement its contract and every library that supports Gymnasium can train on your environment, with no extra glue code. Phase 1's whole job is to implement that contract for the race.

class MyEnv(gym.Env):
    def reset(self, seed=None, options=None) -> tuple[obs, info]:
        """Start a new episode. Returns the first observation."""

    def step(self, action) -> tuple[obs, reward, terminated, truncated, info]:
        """Advance one step. Apply the action, return what happened."""

reset() starts an episode: it re-draws whatever is random and returns the first observation. step() runs one step and returns five things: the new obs, the reward, terminated (the task finished), truncated (cut off for an outside reason, such as a step limit) and info, a dictionary for anything that does not belong in the observation.

Gymnasium keeps the two end flags apart because learners treat them differently. A truncated episode still had value beyond its last step; a terminated one, by definition, has none.

The real environment works the same way. reset() samples a weather scenario and a safety-car trace and returns lap 1's observation. step() computes the lap time, adds the pit loss if the agent pitted, updates the tyres and returns the next observation. terminated becomes True when current_lap > total_laps. truncated is always False: there is no outside time limit.

Spaces tell a library what to expect

Every environment declares the shape and bounds of its observations and actions up front. That is what lets a generic library build a network with the right input and output sizes without knowing anything else. spaces.Box(low, high, shape, dtype) is an array of numbers within bounds; spaces.Discrete(n) is one of the integers 0 to n−1.

The project's observation space is Box(low=0.0, high=1.0, shape=(16,)): every one of the 16 features is scaled into [0, 1] on purpose. Networks train far more reliably when inputs share a scale, rather than one in the hundreds next to one in single digits. The action space is Discrete(6), STAY_OUT to PIT_WET.

Deep diveGridWorld, a whole Gym environment built piece by piece560 words, with code

A generic example on purpose: an agent on a 5×5 grid walks from (0, 0) to the goal at (4, 4) with four moves. It has nothing to do with racing, which is what shows which parts of the contract every environment needs and which are specific to F1 (page 05). It is the "hello world" of writing a gym.Env, and the lab tests this same class.

The constants and the class shell. Nothing but the action labels and the spaces:

import numpy as np
import gymnasium as gym
from gymnasium import spaces

UP, DOWN, LEFT, RIGHT = 0, 1, 2, 3
GRID_SIZE = 5
MAX_STEPS = 50          # gives truncation something to do -- see below

class GridWorldEnv(gym.Env):
    metadata = {"render_modes": ["human"]}

    def __init__(self):
        super().__init__()
        # obs = [row_normalized, col_normalized], both in [0, 1]
        self.observation_space = spaces.Box(low=0.0, high=1.0, shape=(2,), dtype=np.float32)
        self.action_space = spaces.Discrete(4)   # UP | DOWN | LEFT | RIGHT

Two choices carry over to the real project. The observation is scaled to [0, 1] rather than left as 0..4, for the same reason as the real 16-number vector. And the position is two numbers rather than one Discrete(25) index. A table method (page 03) would be as happy with the index, but a Box suits a neural network and mirrors how the real state is a vector of features.

reset() puts the agent back at the start and returns the first observation:

    def reset(self, seed=None, options=None):
        super().reset(seed=seed)
        self._row, self._col = 0, 0
        self._steps = 0
        return self._get_obs(), {}

    def _get_obs(self):
        return np.array([self._row / (GRID_SIZE - 1),
                          self._col / (GRID_SIZE - 1)], dtype=np.float32)

Building the observation in one helper, called from both methods, is a habit worth having early. The real F1StrategyEnv._get_obs() (page 06) exists for the same reason.

step(), movement first, clamped so the agent cannot walk off the grid:

    def step(self, action):
        assert self.action_space.contains(action)

        if action == UP:
            self._row = max(0, self._row - 1)
        elif action == DOWN:
            self._row = min(GRID_SIZE - 1, self._row + 1)
        elif action == LEFT:
            self._col = max(0, self._col - 1)
        elif action == RIGHT:
            self._col = min(GRID_SIZE - 1, self._col + 1)

Then the reward and the two endings. Every step costs −1, so the shortest path has the best return. Reaching the goal terminates; running out of steps first truncates:

        self._steps += 1
        at_goal = (self._row == GRID_SIZE - 1) and (self._col == GRID_SIZE - 1)

        reward = -1.0
        terminated = at_goal
        truncated = (self._steps >= MAX_STEPS) and not at_goal

        return self._get_obs(), reward, terminated, truncated, {}

Run it:

if __name__ == "__main__":
    from stable_baselines3.common.env_checker import check_env
    env = GridWorldEnv()
    check_env(env)   # raises if the Gymnasium contract is violated

    obs, info = env.reset(seed=0)
    total_reward = 0.0
    print(f"start  obs={obs}")
    for t in range(MAX_STEPS):
        action = RIGHT if t % 2 == 0 else DOWN   # zig-zag toward the goal
        obs, reward, terminated, truncated, info = env.step(action)
        total_reward += reward
        print(f"step {t+1:2d}  action={action}  obs={obs}  reward={reward:.1f}")
        if terminated or truncated:
            print("terminated" if terminated else "truncated")
            break
    print(f"episode return: {total_reward:.1f}")

The position climbs to [1.0, 1.0] and the run ends with terminated. Change the policy to always UP and truncated fires after MAX_STEPS instead, with a worse return, since the episode ran its full length and never reached the goal. That contrast is the cheapest way to feel why the two flags are kept apart.

Passing check_env proves the interface, not the physics

Stable-Baselines3's check_env runs an environment through a battery of checks. Do reset() and step() return the right types and shapes? Do observations stay inside the declared bounds? Is the reward a plain number? Passing it is necessary, not sufficient: it says the environment obeys the contract, not that its lap times or tyre wear are right. It is on Phase 1's Definition of Done because interface bugs slip in quietly and are hard to see by eye: a float64 where float32 was declared, an observation that rounds to 1.0000001.

Three ways to handle an illegal call

Gymnasium's core has no idea of "this action is illegal right now". The convention, from sb3-contrib's MaskablePPO, is an extra method, action_masks(), that returns one true/false value per action. Libraries that support masking call it every step and never pick a false action. Libraries that do not will try illegal ones.

So there are three designs. Clamp: turn the bad action into something harmless, as GridWorld does with walls. Mask: never offer it, as the Pit Wall's grey buttons do. Penalise: let it happen and charge for it. Clamping is fine for a wall. It is a poor fit when an action is illegal for a reason the agent should recognise, such as pitting for the compound you are on or running intermediates in the dry. There, masking is the right tool.

The rules of the race belong to the environment. Before every lap it publishes the mask, the agent picks only from legal calls, and the agent never has to learn the regulations by crashing into them. The project keeps the penalty too, as a backstop: a −500 terminal reward in step() in case an agent or a bug bypasses action_masks(). Defence in depth, not the main line.
