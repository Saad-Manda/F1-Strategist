Reading the Implementation Plan's Code

A reading guide, not a reproduction — phase-9-ppo-sb3.md's pseudocode, not a built file in src/.

Phase 9 hasn't been implemented yet, and part of what this page teaches is reading a plan critically before trusting its pseudocode — including where the plan depends on a third-party library's documented behavior rather than anything checkable in this repo. src/agents/ppo_agent.py, src/env/sb3_wrapper.py, and configs/ppo.yaml are all still just proposals in the plan file.

Reading order

  1. src/env/sb3_wrapper.py first — where page 07's fix belongs, and where the choice of n_envs and DummyVecEnv vs. SubprocVecEnv is made.
  2. configs/ppo.yaml next — page 03/04/10's parameter mapping, and the missing gae_lambda key.
  3. src/agents/ppo_agent.py's train_ppo — the .learn() call page 06 described generically, now with real arguments.
  4. scripts/compare_dqn_ppo.py last — where page 08's budget-matching fix and Finding D's eval-mode fix both need to have already landed before this script's output means anything at all.

Where each fix belongs — so you don't go looking in the wrong file

  • J1's fix (page 07) is inside make_vec_masked_envs itself, in sb3_wrapper.py — nowhere else.
  • J2's fix (page 08) is either in configs/ppo.yaml's total_timesteps (to explicitly match DQN's ~260k steps) or in the comparison notebook's plotting code (to put both learning curves on a shared environment-step x-axis) — not inside ppo_agent.py itself, which is not where a training-budget mismatch would be fixed.
  • Finding D's fix (page 10) is in the custom DuelingDoubleDQNAgent/QLearningAgent files from earlier phases, not in anything Phase 9 introduces — PPOAgent is already correct.

What the Definition-of-Done checklist would and wouldn't catch

In the same spirit as Phase 4 page 09, Phase 5 page 11, Phase 6 page 10, and Phase 8 page 10's test-by-test walkthroughs:

DoD itemWhat it catchesWhat it doesn't
MaskablePPO trains for 2M timesteps without crashingAn environment or wrapper that's broken outright (including, on this machine, the page 07 pickling crash before the fix)Whether 2M is a fair budget relative to DQN at all — J2 again
PPOAgent.select_action() respects action masks during evaluationA masking regression in the wrapper or the model callAnything about the training-budget mismatch, or DQN's own eval-mode bug
Comparison runs on 100 paired seeds, with the DP oracle's optimality gap as the shared yardstickEvaluation-time luck across scenario draws (Phase 3, assumed background)Training-time confounds — this item can pass cleanly on top of an unfixed J2, and the number it reports would still be uninterpretable

The payoff of this page: a checklist item can be perfectly well-specified and pass exactly as written, and still be answering a different question than the one it looks like it's answering — because the thing that would make its answer meaningful lives in a fix the checklist itself never names.
