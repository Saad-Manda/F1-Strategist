Glossary

Every term used across pages 1–9 — nothing beyond them. Keep this open while reading the Phase 4 plan or the code.

Scope note

Terms belonging to function approximation (neural networks, replay buffers, target networks, and the rest) aren't listed here because they aren't covered by this doc set — Phase 4 is entirely tabular. See the Phase 5 prerequisites for that vocabulary.

Bootstrapping
Updating a value estimate using another value estimate (rather than a known true value or a fully-played-out return), the way every TD target in this set uses Q(s', a') — itself still being learned — instead of the true value of s'. See page 1.
Curriculum learning
Training on an easier restricted version of the task first (here: dry weather, no safety cars) before introducing the full scenario library, so early episodes concentrate limited experience on fewer distinct table cells. Cross-reference: Phase 1's own entry. See page 8.
Epsilon decay
Linearly shrinking ε from a high starting value toward a small floor over a fixed number of steps, so exploration is heaviest early in training and rarest (but never zero) later. See page 3.
ε-greedy
An action-selection rule: with probability ε act uniformly at random among legal actions, otherwise act greedily on the current Q-table. The standard way to balance exploration against exploitation in tabular TD control. See page 3.
Learning rate (α)
The step size controlling how far a single sampled transition can move a Q-value estimate. Too high: unstable, chases noise. Too low: converges too slowly to be useful in a realistic training budget. See pages 1 & 2.
Off-policy
A learning method whose update target is computed for a different policy (Q-learning's: the greedy policy) than the one actually generating the training data (the ε-greedy behaviour policy). See page 2.
On-policy
A learning method whose update target is computed using the same policy that's actually generating the behaviour — SARSA's target uses the ε-greedy policy's own next action, exploration and all. See page 4.
Optimality gap
mean_race_time(agent) − mean_race_time(Oracle B), in seconds, reported with a paired bootstrap confidence interval — the headline evaluation metric for this phase and every phase after it. Cross-reference: Phase 3.5's own entry. See page 8.
Optimistic initialization
Starting Q-values above what's realistic (e.g. a +10 bonus on pit actions) to bias early exploration toward under-tried actions. Only meaningful relative to the true value scale — see the reward-centring entry below for why a +10 bonus can be negligible or decisive depending on that scale. See page 8.
Reward centring
Learning on reward − constant instead of raw reward (here, reward_offset="base_pace") to bring the true value scale down to a range a fixed learning rate can traverse in a realistic number of visits, without changing which policy is optimal. Cross-reference: Phase 1 page 3's proof that subtracting a constant over a fixed horizon can't change the argmax. See page 8.
State discretization / binning
Converting a continuous observation into a finite, hashable key by bucketing each dimension into a small number of discrete ranges — required because a tabular Q-function is a dictionary, and dictionaries need finite keys. See page 5.
Curse of dimensionality
The exponential growth of a discretized state space as more dimensions or finer bins are added — named here as the general reason tabular methods stop scaling, deferred to the Phase 5 prerequisites, which cover function approximation as the actual resolution. See page 5.
TD error (δ)
The gap between a fresh target estimate and the table's current value for the state-action pair just visited: δ = target − Q(s,a). Every update in this set is Q(s,a) ← Q(s,a) + α·δ. See page 1.
TD target
The fresher estimate an update nudges the table toward — r + γ·max_a' Q(s',a') for Q-learning, r + γ·Q(s',a') for SARSA (or just r if the episode terminated). See pages 1, 2 & 4.
Temporal difference (TD) learning
Estimating a value function from single sampled transitions, bootstrapping off the current estimate of what comes next, rather than solving for the exact expectation (dynamic programming) or waiting for a full episode to finish (Monte Carlo). See page 1.
