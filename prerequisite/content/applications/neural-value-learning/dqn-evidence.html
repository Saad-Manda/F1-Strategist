Read evidence labels before interpreting a curve

The network page computes its supplied gradient witness live in JavaScript. Its downloaded compare.py performs a local 200-step supervised fit with an even/odd training/held-out split when invoked; that fit is not executed or displayed as a recorded curve by this browser page. The stability ablations are recorded chain runs: 192 collected transitions, warm-up 4, update every 4, 48 optimizer steps, capacity 4, batch 4, hard target interval 8, gamma 0.9, lr 0.05, epsilon 0.3, eight-step external cap and width 8.

The variants are replay+target, latest+target, and replay+online. The latest variant repeats the latest transition four times; the online-source variant still uses no-grad labels, but no independent lagged source for those targets. Check versions and seeds in the downloadable recorded reports. Equal budgets isolate selected mechanisms imperfectly; changing sampling changes trajectories and gradients. A single variant need not win on every seed, and four identical deterministic evaluation starts are not four independent scenario samples.

These experiments show what those small configurations did when recorded. They do not establish F1 performance, a universal convergence result, or that a displayed curve came from your candidate. To gather your own evidence later, run compare.py with your candidate and document settings/seeds; this course rebuild does not initiate those training runs.

Verify independent mechanisms before production training

  1. Hand-check forward values, scalar reductions and finite-difference gradients away from ReLU kinks; batch size one must keep its axis.
  2. Check the zero-model 0.3125 loss and analytic one-step SGD weights/biases, with inputs unchanged.
  3. Prove target parameter storage is independent; online changes cannot leak before sync. Target outputs and weights must have no gradient path.
  4. Check FIFO eviction, replacement sampling, copied observations, original successor at truncation and separate streams.
  5. Test 1.5 versus 4.5 targets, illegal huge/negative values, first-index ties, true terminal empty masks, and rejection of nonterminal empty masks.
  6. Test dueling shapes, zero-mean effective deviations and raw-head offset invariance; centering includes all six outputs.
  7. Check priority powers once, positive support, insertion into empty/nonempty buffers, sampling frequencies, index alignment, duplicate policy and actual weight normalization.
  8. Inspect pre-update detached errors, per-item [B] weighting, finite gradients, clipping and target/update counters.
  9. Verify save/load compatibility and separate inference versus full resume. Evaluation must leave parameters, replay, optimizer state and counters unchanged.
  10. Compare matched seeds and physical race units against tabular and baseline policies, with aligned oracle information and uncertainty on whole-race differences.

Recap and self-check

Can the preparation checklist certify a production DQN agent because the teaching packs pass?

No. It acknowledges understanding and transfer. Production integration, environment compatibility, masks, counters and fair evaluation still require their own tests and measured evidence.
