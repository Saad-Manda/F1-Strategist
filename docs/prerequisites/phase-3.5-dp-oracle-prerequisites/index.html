Phase 3.5 DP Oracle Prerequisites

Everything — and only what — you need to read and build the exact optimality oracle described in phase-3.5-dp-oracle.md, assuming you already have Phase 1's prerequisites and nothing more.

Why this phase exists, and why it isn't "more RL"

Every phase before this one either builds the world (Phase 1) or acts in it reactively (Phase 2's dashboard, Phase 3's hand-written rules). Phase 3.5 does something different: it computes the optimal strategy for the single-car race, exactly, by exhaustively working out the consequence of every decision in every reachable situation. Nothing is learned from trial and error here — there is no exploration, no Q-table being nudged toward a target, no gradient step. Given the transition model and reward function Phase 1 already built, the optimal policy is computed directly, once, and cached.

That distinction — planning (compute the answer from a known model) versus learning (estimate the answer from experience) — is the single idea this whole doc set exists to teach. Phases 4, 5, and 9 all learn. Phase 3.5 plans. It is worth being precise about which is which, because the oracle's entire value as an evaluation tool depends on it being the *exact* answer, not an approximation competing with the agents it's meant to judge.

Scope, precisely

Phase 3.5 builds an evaluator, not an agent. So this doc set teaches exactly two things in depth: backward induction (the algorithm that makes exact solving tractable for a finite-horizon MDP) and Markov chains (the tool the oracle's weather model needs). Nothing about Q-learning, TD updates, exploration, or neural networks is covered here, even in preview — that material belongs to Phase 4 and 5's own prerequisites, and this doc set assumes none of it.

How this folder teaches the implementation half

Page 5 has you build a small backward-induction solver yourself, in your own names, across five stages — a deterministic toy first, then a stochastic exogenous event, then an action mask, then a second correlated random process sampled from a small Markov chain you fit yourself, then a sanity test comparing the DP's answer against a brute-force baseline. None of it touches the real project's code. Only page 6 names which piece of the real dp_oracle.py and weather_markov.py corresponds to which toy stage.

How to use this alongside the Phase 3.5 plan

Read pages 1–4 once, in order, treating the F1 examples inside them as illustrations only. Page 5 is hands-on: build the toy solver yourself, one complication at a time. Page 6 then re-derives the same concepts using nothing but this project's actual design decisions — the abstractions from pages 1–4 should stop feeling abstract at that point. Page 7 is the closest thing to a line-by-line reading guide for dp_oracle.py itself. Keep page 8 open as a reference while you work.
