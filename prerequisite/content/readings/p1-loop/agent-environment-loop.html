Why this matters

Before an agent can learn a useful decision, it needs a way to try a decision and see what happened. Reinforcement learning starts with this repeated exchange. In this lesson you will build that exchange, not train a learning algorithm. A simple rule for choosing actions is enough to get started.

Imagine a delivery robot on three locations in a straight line. It begins at location 0. Location 2 is its destination. The robot can move LEFT or RIGHT; moving LEFT at location 0 leaves it at 0. We will use this same small world in all four readings and in your browser and Python practice.

Two jobs, with a clear boundary

The agent chooses what to do. The environment applies that choice according to the world's rules. Here the agent chooses LEFT or RIGHT. The environment owns the robot's position, the movement rules and the signal returned after moving.

An observation is the information the environment gives the agent for its next decision. Our observation is just the current location: 0, 1 or 2. Later you will study worlds where an observation reveals only part of the underlying situation. For now, a location number is enough.

A reward is one number returned for a transition. In this toy world, arriving at the destination gives +5; every other move gives −1. These are invented score units, not seconds or money. The negative score encourages avoiding unnecessary moves. It does not directly tell the agent which action to choose.

The boundary to remember: the agent supplies an action. It does not set the environment's position or choose its own reward. Otherwise it could simply declare that it had delivered the parcel.

A complete small episode

An episode is one run from a fresh starting situation to an ending condition. For this first example, the episode ends when the robot arrives at location 2. A new run starts with a separate reset.

One delivery: always choose RIGHT.
EventAgent's choiceEnvironment's response
Start a new runNo action yetInitial observation 0
First moveRIGHTObservation 1, reward −1, keep going
Second moveRIGHTObservation 2, reward +5, episode ends

The two step rewards add to +4. The first step's reward is still −1, not +4. We will keep the step signal and the total separate; a later lesson develops accumulated returns in detail.

If the agent instead chooses LEFT, RIGHT, RIGHT, the observations after the moves are 0, 1 and 2. The rewards are −1, −1 and +5, totaling +3. The environment follows the same rules in both runs. Only the agent's choices differ.

A policy is a rule for choosing an action

The name for the agent's action-selection rule is policy. A policy can be handwritten, random or learned. Being an agent does not mean it must already contain a neural network.

LEFT = 0
RIGHT = 1

def policy(observation):
    return RIGHT

Python functions can accept an argument without using it. This policy chooses RIGHT at every location. The numbers 0 and 1 are action labels, not movement distances: action 0 means LEFT, and action 1 means RIGHT. Observation 1 separately means location 1. The same integer can have different meanings in different fields.

A random policy would choose among the available actions. Repeating a random policy is useful for inspecting an environment, but it is not the same as learning from experience. You will meet exploration and learning algorithms after the interaction contract is clear.

Recap and a self-check

The environment starts an episode and returns an observation. The agent's policy chooses an action from that observation. The environment applies the action and returns a reward, a new observation and ending information. Repeat until the run ends.

Self-check: if the policy chooses LEFT at location 0, who decides that the robot stays there?

Explanation: the environment decides, using its movement rule. The agent supplies LEFT; the environment returns observation 0 and reward −1. An observation that stays the same does not mean no transition occurred.
