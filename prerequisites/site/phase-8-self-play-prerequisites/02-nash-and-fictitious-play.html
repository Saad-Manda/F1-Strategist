The Game Underneath: Nash Equilibria and Fictitious Self-Play

Self-play isn't really chasing "the optimal policy" — it's chasing a solution to a two-player game, which is a different, relative notion of "solved."

Why "optimal policy" stops being the right target

Every phase through Phase 6 asked for the policy that maximizes expected return against a fixed environment — a well-defined, single best answer. Self-play changes what's being maximized against: each agent picks a strategy — really, a full pit-timing policy, not a single action — and the return either agent gets depends on both agents' strategies at once. That's a two-player game, not a single-agent MDP, and "optimal" no longer has a fixed target to be optimal relative to.

Nash equilibrium

The natural notion of "solved" for a game like this: a pair of strategies where neither player can improve their own return by unilaterally switching strategy, holding the other player's strategy fixed.

(π_A*, π_B*) is a Nash equilibrium if Return_A(π_A*, π_B*) ≥ Return_A(π_A, π_B*) for every alternative π_A Return_B(π_A*, π_B*) ≥ Return_B(π_A*, π_B) for every alternative π_B

Neither side has a unilateral incentive to deviate. This is a genuinely different concept from Phase 4's optimal policy: there, "optimal" meant best against a fixed world; here, each player's "best" depends on what the other player is doing, so the two definitions have to hold simultaneously, each in terms of the other.

Fictitious self-play

A classical way to actually find such a pair: each player repeatedly computes a best response — the strategy that maximizes their own return — not against the other player's single latest strategy, but against the average of the other player's strategies over all rounds played so far. Under broad conditions (provably, in zero-sum two-player games), this process converges to a Nash equilibrium. This is the theoretical backbone the checkpoint pool (page 03) is a practical approximation of.

Why "best-respond to the latest only" doesn't converge: a worked example

Matching pennies. Each player shows heads (H) or tails (T). The row player wins 1 if they match and loses 1 if they do not; the column player gets the opposite. Payoffs to the row player:

col=H col=T row=H: +1 −1 row=T: −1 +1

No pure pair is stable. At (H, H) the column player gains 2 by switching to T; at (H, T) the row player gains 2 by switching to T; and so on round the four cells. Start both on H and best-respond to the opponent's latest move, the row player first, then the column player against the row player's new move:

Round 1: row answers col's H with H (match) → col answers row's H with T (mismatch) (H, T) Round 2: row answers col's T with T → col answers row's T with H (T, H) Round 3: row answers col's H with H → col answers row's H with T (H, T) ... (H, T), (T, H), (H, T), (T, H): a cycle of length 2, for ever

Each player chases what the other just did, and neither ever settles.

Now best-respond to the running average of the opponent's play instead: fictitious play. Each player keeps counts of the other's moves (both start with one H) and best-responds to the frequencies; on a tie, take H.

Round 1: col so far 100% H → row plays H. row so far 2 H, 0 T → col plays T Round 2: col so far 1 H, 1 T (tie) → row plays H. row so far 3 H, 0 T → col plays T Round 3: col so far 1 H, 2 T → row plays T. row so far 3 H, 1 T → col plays T Round 4: col so far 1 H, 3 T → row plays T. row so far 3 H, 2 T → col plays T Round 5: col so far 1 H, 4 T → row plays T. row so far 3 H, 3 T (tie) → col plays H after five rounds: row 3 H / 3 T, col 2 H / 4 T

Each player still swings, now in longer and longer runs, but the averages close in on 50/50: 0.5002 / 0.4998 for both after 2,000 rounds. That is the game's equilibrium. Against 50/50, H and T each earn 0, so neither player can gain by deviating. Best-responding to history, not to the latest snapshot, is what makes this converge instead of cycle. Lab p8-02 runs both, and rock-paper-scissors too, where latest-only cycles with length 3.

An earlier version of this page used a two-move "rock-paper" game: rock against paper loses, paper against rock wins, the same move ties. That game cannot cycle. Paper is better than rock against either move (it dominates rock), so best responses go to (paper, paper) at once and stay there; its equilibrium is pure, not 50/50. Cycling needs a game where every move has an answer, as in matching pennies and rock-paper-scissors.

Population-based training, in one paragraph

AlphaStar (DeepMind), referenced by name in the real plan's own docstring, is the large-scale descendant of this same idea: instead of tracking one running average opponent, maintain a whole population of diverse policies and train against a mixture of them, which both approximates fictitious play's averaging and adds robustness against being over-fit to any single opponent style. This is the direct motivation for why the real plan keeps up to 50 checkpoints in a pool, rather than training against only "the current best" — the next page works through exactly how that pool approximates the running-average idea above with discrete, sampled snapshots instead of literal averaging.

Warm-up, in the page · checking an equilibrium by hand

A pair of strategies is a Nash equilibrium when neither player gains by switching on their own. In matching pennies the row player wins 1 on a match and loses 1 on a mismatch; the column player gets the opposite.

Now the game this page used to use: two moves, R and P. Paper beats rock; the same move ties. As the row player: R against R is 0, R against P is −1, P against R is +1, P against P is 0.

What is the equilibrium of the R/P game?
Worked solution for the warm-up

Matching pennies: at (H, H) the column player gains 2 by switching, so no pure pair is stable; against 50/50 both actions earn 0, so 50/50 is. Rock-paper-scissors: every move earns 0 against 1/3 each. The R/P game: P dominates R, so the equilibrium is pure, (P, P).
