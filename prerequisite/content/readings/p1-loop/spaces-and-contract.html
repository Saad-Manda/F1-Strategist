Why this matters

You can now choose actions, record transitions and stop on either ending flag. The remaining question is what counts as a valid action or observation. An environment should describe those formats before an agent begins using it.

A space is a description of permitted values. It is a contract, not a container holding the current observation. Our chain has three possible location observations and two possible action labels.

Describe the chain's values

from gymnasium import spaces

observation_space = spaces.Discrete(3)  # 0, 1 or 2
action_space = spaces.Discrete(2)       # 0 (LEFT) or 1 (RIGHT)

assert observation_space.contains(2)
assert not observation_space.contains(3)
assert action_space.contains(0)
assert not action_space.contains(2)

Discrete(3), with its default starting value, describes the integers 0, 1 and 2. The upper count is excluded: 3 is not a chain observation. The assertion succeeds only when its condition is true, so these lines are small checks you can run.

The observation space includes the terminal observation 2. Ending the episode does not make that observation invalid. A checker should be able to inspect the final transition before you reset.

Spaces describe formats, not all decision rules. LEFT is a valid action at position 0, even though it makes no movement. In other tasks an action can be representable but temporarily unavailable; such tasks need an additional legal-action rule, often called an action mask. The chain permits both actions at every nonterminal position, so it needs no mask. A later lesson develops masks and policies.

When one number becomes an array

Suppose a small grid world reports row and column together. Its observation is an array with two entries, such as [1, 2]. An array's shape describes how its entries are arranged; (2,) means one dimension with two entries. Its dtype describes the type stored in each entry.

import numpy as np
from gymnasium import spaces

grid_observations = spaces.Box(low=0, high=2, shape=(2,), dtype=np.int64)
observation = np.array([1, 2], dtype=np.int64)
assert grid_observations.contains(observation)

np is the usual short name for NumPy, a Python library for arrays. Here Box says each entry is between 0 and 2 inclusive, and each uses a 64-bit integer type. A scalar 1 does not have the required two-entry shape; an array with three entries is wrong too. For continuous measurements, an environment can specify a floating-point dtype instead. The returned data must agree with the declared space.

The grid example introduces an array format; it does not replace the supplied chain exercise. Keep its scalar Discrete(3) observations and two actions so the downloaded checks continue to test the same world. Tensor batches and matrix calculations are taught later when networks need them.

Reset the episode and seed randomness deliberately

The chain's reset clears position, the step count and the finished flag, then returns observation 0 and a fresh {"steps": 0} dictionary. In a Gymnasium environment subclass, call super().reset(seed=seed) to initialize the environment's random generator correctly, even when the small teaching transition is deterministic.

A seed initializes a random generator so a run can be reproduced under the same implementation. Resetting a stochastic environment with the same seed reproduces its random sequence; resetting with no new seed lets that generator continue. Repeatedly fixing the same seed at every episode can unintentionally keep repeating the same scenario.

Random action sampling has its own generator. If you use env.action_space.sample(), seed the action space separately for repeatable action choices. The browser and Python exercises use different random generators; identical seed numbers need not produce identical traces across the two platforms. Compare scripted RIGHT, RIGHT when checking that their contracts agree.

Check the interface, then check your task rules

from gymnasium.utils.env_checker import check_env

# ChainEnv is your implemented environment class from the exercise.
env = ChainEnv()
try:
    check_env(env, skip_render_check=True)
finally:
    env.close()

check_env checks aspects of the Gymnasium interface, including declared spaces and reset/step behavior. It interacts with the environment, so reset again before collecting your own trace. The try/finally structure closes the environment even if a check raises an error.

Rendering means producing a view for a person, such as a window or an image. Environments that support rendering declare their modes and choose a render_mode when created. The chain's Python pack declares no rendering modes; skipping the render check fits that contract. The browser's visible chain is a teaching interface, not a rendering mode you must implement in Python.

A checker cannot infer that your intended destination was 2 or that its reward should be +5. Verify those task rules independently: RIGHT, RIGHT must give observations 1 and 2, rewards −1 and +5, total +4, and termination on the second move. A one-step cap must stop at observation 1 with reward −1 and truncation. LEFT at 0 must stay at 0 and still cost −1.

Common mistake: changing the declared space to accept a mistaken output rather than fixing the output or explaining an intentional task change. Spaces and rules must describe the same environment.
