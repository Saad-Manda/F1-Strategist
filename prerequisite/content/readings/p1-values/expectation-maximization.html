Why this matters

An average answers what a specified policy does. A maximum answers which allowed decision has the greatest value. Confusing them silently replaces the policy you are evaluating with a better one, or lets the agent choose outcomes it cannot control.

Use the same action table twice

At gamma 1 in the A/B world, the action values are DIRECT 3 and VIA 5. The illegal stored entry 99 is excluded. For a policy with probability 0.5 on each legal action, evaluation gives 0.5×3 + 0.5×5 = 4. Choosing greedily gives max(3,5)=5, achieved by VIA.

If VIA probability is 0.25, evaluation gives 0.75×3 + 0.25×5 = 3.5. The greedy choice still gives 5. Changing the policy probabilities changes the average without changing this action table's largest legal value.

def backup(action_values, policy, legal):
    if not (len(action_values) == len(policy) == len(legal)) or not any(legal):
        raise ValueError("matching arrays and at least one legal action required")
    validate_distribution(policy)
    if any(p != 0 for p, allowed in zip(policy, legal) if not allowed):
        raise ValueError("policy has mass on illegal actions")
    evaluated = sum(p * q for p, q, allowed
                    in zip(policy, action_values, legal) if allowed)
    improved = max(q for q, allowed in zip(action_values, legal) if allowed)
    return evaluated, improved

assert backup([3, 5, 99], [0.5, 0.5, 0], [True, True, False]) == (4, 5)

The pack adds finite-number checks as well. This helper takes action values that already include their future consequences. Do not multiply them by gamma again. validate_distribution checks the probability row introduced in the refresher.

Outcomes are still averaged for the chosen action

Consider SAFE, which always gives 2, and RISKY, which terminates with +10 at probability 0.25 or −2 at probability 0.75. Its action value is 0.25×10 + 0.75×(−2) = 1. A greedy expected-return policy chooses SAFE because 2 exceeds 1.

Taking max(10,−2) would pretend the agent controls whether RISKY succeeds. It controls the action, not the random outcome. First average each action's possible outcomes; then compare action values. A policy that chooses SAFE and RISKY equally has value 1.5, rather than the greedy value 2.

The decision order matters. If new information arrives before a later action, a later policy may legitimately adapt to it. It cannot use a future event to retroactively change a decision already made.

Policy improvement has a specific meaning

A greedy improvement based on Q^π chooses actions with the best expected returns when followed by the old policy π. Under the usual finite discounted MDP assumptions, that construction supports policy improvement. In a general multi-step world, one improvement does not instantly turn every old Q^π entry into Q*. New continuation choices can change the values and require reevaluation.

Our A/B world has only one choice before FINISH, so always-VIA at gamma 1 is already optimal. At gamma 0.5 DIRECT and VIA tie at 3; either deterministic choice or any mixture is optimal in this particular world.

Common mistake: maximizing before masking, or averaging after silently discarding illegal probability mass. Both change the defined calculation.

Does a value of 99 for an illegal action affect the practice world's evaluated or optimal value?

No. Its policy probability must be zero and it cannot enter the legal-action maximum. The test intentionally makes the invalid entry tempting.
