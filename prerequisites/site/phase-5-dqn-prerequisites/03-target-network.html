The Target Network

The naive DQN trains a network toward a target computed by that same network, and the target moves with every update. The fix is a second, slower copy.

Your call · how slow is slowly?

The real agent nudges its second copy toward the network it trains, a fraction τ = 0.005 of the remaining gap per update. Suppose the trained network jumps once and then holds still.

How many updates until the copy has closed half the gap?

The naive idea, and why it's unstable

The target is still r + γ·max_a′ Q(s′, a′). The direct way to use a network puts its own prediction in the target, r + γ·max_a′ Q(s′, a′; θ), and trains the same θ toward it with page 02's step. Now θ has two jobs: it is the prediction being trained and the source of the target it is trained toward. Every step that fixes today's error also moves tomorrow's target.

Say the network predicts Q(s, a; θ) = 3.0 and the target, from the same weights, is 5.0. The step that raises Q(s, a; θ) toward 5.0 can also raise Q(s′, a′; θ), which lifts the target to, say, 5.4. The gap the next update sees grew. Nothing is wrong with gradient descent; one set of weights is serving two roles that are meant to converge on each other.

The fix: a second, slower copy

Keep two networks. The online network θ is trained on every update. The target network θ⁻ is used only inside the target, r + γ·max_a′ Q(s′, a′; θ⁻), and never receives a gradient. The target stops moving with each step taken toward it.

A copy that never changed would train the network toward an ever more out-of-date answer, so θ⁻ has to follow, one of two ways:

  • Hard update: every N steps, copy θ into θ⁻. Simple, and every target jumps at each copy.
  • Soft (Polyak) update: every step, θ⁻ ← τ·θ + (1 − τ)·θ⁻ with a small τ, 0.005 in the real agent. No jumps; θ⁻ trails θ smoothly. The real agent uses this one.

The numbers sayAbout 139 updates

Each update closes a fraction τ of what is left, so after n updates (1 − τ)ⁿ of the gap remains. Half is gone when n = ln 0.5 / ln 0.995 ≈ 138.3: 139 updates.

The real agent updates every 4 laps, so that is about 556 laps, about eleven 52-lap races. Slow enough to stop the chase, fast enough that over 5,000 races the target never falls far behind. The lab below lets you drag τ and watch both effects.

The target network in the case

Both networks are training machinery. A target network that lags can make training wobble, and a wobbly network might have learned a wrong number somewhere. But the champion's evaluation trains nothing: its weights are fixed, and the replay is a recording of them. A lagging copy can't move a call in the middle of an evaluated race, and the network that was recorded rates lap 9's stop 5.29 s worse.

Evidence so farRuled out: the target network. It shapes training only, and nothing trains during evaluation. Next: the other half of the training machinery, the replay memory.

A hard copy every 139 updates and a soft update at τ = 0.005 both close half a gap in about 139 updates. Which one makes every target jump at the same moment?
Worked solution for the warm-up

Half-life in updates: n = ln 0.5 / ln(1 − τ). At τ = 0.01, n = 68.97, so update 69; 276 laps; 5.3 races. One race (13 updates) needs τ = 1 − 0.5^(1/13) ≈ 0.052. At τ = 0.005 after 1,000 updates, 0.995¹⁰⁰⁰ ≈ 0.67% of the gap is left. The hard copy is the one that jumps.
