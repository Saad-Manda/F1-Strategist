Reference

Glossary

Every term from every prerequisite set, in one list. Each entry is tagged with the phase that introduces it; where a later phase sharpens a definition, that refinement sits under the original.

Phase 1 scope note

Terms belonging to algorithm training (Q-learning's tabular update rule, DQN, PPO, replay buffers, and the rest) aren't listed here because they aren't covered by this doc set; that material starts once Phase 1 is done and a later phase's prerequisites take over.

Phase 3.5 scope note

Terms belonging to learned methods (Q-values, TD error, epsilon-greedy, replay buffers, and the rest) aren't listed here because they aren't covered by this doc set — Phase 3.5 plans, it doesn't learn. See the Phase 4 and 5 prerequisites for that vocabulary.

Phase 4 scope note

Terms belonging to function approximation (neural networks, replay buffers, target networks, and the rest) aren't listed here because they aren't covered by this doc set — Phase 4 is entirely tabular. See the Phase 5 prerequisites for that vocabulary.

Phase 6 scope note

Terms belonging to self-play, PettingZoo, or genuinely non-stationary multi-agent learning aren't listed here because Phase 6 doesn't implement them — page 07 previews why Phase 8 needs them, not what they are. See the eventual Phase 8 prerequisites for that vocabulary.

Phase 8 scope note

Terms belonging to PPO, actor-critic methods, or Stable-Baselines3 aren't listed here because Phase 8 doesn't use them — those belong to the eventual Phase 9 prerequisites.

Phase 9 scope note

Terms belonging to multi-agent RL, self-play, or PettingZoo aren't listed here because Phase 9 doesn't use them — those belong to the Phase 8 prerequisites, and Phase 9 is architecturally independent of that phase.

Action Phase 1
A choice available to the agent at a given step. Here, one of six: stay out, or pit for SOFT/MEDIUM/HARD/INTERMEDIATE/WET.
Action masking Phase 1Phase 3.5
Restricting which actions are legal in a given state, provided as a boolean array alongside the observation, so the agent never has to learn illegal-action avoidance purely from trial and error.
Refined in Phase 3.5 (as “Action mask”)The boolean array of which actions are legal in a given state, computed once by dynamics.compute_action_mask and shared verbatim between the environment and the DP oracle. See pages 5 & 6.
ActionMasker / MaskablePPO Phase 9
sb3-contrib's mechanism for exposing an environment's existing action-validity mask to a PPO policy, which applies the mask before sampling rather than rejecting invalid draws afterward. See page 6.
Actor-critic Phase 9
Training a policy (the actor) using a separately-learned value function (the critic) as a variance-reducing baseline, rather than the raw episode return. See page 2.
Adam optimizer Phase 5
Gradient descent with a step size adapted separately for each weight from that weight's recent gradients. In practice each weight moves by roughly the learning rate per step whatever the size of its gradient. See pages 02 & 08.
Advantage function A(s,a) Phase 9
Q(s,a) − V(s) — how much better an action was than a state's own average outcome; the natural choice of "return minus baseline." See page 2.
Advantage stream A(s,a) Phase 5
The head of the dueling network that outputs one number per action: how much better or worse that action is than the state's average action. Its mean across actions is subtracted before it is added to the value stream. See page 05.
AEC (Agent Environment Cycle) API Phase 8
Agents act strictly one at a time in a cycle, each seeing the state left by the previous agent's action — the natural fit for turn-based games. Not used by this project. See page 4.
Agent Phase 1
The decision-maker in the RL loop; the thing being trained. Not implemented in Phase 1 — Phase 1 builds the world the agent will act in.
Backpropagation Phase 5
The chain rule applied layer by layer from the output backward, giving the gradient of the loss with respect to every weight. PyTorch's autograd does it automatically. See page 02.
Backward induction Phase 3.5
The algorithm this phase implements: starting from a known terminal value (zero, after the last lap) and working one lap at a time toward lap 1, computing each lap's exact optimal value from the lap after it. The finite-horizon special case of dynamic programming. See page 2.
Baseline Phase 9
Any state-dependent function b(s) subtracted from the return before scaling the log-gradient by it; provably does not change the expected gradient, but can sharply reduce its variance. See page 2.
Bellman equation Phase 1
The recursive relationship expressing a state's (or state-action pair's) value in terms of immediate reward plus the discounted value of what follows; derived from the return's own definition on page 3.
Best response Phase 8
The strategy that maximizes a player's own return given a fixed assumption about what the other player is doing. See page 2.
Bias-variance tradeoff (in advantage estimation) Phase 9
GAE's λ parameter trades a lower-variance, more-biased estimate at λ=0 against a higher-variance, unbiased one at λ=1 — the same dial as Sutton & Barto's TD(λ), applied to advantage estimation for a policy gradient. See page 3.
Blocking constraint Phase 6Phase 8
The rule that a trailing car within the following gap, absent a successful overtake, is held to at best the pace of the car ahead (plus dirty air). The one addition that makes track position a real resource. See page 5.
Refined in Phase 8 (as “Blocking constraint / track position as a resource”)The rule that a trailing car within a following gap, absent a successful overtake, is held to at best the pace of the car ahead — the one addition to Phase 6's dynamics that makes track position, and therefore pit-timing relative to a rival, matter at all. See page 6 (full derivation: Phase 6 page 5).
Bootstrapping Phase 4
Updating a value estimate using another value estimate (rather than a known true value or a fully-played-out return), the way every TD target in this set uses Q(s', a') — itself still being learned — instead of the true value of s'. See page 1.
Build-vs-buy (as an engineering heuristic) Phase 9
Build from scratch when an algorithm's failure modes are loud (easy to catch by inspection); reach for a well-tested library when they're quiet (a plausible-looking result that's silently worse than it should be). See page 5.
Centralized-training, decentralized-execution (CTDE) Phase 8
A shared value function (often a centralized critic) sees every agent's joint state during training, while each agent still acts on its own local observation at execution time. The more powerful, more complex alternative not used here. See page 1.
Checkpoint pool Phase 8
A stored collection of past policy snapshots sampled from during training, standing in for fictitious self-play's running average since neural network weights can't meaningfully be averaged the way a mixed strategy can. See page 3.
Clipped surrogate objective Phase 9
min(r_t(θ)·A_t, clip(r_t(θ), 1−ε, 1+ε)·A_t) — PPO's mechanism for bounding how far a policy update can move probabilities away from the policy that collected the current batch. See page 4.
Credit-assignment problem Phase 6
The difficulty of apportioning a reward that arrives many steps after the decisions that caused it back across those decisions — acute here because "final position" is known only at the very end of an episode. See page 2.
Curriculum learning Phase 1Phase 4
Training on an easier version of a task first, then increasing difficulty once the easier version is solved. This project's dry_no_sc curriculum hook is an instance of this.
Refined in Phase 4Training on an easier restricted version of the task first (here: dry weather, no safety cars) before introducing the full scenario library, so early episodes concentrate limited experience on fewer distinct table cells. Cross-reference: Phase 1's own entry. See page 8.
Curse of dimensionality Phase 4Phase 5
The exponential growth of a discretized state space as more dimensions or finer bins are added — named here as the general reason tabular methods stop scaling, deferred to the Phase 5 prerequisites, which cover function approximation as the actual resolution. See page 5.
Refined in Phase 5The resolution promised there: a network with 35,655 shared weights replaces a table of about a million separate cells. See pages 01 & 10.
Dead-code overwrite (E2, as a general pattern) Phase 6
A stateful, partial update to a quantity immediately followed by a from-scratch recomputation of that same quantity, where the recomputation silently wins. See page 6.
Deadly triad Phase 5
Sutton and Barto's name for the combination of function approximation, bootstrapping and off-policy learning. Any two are safe; all three together can make value estimates grow without limit. The target network, replay and Double DQN each weaken the interaction. See page 06.
Degenerate deterministic policy (as a general pattern) Phase 8
A greedy policy over an untrained or randomly initialized function, which is not noisy or varied but a fixed, repeatable answer — easy to mistake for a random baseline. See page 5.
Dirty air Phase 6
The real aerodynamic effect where a trailing car loses downforce, and pace, running close behind another. Modeled as a linear penalty from 0.5s at zero gap to 0s at a 1.5s gap. See page 4.
Discount factor (γ) Phase 1
A number in [0, 1] controlling how much future reward counts relative to immediate reward. This project uses γ = 1.0 — see pages 2 & 3.
Double DQN Phase 5
A change to the DQN target in which the online network chooses the next action and the target network scores it, so that one network's lucky overestimate is not also used as the value. It reduces maximization bias and does not remove it. See page 06.
Double-counting bug (E1, as a general pattern) Phase 6
Two separate pieces of code both updating the same piece of state, each unaware the other already did. See page 6.
Dueling architecture Phase 5
A Q-network with a shared trunk and two heads, a value stream and an advantage stream, combined as Q = V + (A − mean of A). It lets what is common to all actions in a state be learned once. See page 05.
Dynamic programming (DP) Phase 3.5
Solving a problem by breaking it into overlapping subproblems, solving each exactly once, and reusing the results — as opposed to recomputing shared work repeatedly. Backward induction is this project's instance of it. See page 2.
Entropy bonus Phase 9
A term added to the training objective that rewards keeping the policy's action distribution spread out rather than collapsing early — the real plan's ent_coef, relevant given this project's sparse pit-stop rewards. See page 10.
Environment Phase 1
The world the agent interacts with; here, F1StrategyEnv, implementing the Gymnasium Env contract.
Episode Phase 1
One complete run of the agent–environment loop from start to a natural end; here, one full race.
Epsilon decay Phase 4
Linearly shrinking ε from a high starting value toward a small floor over a fixed number of steps, so exploration is heaviest early in training and rarest (but never zero) later. See page 3.
ε-greedy Phase 4
An action-selection rule: with probability ε act uniformly at random among legal actions, otherwise act greedily on the current Q-table. The standard way to balance exploration against exploitation in tabular TD control. See page 3.
Expectation (over a random next state) Phase 3.5
A probability-weighted average over every possible outcome, used wherever the recursion references "the next value" but the actual next state is uncertain — the safety car, and (for Oracle B) the weather regime. See page 3.
Experience replay buffer Phase 5
A fixed-size store of past transitions. Training draws random batches from it and not the latest transition, which breaks the correlation between consecutive laps and lets each transition be learned from many times. See page 04.
Exploration vs. exploitation Phase 1
The trade-off between trying new actions to learn more (exploration) and using the best-known action so far (exploitation). Named on page 1; resolving it is an agent's job in a later phase, not Phase 1's.
Fictitious self-play Phase 8
Repeatedly best-responding to the running average of the opponent's past strategies rather than their single latest strategy; provably converges to a Nash equilibrium in two-player zero-sum games. In matching pennies, best-responding to the latest move cycles (H, T), (T, H), … for ever, while fictitious play's averages reach 50/50. A checkpoint pool sampled uniformly and never trimmed is exactly fictitious play (the Phase 8 capstone); the checkpoint pool approximates it. See page 2.
Following gap / DRS-style attempt gap Phase 6
The distance threshold (1.0s in the real plan) within which an overtake attempt becomes possible at all. See page 4.
Forward pass Phase 5
Computing a network's output from its input, layer by layer: a matrix multiply plus a bias, then a nonlinearity. See page 02.
Function approximation Phase 5
Replacing the Q-table with a function Q(s,a;θ) whose adjustable numbers θ are shared across all states, so that an update at one state also changes the estimate at similar states. See page 01.
Generalization Phase 5
An update at one state changing the estimate at states that were not part of that update, because the same weights compute both. The property a table cannot have. See page 01.
Generalized Advantage Estimation (GAE-λ) Phase 9
An exponentially-weighted sum of TD residuals, Σ(γλ)^l δ_{t+l}, that interpolates between the 1-step estimate (λ=0) and the full Monte Carlo advantage (λ=1). What Stable-Baselines3's MaskablePPO actually computes. See page 3.
Gradient clipping Phase 5
Scaling the whole gradient down, direction unchanged, whenever its norm exceeds a limit (10 in the real agent). A guard against one unusual batch, and also a cap on how far one batch can move the weights. See page 08.
Gradient descent Phase 5
The update θ ← θ − lr·∂L/∂θ: move every weight a small step in the direction that reduces the loss. The network counterpart of the tabular Q ← Q + α·δ. See page 02.
Gymnasium Phase 1
The standard Python API for RL environments (reset, step, spaces), successor to OpenAI Gym. See page 4.
Hard update Phase 5
Copying the online network's weights into the target network every N steps. Simple, and it makes every target jump at each copy. The real agent uses the soft update. See page 03.
Hazard rate Phase 3.5
The per-lap probability that a safety car starts on any given green lap, fit per circuit from historical data. Paired with a continuation probability (1 − 1/mean_duration) for laps already under a safety car. See page 3.
Huber loss (smooth L1) Phase 5
A loss that is quadratic for errors up to 1 and linear beyond, so the push on a prediction is never larger than 1. It keeps one badly wrong prediction from wrecking the weights, and gives no extra urgency for being far away. See pages 02 & 08.
Identifiability (of V and A) Phase 5
The problem that Q = V + A has no unique split: any constant can move from V to A without changing Q. Subtracting the mean advantage fixes the split to exactly one. See page 05.
i.i.d. assumption Phase 5
The assumption behind gradient descent's good behaviour that training examples are drawn independently from one fixed distribution. Consecutive laps of one race violate it; sampling from a replay buffer restores it approximately. See page 04.
Importance-sampling weight Phase 5
The factor w = (N·P(i))^(−β) that shrinks the loss of a transition sampled more often than uniform sampling would, correcting the distortion prioritized replay introduces. β is raised toward 1 over training. See page 07.
Independent learners Phase 8
Each agent has its own separate value function and learns only from its own experience, with no shared network or communication between agents. The paradigm the real plan uses. See page 1.
Learning rate (α) Phase 4Phase 5
The step size controlling how far a single sampled transition can move a Q-value estimate. Too high: unstable, chases noise. Too low: converges too slowly to be useful in a realistic training budget. See pages 1 & 2.
Refined in Phase 5The same role is played by lr, the base step size of the optimizer, which now moves every weight of the network and not one table cell. See page 02.
Log-derivative trick Phase 9
The identity ∇_θP = P·∇_θ log P, used to rewrite a gradient of an expectation as an expectation of a gradient — the step that makes policy gradients estimable by sampling. See page 1.
Loss function Phase 5
A single number measuring how wrong a prediction is, small when prediction and target are close. In DQN the prediction is Q(s,a;θ) and the target is the TD target. See page 02.
Markov chain Phase 3.5
A model of a sequence of states where the next state depends only on the current one — the Markov property, applied to a process with no actions or rewards. Oracle B's weather model is one. See page 4.
Markov property Phase 1
The requirement that the next state depends only on the current state and action, not on any earlier history. See page 2.
Maximization bias Phase 5
The upward bias of a maximum taken over noisy estimates: the max tends to pick whichever estimate landed high and then reports that lucky number as the value. Three estimates of a true 5 with ±1 noise average a max of 5.75. See page 06.
Maximum-likelihood estimate (of a transition matrix) Phase 3.5
The standard way to fit a Markov chain from data: count every observed i → j transition, divide by how often i occurred as a starting point. No iteration required. See page 4.
MDP Phase 1
Markov Decision Process — the formal tuple (S, A, P, R, γ) defining a sequential decision problem. See pages 2 & 6.
Multi-car state extension Phase 6
The three features added to Phase 1's 16-dimensional observation for Phase 6: gap_to_car_ahead, gap_to_car_behind, position_normalized. See page 1.
Nash equilibrium Phase 8
A pair of strategies where neither player can improve their own return by unilaterally switching, holding the other player's strategy fixed — the natural notion of "solved" for a two-player game. See page 2.
Ng-Harada-Russell theorem Phase 6
Cross-reference to "potential-based shaping" above — the paper's central result, worked through via a one-step Bellman-consistency check on page 3 rather than the full proof.
Non-stationarity Phase 6Phase 8
The breakdown of the fixed-environment assumption underlying standard RL convergence results, once more than one agent in the environment is learning and changing its behavior over time. See page 7; full treatment deferred to the eventual Phase 8 prerequisites.
Refined in Phase 8 (as “Non-stationarity (multi-agent case)”)The breakdown of the fixed-environment assumption once more than one agent in the world is learning and changing its own behavior, so that transitions describing an earlier version of the game no longer describe the current one. See page 1.
n_steps / batch_size / n_epochs Phase 9
How many transitions per environment are collected before an update (n_steps), how they're split into minibatches (batch_size), and how many gradient passes each minibatch gets (n_epochs) before the next rollout. See page 6.
Observation Phase 1
What the agent actually sees each step. Here, the 16-dimensional normalized vector.
Off-policy Phase 4
A learning method whose update target is computed for a different policy (Q-learning's: the greedy policy) than the one actually generating the training data (the ε-greedy behaviour policy). See page 2.
Online network Phase 5
The network with weights θ that is trained by gradient descent, used to choose actions and, in Double DQN, to choose the next action inside the target. See pages 03 & 06.
On-policy Phase 4
A learning method whose update target is computed using the same policy that's actually generating the behaviour — SARSA's target uses the ε-greedy policy's own next action, exploration and all. See page 4.
On-policy vs. off-policy Phase 9
PPO is on-policy — its ratio is only meaningful for data collected under a policy close to the current one — unlike Phase 5's DQN, which reuses arbitrarily old off-policy transitions from a replay buffer. See page 4.
Optimality gap Phase 3.5Phase 4Phase 5
mean_race_time(agent) − mean_race_time(oracle_B), in seconds, reported with a paired bootstrap confidence interval. The headline evaluation metric from Phase 4 onward. See page 6.
Refined in Phase 4mean_race_time(agent) − mean_race_time(Oracle B), in seconds, reported with a paired bootstrap confidence interval — the headline evaluation metric for this phase and every phase after it. Cross-reference: Phase 3.5's own entry. See page 8.
Refined in Phase 5Now reported for four agents side by side: DP oracle, threshold baseline, tabular Q-learning and DQN. See page 10.
Optimistic initialization Phase 4
Starting Q-values above what's realistic (e.g. a +10 bonus on pit actions) to bias early exploration toward under-tried actions. Only meaningful relative to the true value scale — see the reward-centring entry below for why a +10 bonus can be negligible or decisive depending on that scale. See page 8.
Oracle A (per-template DP) Phase 3.5
The DP solved with one specific historical weather trace fixed and known in advance — an upper bound the agent provably cannot reach, since the agent never sees the future. See pages 4 & 6.
Oracle B (Markov-weather DP) Phase 3.5
The DP solved with weather tracked as part of the state and transitioning according to a fitted Markov chain — exactly the MDP the agent actually faces, and therefore an achievable target. See pages 4 & 6.
Overcut Phase 6Phase 8
The mirror strategy: staying out longer than a rival to bank track position on old tyres before eventually pitting, betting that the time lost to degradation is worth less than the position gained by staying out. Named alongside "undercut" throughout this set; the mechanism is symmetric.
Refined in Phase 8The mirror strategy: staying out longer than a rival to bank track position on older tyres before eventually pitting. See page 6.
Overlapping subproblems Phase 3.5
The property that many different paths through a race arrive at the same state, so its value only needs to be computed once and then reused — the reason a value table (not repeated recomputation) makes backward induction tractable. See page 2.
Paired training-budget comparison Phase 9
The requirement that two algorithms being compared receive the same amount of environment interaction during training, not just the same number of paired evaluation seeds — distinct from, and just as necessary as, Phase 3's paired-seed evaluation discipline. See page 8.
Parallel API Phase 8
All agents submit actions simultaneously each timestep, with no agent seeing another's action before committing to its own. The API F1 strategy actually needs. See page 4.
Parameter sharing Phase 8
All agents use one shared network trained on everyone's combined experience — faster learning, but assumes symmetric agent roles. See page 1.
Permutation test / null baseline Phase 8
Comparing an observed statistic against the same statistic recomputed on data with the tested-for relationship deliberately destroyed (here, by shuffling the pairing between an agent's pit laps and a rival's), to check whether an observed pattern could plausibly have arisen by chance. When both quantities respond to a shared cause (here, the same safety car or scenario seed), shuffle only within groups that share it, a stratified permutation test; a plain shuffle reads the shared cause as a link. It tests for a within-race reaction, not for whether a histogram's shape is strategic. See page 7.
PettingZoo Phase 8
The library providing standard multi-agent environment APIs (AEC and Parallel) that F1PettingZooEnv is built on. See page 4.
Pickling / process-start method (fork vs. spawn) Phase 9
Serializing an object to cross a process boundary. Plain pickle stores a function by name, so it cannot ship a lambda or closure; cloudpickle, which Stable-Baselines3 uses for environment factories, can. The start method decides how a worker begins: fork copies the parent, while spawn (the only one on Windows) starts a fresh interpreter that re-imports the main module, which is why a script that starts workers needs an if __name__ == "__main__": guard. See page 7.
Planning Phase 3.5
Computing an optimal policy directly from a fully known model of the environment's dynamics and reward, with no trial and error. Contrasted with learning (Phases 4, 5, 9), which estimates a policy from sampled experience because the model isn't known. See page 1.
Policy (π) Phase 1
A mapping from states to actions (or to a distribution over actions); the agent's strategy. Not implemented in Phase 1.
Policy gradient Phase 9
Directly parameterizing a policy π_θ(a|s) and adjusting θ to maximize expected return, rather than learning a value function and acting greedily with respect to it. See page 1.
Policy gradient theorem Phase 9
The result ∇_θJ(θ) = E_π[∇_θ log π_θ(a|s)·G], derived via the log-derivative trick, which lets the gradient be estimated from sampled trajectories without differentiating through the environment's own dynamics. See page 1.
Polyak / soft update Phase 5
Moving the target network a small fraction toward the online network on every training step: θ⁻ ← τ·θ + (1−τ)·θ⁻. With τ = 0.005 it closes half of a gap in about 139 updates. See page 03.
Population-based training Phase 8
Training against a diverse population of policies rather than one running average — AlphaStar's large-scale descendant of fictitious self-play, and the direct motivation for keeping a 50-checkpoint pool. See page 2.
possible_agents / per-agent dict convention Phase 8
PettingZoo's convention of keying observations, actions, rewards, and spaces by agent id in a dict rather than a single shared value. See page 4.
Potential function Φ(s) Phase 6
The state-only function a potential-based shaping term is built from — the real plan's choice is Φ(s) = -position_normalized. See pages 3 and 9.
Potential-based shaping Phase 6
A shaping term of the specific form F(s,a,s') = γ·Φ(s') − Φ(s), for any function of state alone Φ. Ng, Harada & Russell (1999) prove this form, and only this form, preserves the optimal policy exactly. See page 3.
Prioritized experience replay (PER) Phase 5
A replay buffer that samples transitions with probability proportional to (|δ| + ε)^α, so the ones the network gets most wrong are seen more often, and corrects the resulting distortion with importance-sampling weights. See page 07.
Probabilistic overtaking model Phase 6
The sigmoid function converting a car's pace advantage over the car ahead into a probability that an attempted pass succeeds, plus a small bonus for consecutive laps spent following. See page 4.
Probability ratio r_t(θ) Phase 9
π_θ(a_t|s_t) / π_θ_old(a_t|s_t) — how much more or less likely the current policy makes an action the batch-collecting policy actually took. See page 4.
Q-learning Phase 1
Mentioned only as the algorithm whose update rule the Bellman equation (page 3) makes possible: repeatedly nudging a table of estimated Q-values toward R + γ·max Q(s',a') from observed transitions. Not implemented in Phase 1 — how to do the nudging is a later phase's prerequisite, not this doc set's.
Q-value / action-value function (Q) Phase 1
The expected return from taking a specific action in a specific state, then following a policy thereafter. See page 3.
Race position Phase 6
A car's rank among all cars in the race, computed by sorting cumulative total_time ascending. Page 5 explains why this computation alone isn't enough to make position matter strategically.
Reachability pruning Phase 3.5
Marking, in a forward pass before solving, which of the enumerated states can actually occur (e.g. tyre age can never exceed the current lap number) — cutting the states backward induction has to visit by roughly 5–10×. See page 6.
Recency-biased sampling Phase 8
The real plan's sampling rule: 70% chance of sampling from the most recent 20% of the pool, 30% chance from the older 80% — roughly a 9:1 per-checkpoint weighting of recent versus old. See page 3.
REINFORCE Phase 9
The Monte Carlo algorithm built directly on the policy gradient theorem: for every visited (state, action), nudge θ in the direction of the log-probability gradient scaled by the full episode return. See page 1.
Return (G) Phase 1
The (possibly discounted) sum of future rewards from a given point onward; what the agent is actually trying to maximize.
Reward Phase 1
The scalar feedback signal received after each step. Here, -lap_time.
Reward centring Phase 4Phase 5
Learning on reward − constant instead of raw reward (here, reward_offset="base_pace") to bring the true value scale down to a range a fixed learning rate can traverse in a realistic number of visits, without changing which policy is optimal. Cross-reference: Phase 1 page 3's proof that subtracting a constant over a fixed horizon can't change the argmax. See page 8.
Refined in Phase 5The same fix, needed for a different reason: a network's outputs start near 0 and cannot be initialised state by state, so the scale of the target has to change. See page 08.
Reward hacking Phase 1Phase 6
An agent finding a way to score well by exploiting an accident of the environment's construction rather than solving the intended problem. This project's fresh-sampled safety cars exist specifically to prevent one instance of this. See page 1.
Refined in Phase 6 (as “Reward hacking / proxy optimization”)An agent finding the fastest way to raise a proxy reward's number, which isn't always the same as the best way to achieve the real objective the proxy stands in for — the tyre-pushing risk named for gap_change on page 2, and the general lesson behind E3 on page 6.
Reward hypothesis Phase 1
The assumption underlying all of RL: any goal can be expressed as maximizing the expected cumulative sum of a scalar reward. See page 1.
Reward shaping Phase 6
Adding an extra term to a base reward to make learning easier or faster. Can be principled (potential-based, page 3) or ad-hoc (page 2's gap_change, page 3's pit-bonus example), with very different guarantees about whether the optimal policy is preserved.
Reward/dynamics disagreement (E3, as a general pattern) Phase 6
A reward that penalizes or rewards something the actual state transitions don't reflect — a reward-hacking surface, not a cosmetic inconsistency. See page 6.
Reward-scale trap Phase 5
Training that is stable and silent and makes no visible progress, because the true Q-values (about −5,000) are far from a fresh network's outputs (about 0) and every stabilising mechanism limits how far one update can move them. See page 08.
Rollout buffer Phase 9
The store of observations, actions, rewards, log-probabilities, and value estimates collected during a rollout phase, used to compute GAE and run the clipped-objective update. See page 6.
Row-stochastic (matrix) Phase 3.5
A matrix whose rows each sum to 1 — the defining property of a valid transition matrix, since the chain has to go somewhere at every step. See page 4.
Self-play evaluation trap Phase 8
The fact that a rising self-play training reward curve only proves progress relative to one's own recent history, not skill against a genuinely different opponent — the reason the real plan's Definition of Done checks the learner outside the self-play loop. See page 3.
Sparse reward Phase 6
A reward that's zero (or absent) on most steps and non-zero only rarely, such as final position, known only on the terminal step. Contrasted with Phase 1–5's fully dense -lap_time. See page 2.
State Phase 1
The underlying situation the environment is in. In this project the full state is observable, so state and observation coincide.
State discretization / binning Phase 4
Converting a continuous observation into a finite, hashable key by bucketing each dimension into a small number of discrete ranges — required because a tabular Q-function is a dictionary, and dictionaries need finite keys. See page 5.
Stationary distribution Phase 3.5
The long-run fraction of time a Markov chain spends in each state, independent of where it started. Mentioned on page 4 for completeness; not used by this project.
Stationary opponent / fixed-script rival Phase 6
An opponent whose behavior is decided in advance and never adapts to what the learning agent does — Phase 6's RivalState, which sidesteps non-stationarity entirely by construction. See pages 1, 7 & 9.
Sum tree Phase 5
A binary tree whose leaves hold priorities and whose every other node holds the sum of its two children. Sampling in proportion to priority and updating one priority both take a number of steps equal to the tree's depth. See page 07.
Target network Phase 5
A second copy of the Q-network, with weights θ⁻, used only to compute targets and never trained directly, so the target does not move with every update of the network chasing it. See page 03.
TD error (δ) Phase 4Phase 5
The gap between a fresh target estimate and the table's current value for the state-action pair just visited: δ = target − Q(s,a). Every update in this set is Q(s,a) ← Q(s,a) + α·δ. See page 1.
Refined in Phase 5Also used as a sampling signal: prioritized replay draws a transition more often the larger its |δ| was when last seen. See page 07.
TD residual δ_t Phase 9
r_t + γV(s_{t+1}) − V(s_t) — the 1-step advantage estimate, low-variance but biased when the critic's own estimates are inaccurate. See page 3.
TD target Phase 4
The fresher estimate an update nudges the table toward — r + γ·max_a' Q(s',a') for Q-learning, r + γ·Q(s',a') for SARSA (or just r if the episode terminated). See pages 1, 2 & 4.
Temporal difference (TD) learning Phase 4
Estimating a value function from single sampled transitions, bootstrapping off the current estimate of what comes next, rather than solving for the exact expectation (dynamic programming) or waiting for a full episode to finish (Monte Carlo). See page 1.
Terminal condition Phase 3.5
V_(T+1)(s) = 0 for every state — the anchor that makes backward induction a single, non-circular pass rather than requiring iteration to convergence. See page 2.
Terminal cut-off Phase 5
The factor (1 − done) in the target, which removes the bootstrapped future term on the last transition of an episode. Terminal targets are the only ones containing no estimate, and anchor all the others. See page 06.
Track position as a resource Phase 6
The idea that being ahead has value in itself, beyond the time already banked to get there — only true once a blocking constraint exists; without one, position is purely a readout of accumulated time. See page 5.
Transition function (P) Phase 1
The (possibly stochastic) rule for how the environment moves from one state to the next given an action. Here, compute_lap_time plus the episode bookkeeping in step().
Transition matrix Phase 3.5
The n × n table of probabilities P[i,j] = P(next = j | current = i) that fully describes a Markov chain. See page 4.
Undercut Phase 6Phase 8
Pitting before a rival on comparable pace so that fresh tyres convert into track position the rival can't immediately take back, because — with a blocking constraint in place — the rival can't simply drive around a stopped or slower car. See page 5.
Refined in Phase 8Pitting before a rival on comparable pace so fresh tyres convert into track position the rival can't immediately take back — unreachable as a learned behavior until the blocking constraint above exists. See page 6.
Value function (V) Phase 1
The expected return from a given state onward, following a given policy. See page 3.
Value of perfect foresight Phase 3.5
Oracle A − Oracle B: how much a strategist would gain from genuinely knowing the future weather, versus only being able to reason about it probabilistically. An interesting F1 quantity in its own right, not a measure of RL underperformance. See page 6.
Value stream V(s) Phase 5
The head of the dueling network that outputs a single number: how good the state is regardless of the action taken. See page 05.
VecEnv / DummyVecEnv / SubprocVecEnv Phase 9
SB3's vectorized-environment abstraction for running several environment copies at once; DummyVecEnv steps them sequentially in one process, SubprocVecEnv steps them in parallel worker processes. See page 6.
Zero-noise expectation shortcut Phase 3.5
Calling dynamics.compute_lap_time(..., rng=None) to get the exact expected lap time rather than a sampled one — valid because the environment's noise term is additive and zero-mean, so dropping it doesn't approximate the expectation, it equals it exactly. See page 3.
