RL Fundamentals

The agent–environment loop, the reward hypothesis, and the vocabulary every later page is built from.

The agent–environment loop

Reinforcement learning has one loop, repeated over and over:

  1. The environment hands the agent an observation describing the current situation.
  2. The agent chooses an action.
  3. The environment applies that action, moves to a new situation, and hands back a reward (a single number saying how good that step was) plus the next observation.
  4. Repeat until the episode ends.

Nothing else in RL is more than an elaboration of this loop. The agent's only job is to learn a policy — a rule for picking actions from observations — that makes the running total of rewards as large as possible.

Generic example

In a video game, the observation might be the screen pixels, the action a joystick direction, and the reward the score delta. The agent never sees "the rules of the game" directly — it only ever sees observation → action → reward, over and over, and has to infer good behaviour from that alone.

This project

The observation is a 16-number description of the race (laps remaining, tyre compound and age, weather, whether a safety car is out); the action is one of six choices (stay out, or pit for one of five compounds); the reward is the negative lap time. Nothing about "tyre degradation" or "the pit-loss penalty" is ever told to the agent directly — it has to discover, purely from rewards, that pitting for softs late in dry weather is a bad idea.

The reward hypothesis

RL rests on one assumption, sometimes called the reward hypothesis: any goal you care about can be expressed as maximizing the expected cumulative sum of a scalar reward signal. This is a real design constraint, not a footnote — if you can't collapse "what we want" into a single number per step, you don't have an RL problem yet, you have a reward-design problem to solve first.

This project

This is exactly the tension Phase 1's "Reward design" section wrestles with. The obvious goal is "win the race," but the reward actually used is -lap_time on every single lap. The plan spends real effort proving that summing -lap_time over the whole race is mathematically identical to -total_race_time — with no shortcut left for the agent to exploit, like getting free reward by pitting during a safety car. You'll see this same proof step again in Phase 5's reward-shaping decisions.

Episodes, and episodic vs. continuing tasks

An episode is one complete run of the loop from a starting situation to a natural ending. Some RL tasks never end (continuing tasks — e.g., a thermostat runs forever), but most have a clear boundary, and this project does too: one episode = one full race, from lap 1 to the chequered flag. Phase 1 fixes the episode length in advance, which is a fixed-length episode. This matters later because terminated (the race genuinely finished) and truncated (we cut it off early for some other reason) are different signals in Gymnasium, and Phase 1 explicitly sets truncated = False always — there's no artificial cutoff, the episode only ends when the race does.

Exploration vs. exploitation

At any point the agent can either exploit — take the action it currently believes is best — or explore — try something else, to find out if it's actually better. Too much exploitation and the agent gets stuck on a mediocre strategy it found early and never questions again. Too much exploration and it never settles into using what it's learned. Balancing the two is a central, recurring problem across almost every RL algorithm. Phase 1 doesn't need a resolution to it — no algorithm is trained here — but it's worth naming because it's the reason the next section (fresh-sampled stochasticity) matters as much as it does: an environment an agent can memorize gives exploration nothing real to discover.

This project

Phase 1 doesn't implement exploration itself — that's the agent's job, in Phases 3 onward — but it shapes how hard the problem is. The curriculum hook (options={"curriculum": "dry_no_sc"}) exists specifically to make early exploration easier: by restricting episodes to dry weather with no safety cars, the agent faces a smaller, less noisy version of the problem first. This is curriculum learning — start simple, increase difficulty once the easy version is solved.

Why stochasticity is sampled fresh, not replayed

A subtler point Phase 1 is very deliberate about: safety cars are sampled from a hazard process every episode, not replayed from a fixed set of historical race templates. If only 3–4 fixed scenarios existed, and the agent's observation includes laps_remaining, the agent could simply memorize "an SC always arrives around lap 12 in scenario #2" — a lookup table dressed up as a policy, learning nothing generalizable. This failure mode has a name: reward hacking (or environment overfitting) — the agent finds a way to score well that exploits an accident of the environment's construction rather than solving the real problem.

Guarding against it is why the plan splits weather (replayed from real history, where variety is desirable) from safety cars (freshly sampled every episode, where memorization would be a bug).
