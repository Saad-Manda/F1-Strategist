Page 01 / 12 — Foundations

From a Table Cell to a Function

Nothing about the TD-error idea ever required a table. It only ever needed something that could store and update a number per state-action pair — Phase 5 changes what that something is.

The tabular update, restated as what it actually is

Phase 4 page 02's update rule: Q(s,a) ← Q(s,a) + α·δ, where δ = target − Q(s,a). Read mechanically, that line does exactly one thing — it overwrites one cell of a lookup table with a slightly nudged value. Nothing in the derivation of δ, or in the reasoning behind why nudging toward a sampled target eventually converges, depended on the table being the storage mechanism. The table was simply the most direct way to associate a number with each (s,a) pair, not a requirement of the underlying idea.

The curse of dimensionality, with this project's own numbers

Phase 4 page 05 already did the arithmetic: eight binned observation dimensions produce a table with 518,400 states, each needing its own independently-learned number per action. Two states that differ by exactly one lap of tyre age, everything else equal, get assigned to completely unrelated table cells — the table has no way to know they're similar situations, so a hundred visits to one cell teach it nothing whatsoever about the neighbouring cell one lap over. Phase 6's plan (adding per-rival gap features) only multiplies this further: every new continuous-ish dimension that needs binning multiplies the total state count by however many bins it's given, while learning a good estimate for any one cell still takes roughly the same number of visits regardless of how many other cells now exist.

This is the general shape of the curse of dimensionality: the size of a discretized state space grows exponentially in the number of dimensions binned, while the training budget (episodes × steps per episode) stays fixed. A table that was already straining to get enough visits per cell in Phase 4's 8-dimensional space becomes hopeless once a 9th or 10th dimension is added — not because the algorithm got worse, but because the representation's cost scales in a way the training budget can't keep up with.

Function approximation, defined generally

Replace the table lookup Q(s,a) with a parameterized function Q(s,a;θ), where θ is a (large) vector of adjustable numbers — the network's weights. Instead of an update overwriting one cell, an update nudges all of θ a little in a direction that reduces error on the transition just seen. Because the same weights are shared across every state the function is ever asked about, a nudge from training on lap 27 also moves the function's output for lap 26 and lap 28, even though neither was directly involved in that update. This sharing — one update changing predictions at states it never directly visited — is what generalization means here, concretely, and it's the property no table can ever have: a table's cells are, by construction, completely independent of one another.

The catch, named up front

Sharing information across states cuts both ways. An update that helps the function's prediction at a nearby state can just as easily hurt its prediction at a state it previously handled well, if the two states are treated as more similar than they should be, or if the update is allowed to move θ too far in one step. Choosing θ so the function actually improves overall, rather than forgetting what it just learned elsewhere every time it's nudged, is what the rest of this set is about: gradient descent (page 02) is the mechanism that nudges θ at all; the target network (page 03) and experience replay (page 04) exist specifically because training a network online, without them, destabilizes that nudging badly enough to prevent learning altogether.

What carries over unchanged

Everything about what is being learned stays exactly as Phase 4 left it. The Bellman-derived target — r + γ·max_a' Q(s',a') for the off-policy case Phase 4 page 02 derived — is still the thing every update tries to close the gap toward. The TD-error idea, δ = target − Q(s,a), is still the signal driving every update. Even the ε-greedy exploration schedule from Phase 4 page 03, decay arithmetic and all, is reused without modification (page 10 confirms the real agent's epsilon_start/epsilon_end/epsilon_decay_steps values). The only thing this phase changes is how the number gets stored and updated — a function with shared parameters instead of independent table cells, updated by a gradient step instead of an overwrite. Page 02 makes that gradient step concrete.
