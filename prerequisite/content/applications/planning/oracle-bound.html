Two references answer different information questions

Oracle A knows one full weather trace while choosing its policy. It still uses the specified safety-car uncertainty unless that information is also explicitly privileged. Oracle B observes the current weather and averages future weather using the fitted Markov law. Under matching dynamics and observation assumptions, B is an attainable optimal-policy reference in principle; A measures the value of added weather information.

Align distributions before stating a bound. For positive costs, E[C_A] ≤ C_B when A can reproduce every B policy and both are evaluated on the same weather law and starting conditions. For negative-time rewards the inequality reverses. The information advantage is C_B−E[C_A] ≥ 0, or E[R_A]−R_B ≥ 0. Do not subtract A−B costs and describe the negative result as saved time.

Perfect foresight is not always strictly useful: if every weather trace has the same best action, equality is possible. A nonprivileged policy may also match A on particular runs. The bound concerns optimal expected performance under aligned information sets, not a guarantee that every noisy race is slower than an oracle average.

A real-scale cell retains the toy structure

At lap 50 of 55, MEDIUM age 6, dry/green, two dry compounds already used, six laps remain inclusively. Illustrative current timing constants give 92 + 6×0.03 + 6×1.6×0.033 = 92.4968 seconds. No cliff, mismatch or warmup term applies here. Use the shared calibrated function in the actual implementation.

Suppose next SC probability is 0.2 and next dry/damp probabilities are 0.8/0.2, independently conditional on today's state. For STAY's next MEDIUM age 7, successor cost values are 470 dry/green, 480 damp/green, 500 dry/SC and 510 damp/SC. For a legal PIT target's fresh successor they are 450, 460, 480 and 490. Green pit loss is 22:

weights = [0.64, 0.16, 0.16, 0.04]
stay_future = sum(p*c for p,c in zip(weights, [470,480,500,510]))
pit_future = sum(p*c for p,c in zip(weights, [450,460,480,490]))
stay_total = 92.4968 + stay_future
pit_total = 92.4968 + 22 + pit_future
assert abs(stay_total - 570.4968) < 1e-9
assert abs(pit_total - 572.4968) < 1e-9

STAY wins by two seconds in this stipulated cell. Its current cost is fixed; expectation concerns the successor. The pit successor must update compound, age and usage, rather than reuse STAY's successor table entries. These supplied successor numbers illustrate a solved slice, not a claimed measurement from production.

Report algorithmic and information gaps separately

Define agent gap in seconds as mean_time(agent)−mean_time(Oracle B) on paired scenarios/seeds. If B averages 5000 seconds, an agent 5040 and an aligned A reference 4990, the agent's B-gap is 40 and weather-information advantage 10. The agent's gap to A is 50, combining the two.

Use the same weather mode. A fixed historical-template counterfactual and a fitted-chain B rollout are not automatically two policies on the same task. Sampling error can produce a negative measured B-gap; a statistically meaningful advantage over a correctly solved matched model calls for checking assumptions, masks, information or solver accuracy.
