Page 05 / 12 — What the real agent adds, part one

The Dueling Architecture: Separating "How Good Is This Spot" from "Which Move Helps"

On this problem, one action is correct on roughly 85% of laps. A network that must learn six independent numbers per state is solving a harder problem than it needs to.

The motivating observation

In this project's races, "stay out" is the correct action on roughly 85% of laps — the real plan's own estimate. A single shared output head, predicting Q(s,a) for all six actions from the same trunk with no further structure, still has to learn a genuinely separate number for every one of those six actions at every state, even though five of them are usually near-identical, low-value alternatives to the one action that actually matters at that moment.

Value/advantage decomposition

Split the question "how good is action a at state s" into two smaller questions:

  • V(s) — how good is it to be in this state at all, regardless of which action gets taken next.
  • A(s,a) — how much better or worse is this specific action than the state's average action.

Combined: Q(s,a) = V(s) + A(s,a). Why this helps concretely for this problem: V(s) can absorb "it's lap 15, tyres are fine, this is generally a fine spot to be in" once, shared across all six actions, while A(s,a) only has to capture the much smaller signal "...and pitting right now specifically would be a mistake." The large, mostly action-independent part of the answer and the small, action-specific correction are learned by two different parts of the network, instead of one head having to learn their sum from scratch, independently, for each of six actions.

The identifiability problem

Q(s,a) = V(s) + A(s,a) has no unique solution for V and A given only Q. Adding any constant c to V(s) and subtracting the same c from every A(s,a) at that state leaves every Q(s,a) unchanged:

Suppose the true Q-values at some state are Q = [-2, -5, -3] (3 actions) Decomposition A: V = 0, A = [-2, -5, -3] → V + A = [-2, -5, -3] ✓ Decomposition B: V = -10, A = [8, 5, 7] → V + A = [-2, -5, -3] ✓ Both decompositions produce identical Q. Nothing in the sum alone can tell them apart.

A network trained only on the resulting Q could put an arbitrary, unconstrained shifting constant into either stream — V could drift toward +1,000,000 and A toward −1,000,002 and the loss would never notice, since the loss only ever sees the sum.

The fix: pin the advantage stream's mean to zero

Replace the plain sum with Q(s,a) = V(s) + (A(s,a) − mean_a A(s,·)). Subtracting the mean of A(s,·) forces mean_a A(s,·) = 0 to hold by construction, which removes the shifting degeneracy: exactly one decomposition now satisfies both "sums to the right Q" and "the advantage stream's mean is zero" — decomposition B above fails that second requirement (mean([8, 5, 7]) ≈ 6.67 ≠ 0), decomposition A passes it (mean([-2, -5, -3]) ≈ -3.33... — actually check with the corrected version below):

Decomposition A, mean-subtracted: A' = A - mean(A) = [-2, -5, -3] - (-10/3) = [-2+3.33, -5+3.33, -3+3.33] = [1.33, -1.67, 0.33] V' = V + mean(A) = 0 + (-10/3) = -3.33 Check: V' + A' = [-3.33+1.33, -3.33-1.67, -3.33+0.33] = [-2, -5, -3] ✓, and mean(A') = 0 ✓ Decomposition B, mean-subtracted: A' = A - mean(A) = [8, 5, 7] - 6.67 = [1.33, -1.67, 0.33] V' = V + mean(A) = -10 + 6.67 = -3.33 Check: same V' and A' as decomposition A — the mean-subtraction collapses every degenerate decomposition onto the same unique one.

Both starting decompositions land on the same (V', A') once the mean is subtracted — the formula makes the split unique, no matter what arbitrary constant a not-yet-converged network happened to put into V versus A.

Architecture: two heads on a shared trunk

Matched to the real DuelingDQN: the shared trunk from page 02 (Linear(16→128) → ReLU → Linear(128→128) → ReLU) feeds two separate small heads — a value stream (Linear(128→64) → ReLU → Linear(64→1), producing the single scalar V(s)) and an advantage stream (Linear(128→64) → ReLU → Linear(64→6), producing one scalar per action, A(s,·)). The two streams' outputs are combined by this page's formula to produce the six Q(s,a) values the rest of the agent uses exactly as before. This is the first place the primer's forward-pass mechanics (page 02) get used on something DQN-specific rather than a toy example — everything about how each linear layer and ReLU computes its output is unchanged; only the fact that there are now two output heads sharing one trunk is new.
