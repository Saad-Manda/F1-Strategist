Why this matters

Identifying hidden information is useful only if you can decide what to do about it. A simulator can have Markov state while the policy receives a partial observation. This is often called a partially observable decision problem. Calling the observation “state” does not remove that limitation.

Three repairs, with different assumptions

Add a measurement. In the battery example, expose a charge sensor if the intended agent could obtain that reading. In the switch exercise, report mode 0 or 1. This directly distinguishes the situations responsible for different CLAIM rewards.

Remember a sufficient summary. Suppose the initial switch mode is known to be 0 and every FLIP succeeds. Track one bit: an even number of FLIPs leaves mode 0, an odd number leaves mode 1. Remembered action parity reconstructs the state without retaining the whole log. If FLIPs sometimes fail without a revealing observation, this reconstruction is no longer exact.

Track uncertainty. If the initial mode is unknown, a policy can maintain a belief: probabilities assigned to possible hidden states based on available evidence. A 50/50 belief means neither mode is known. Deterministic FLIP exchanges the probabilities, so a 50/50 belief remains 50/50. CLAIM then has expected reward 0: half the runs give +1 and half give −1. The probability refresher later in this module explains that weighted calculation.

A belief is information about state, not the simulator state itself. Exact belief updating needs a model of transitions and observations. A remembered history can support estimation without providing perfect certainty; more memory is not automatically more information.

Implement the exercise's sufficient encoder

The Python pack supplies the switch mechanics. Your function encode_state(mode, remaining=None) represents the state it is given. The optional remaining argument belongs to an intrinsic deadline variant, not the base infinite-choice switch.

def encode_state(mode, remaining=None):
    if type(mode) is not int or mode not in (0, 1):
        raise ValueError("mode must be 0 or 1")
    if remaining is None:
        return mode
    if type(remaining) is not int or remaining < 0:
        raise ValueError("remaining must be a nonnegative integer")
    return (mode, remaining)

None means no deadline was provided. A tuple groups the mode and countdown without collapsing them to one ambiguous number. The explicit type checks reject a Boolean pretending to be a mode or countdown, even though Python otherwise treats booleans as integer-like values.

This encoder does not invent a new sensor for an already deployed robot. It defines the information made available in a teaching model. If a real sensor cannot measure charge, an encoder cannot recover it by rescaling location or adding more copies of the same observation.

Recap and practice

Choose the information contract first, then an encoding that preserves it. Adding features from a private future scenario can improve a score by leaking information rather than improving the policy. Evaluate what a feature means and when it becomes available.

Common mistake: merging mode 0 with mode 1, or merging two different intrinsic countdowns, merely because the resulting table is smaller. That aggregation changes the decision problem when the merged situations need different actions.

If reset samples a uniform hidden mode, does remembering FLIPs reveal its initial value?

No. FLIP parity identifies how the unknown initial mode changed, not what it was. A revealing measurement or additional evidence is needed.
