Page 05 / 11 — A lesson in disguised determinism

Why the Pool's First Member Matters

"Epsilon = 0.0" and "random opponent" sound similar. They are not the same thing, and confusing them poisons the very first round of training.

What the real plan does

The real plan's train_self_play seeds the checkpoint pool before any training happens: pool.add(learner, episode=0) stores a freshly initialized, entirely untrained network. Then pool.sample() sets epsilon = 0.0 — fully greedy — on whatever checkpoint it returns, including this very first one.

The general lesson, before the specific bug

A greedy policy over a randomly initialized network is not noisy, varied, or weak-but-fair. It is a deterministic function of that network's fixed random weights: given the same observation, it picks the same action, every single time, for as long as that checkpoint stays in the pool's rotation. "Untrained" describes how good the policy is. It says nothing about how varied the policy is — and those are independent properties that are easy to conflate.

Concretely, what goes wrong

If the untrained network's fixed initial weights happen to favor the "pit" action for whatever observation values it's fed, the very first opponent in the pool pits on lap 1 — and every lap after that, forever, because greedy selection over a network that never updates always returns the same answer. That's not merely a bad opponent; it's a bad opponent in a fixed, entirely predictable, non-representative way. The learner's very first training signal comes from a degenerate, repeatable game, not from anything resembling the range of strategies it will eventually have to handle.

Why this is easy to miss

It looks superficially reasonable: "of course an untrained network makes a weak opponent to start with — that's fine, the learner will quickly outgrow it." That framing is about to be wrong in a way that isn't about weakness at all. The danger isn't that the first opponent is weak — a weak-but-varied opponent would be a perfectly fine, even useful, starting point. The danger is that it has zero variance: every one of the (up to) 1000 episodes before the next checkpoint is added is spent playing against the exact same fixed response, which teaches the learner to exploit one specific quirk of one specific random initialization rather than anything general.

The fix

Either of two changes genuinely fixes this, for different reasons:

  • Seed with a stochastic policy — epsilon = 1.0, literally uniform-random action selection, for the pool's earliest entries. This restores genuine variance immediately, at the cost of the opponent being uniformly unskilled rather than merely simple.
  • Seed with Phase 3's rule-based agents (assumed background) — the real plan's stronger suggestion. These are simultaneously competent and diverse (several different named strategies), giving the learner a meaningful curriculum from episode 0 rather than either noise or a degenerate greedy trap.
The reusable shape of this trap

"A greedy policy over an untrained or random function is not automatically a random baseline" generalizes well past self-play. Anywhere code substitutes "hasn't learned yet" for "behaves like noise" — an untrained classifier used as a control group, an unfitted model used as a null hypothesis — the same gap can hide: the thing that's supposed to represent variety may in fact be a single, silently repeatable answer.
