Glossary

Every term used across pages 1–7 — nothing beyond them. Keep this open while reading the Phase 1 plan or the code.

Scope note

Terms belonging to algorithm training (Q-learning's tabular update rule, DQN, PPO, replay buffers, and the rest) aren't listed here because they aren't covered by this doc set; that material starts once Phase 1 is done and a later phase's prerequisites take over.

Action
A choice available to the agent at a given step. Here, one of six: stay out, or pit for SOFT/MEDIUM/HARD/INTERMEDIATE/WET.
Action masking
Restricting which actions are legal in a given state, provided as a boolean array alongside the observation, so the agent never has to learn illegal-action avoidance purely from trial and error.
Agent
The decision-maker in the RL loop; the thing being trained. Not implemented in Phase 1 — Phase 1 builds the world the agent will act in.
Bellman equation
The recursive relationship expressing a state's (or state-action pair's) value in terms of immediate reward plus the discounted value of what follows; derived from the return's own definition on page 3.
Curriculum learning
Training on an easier version of a task first, then increasing difficulty once the easier version is solved. This project's dry_no_sc curriculum hook is an instance of this.
Discount factor (γ)
A number in [0, 1] controlling how much future reward counts relative to immediate reward. This project uses γ = 1.0 — see pages 2 & 3.
Environment
The world the agent interacts with; here, F1StrategyEnv, implementing the Gymnasium Env contract.
Episode
One complete run of the agent–environment loop from start to a natural end; here, one full race.
Exploration vs. exploitation
The trade-off between trying new actions to learn more (exploration) and using the best-known action so far (exploitation). Named on page 1; resolving it is an agent's job in a later phase, not Phase 1's.
Gymnasium
The standard Python API for RL environments (reset, step, spaces), successor to OpenAI Gym. See page 4.
Markov property
The requirement that the next state depends only on the current state and action, not on any earlier history. See page 2.
MDP
Markov Decision Process — the formal tuple (S, A, P, R, γ) defining a sequential decision problem. See pages 2 & 5.
Observation
What the agent actually sees each step. Here, the 16-dimensional normalized vector.
Policy (π)
A mapping from states to actions (or to a distribution over actions); the agent's strategy. Not implemented in Phase 1.
Q-learning
Mentioned only as the algorithm whose update rule the Bellman equation (page 3) makes possible: repeatedly nudging a table of estimated Q-values toward R + γ·max Q(s',a') from observed transitions. Not implemented in Phase 1 — how to do the nudging is a later phase's prerequisite, not this doc set's.
Q-value / action-value function (Q)
The expected return from taking a specific action in a specific state, then following a policy thereafter. See page 3.
Return (G)
The (possibly discounted) sum of future rewards from a given point onward; what the agent is actually trying to maximize.
Reward
The scalar feedback signal received after each step. Here, -lap_time.
Reward hacking
An agent finding a way to score well by exploiting an accident of the environment's construction rather than solving the intended problem. This project's fresh-sampled safety cars exist specifically to prevent one instance of this. See page 1.
Reward hypothesis
The assumption underlying all of RL: any goal can be expressed as maximizing the expected cumulative sum of a scalar reward. See page 1.
State
The underlying situation the environment is in. In this project the full state is observable, so state and observation coincide.
Transition function (P)
The (possibly stochastic) rule for how the environment moves from one state to the next given an action. Here, compute_lap_time plus the episode bookkeeping in step().
Value function (V)
The expected return from a given state onward, following a given policy. See page 3.
