Glossary

Every term used across pages 1–7 — nothing beyond them. Keep this open while reading the Phase 3.5 plan or the code.

Scope note

Terms belonging to learned methods (Q-values, TD error, epsilon-greedy, replay buffers, and the rest) aren't listed here because they aren't covered by this doc set — Phase 3.5 plans, it doesn't learn. See the Phase 4 and 5 prerequisites for that vocabulary.

Action mask
The boolean array of which actions are legal in a given state, computed once by dynamics.compute_action_mask and shared verbatim between the environment and the DP oracle. See pages 5 & 6.
Backward induction
The algorithm this phase implements: starting from a known terminal value (zero, after the last lap) and working one lap at a time toward lap 1, computing each lap's exact optimal value from the lap after it. The finite-horizon special case of dynamic programming. See page 2.
Dynamic programming (DP)
Solving a problem by breaking it into overlapping subproblems, solving each exactly once, and reusing the results — as opposed to recomputing shared work repeatedly. Backward induction is this project's instance of it. See page 2.
Expectation (over a random next state)
A probability-weighted average over every possible outcome, used wherever the recursion references "the next value" but the actual next state is uncertain — the safety car, and (for Oracle B) the weather regime. See page 3.
Hazard rate
The per-lap probability that a safety car starts on any given green lap, fit per circuit from historical data. Paired with a continuation probability (1 − 1/mean_duration) for laps already under a safety car. See page 3.
Markov chain
A model of a sequence of states where the next state depends only on the current one — the Markov property, applied to a process with no actions or rewards. Oracle B's weather model is one. See page 4.
Maximum-likelihood estimate (of a transition matrix)
The standard way to fit a Markov chain from data: count every observed i → j transition, divide by how often i occurred as a starting point. No iteration required. See page 4.
Oracle A (per-template DP)
The DP solved with one specific historical weather trace fixed and known in advance — an upper bound the agent provably cannot reach, since the agent never sees the future. See pages 4 & 6.
Oracle B (Markov-weather DP)
The DP solved with weather tracked as part of the state and transitioning according to a fitted Markov chain — exactly the MDP the agent actually faces, and therefore an achievable target. See pages 4 & 6.
Optimality gap
mean_race_time(agent) − mean_race_time(oracle_B), in seconds, reported with a paired bootstrap confidence interval. The headline evaluation metric from Phase 4 onward. See page 6.
Overlapping subproblems
The property that many different paths through a race arrive at the same state, so its value only needs to be computed once and then reused — the reason a value table (not repeated recomputation) makes backward induction tractable. See page 2.
Planning
Computing an optimal policy directly from a fully known model of the environment's dynamics and reward, with no trial and error. Contrasted with learning (Phases 4, 5, 9), which estimates a policy from sampled experience because the model isn't known. See page 1.
Reachability pruning
Marking, in a forward pass before solving, which of the enumerated states can actually occur (e.g. tyre age can never exceed the current lap number) — cutting the states backward induction has to visit by roughly 5–10×. See page 6.
Row-stochastic (matrix)
A matrix whose rows each sum to 1 — the defining property of a valid transition matrix, since the chain has to go somewhere at every step. See page 4.
Stationary distribution
The long-run fraction of time a Markov chain spends in each state, independent of where it started. Mentioned on page 4 for completeness; not used by this project.
Terminal condition
V_(T+1)(s) = 0 for every state — the anchor that makes backward induction a single, non-circular pass rather than requiring iteration to convergence. See page 2.
Transition matrix
The n × n table of probabilities P[i,j] = P(next = j | current = i) that fully describes a Markov chain. See page 4.
Value of perfect foresight
Oracle A − Oracle B: how much a strategist would gain from genuinely knowing the future weather, versus only being able to reason about it probabilistically. An interesting F1 quantity in its own right, not a measure of RL underperformance. See page 6.
Zero-noise expectation shortcut
Calling dynamics.compute_lap_time(..., rng=None) to get the exact expected lap time rather than a sampled one — valid because the environment's noise term is additive and zero-mean, so dropping it doesn't approximate the expectation, it equals it exactly. See page 3.
