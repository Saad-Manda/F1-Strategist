Markov Chains

Oracle B knows the odds of rain. Oracle A knows the rain. The gap between them is the price of not seeing the future.

Your call · rain race #728, lap 6

Dry, 6-lap-old A, B not used yet. Rain comes with a 10% chance each lap. In the wet B is banned, and you cannot box for A while on A: a car on A when the rain comes stays on A until it stops.

Do you box for B now, before any rain?

What does Oracle B know about the weather?

The odds, and only the odds. Its weather model is a Markov chain: the weather on the next lap depends only on the weather now, not on the laps before. A chain is a table of probabilities, one row for each weather now, one column for each weather next. The Pit Wall's:

now \ next lapdrywet
dry0.900.10
wet0.300.70

Each row sums to 1: the matrix is row-stochastic. The real project uses three regimes, DRY, DAMP and WET, so its matrix is 3 × 3.

How do you fit one? Count, then divide

Given logged weather sequences, the matrix that makes them most likely (the maximum-likelihood estimate) is a count. Tally each observed move from i to j, then divide by how often i was the starting point:

P̂[i, j] = n_ij / n_i n_ij = moves from i to j, n_i = Σ_j n_ij

Three short, invented 6-lap logs (D = DRY, P = DAMP, W = WET):

Race 1: D D D P P D Race 2: D D P W W P Race 3: D P P D D D

Count the consecutive pairs inside each race, never across two races, since race 1's last lap says nothing about race 2's first:

From→ D→ P→ Wn_i
D5308
P2215
W0112

Divide each row by its total:

From \ ToDRYDAMPWET
DRY0.6250.3750.000
DAMP0.4000.4000.200
WET0.0000.5000.500

WET never went straight to DRY here, but three races are thin evidence: more data would likely give that move a small chance, not zero. One edge case: a state never seen as a starting point has n_i = 0. The standard fix is a uniform row, not a division by zero.

How does the oracle use the chain?

As page 03 used the safety car. The next lap now has two independent random things, weather and safety car, so there are four next situations, each weighted by the product of its two chances. On a dry, green lap of the Pit Wall: 0.94 × 0.90, 0.94 × 0.10, 0.06 × 0.90 and 0.06 × 0.10.

The chance of rain alone moves Oracle B's stop. With rain possible and none falling, it boxes for B on lap 7, not lap 8: B is banned once it is wet, so getting B fitted early is worth something.

What does Oracle A know?

The whole race's weather, before lap 1. It is solved by the same backward pass on that one fixed weather history, with the safety car still left to chance. Race #728 below is the rain race from the cold open. Play it, then compare the oracle and Oracle A rows at the flag.

Rain falls from lap 7 to lap 19. Oracle A boxes for B on lap 6, the lap before it, and finishes in 297.27 s. Oracle B stays out, is caught on A for thirteen wet laps, and finishes in 344.15 s: 46.88 s behind.

Averaged over 2,000 sampled weather histories, knowing the weather is worth 1.37 s (± 0.09). The capstone report draws 60 histories and gets 0.88 s, which is what a small sample gives. On no history is Oracle A slower than Oracle B's policy on the same weather: knowing more can never cost an exact solver time.

No agent can be Oracle A, because an agent sees only today's weather. So an agent's gap to A mixes information it could never have with its own mistakes. Its gap to B is mistakes only. That is why the real project scores agents against B and reports A separately, as the value of perfect foresight.

Deep diveSeveral laps ahead100 words

If it is wet now, what is the chance it is wet three laps later? Not 0.73 = 34%, which counts only the paths that stay wet every lap. The rain can stop and come back. Multiplying the matrix by itself gives the two-step chances; three times gives three steps, and the answer is 41.2%. As the number of steps grows, most chains settle to a stationary distribution, the long-run share of time in each state, whatever the start. The oracle never needs it: the backward pass uses one row per lap, and the steps take care of themselves.

Deep diveSampling a weather trace from a chain90 words

Start in some state. At each lap, draw the next state from the current state's row, treated as a probability distribution, then move there and use that state's row next time. Two traces started the same way will usually part within a few laps, because each step draws fresh. That is the same "no answer key to memorise" property Phase 1 wanted for the safety car. The real weather_markov.py uses this both for Oracle B's model and for the environment's weather_mode="markov", so the two draw from the same chain.

Deep diveWhen the fitted chain cannot be trusted70 words

weather_markov.py fits one matrix per circuit from every historical weather template Phase 0.5 extracted, and reports the fit's quality alongside it: the count behind each move, and the likelihood on held-out races. If a circuit has too little rain history for its chain to be trusted, the plan says to say so and lean on Oracle A with its information-gap caveat, rather than present a poorly fitted Oracle B as the tight benchmark.

Evidence so farEven the oracle loses to one that knows more: 46.88 s on race #728, 1.37 s on average. That gap is information, not error. Next: you build the solver.
