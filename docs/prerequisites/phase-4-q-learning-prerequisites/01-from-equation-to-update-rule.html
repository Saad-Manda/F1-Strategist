Page 01 / 10 — Foundations

From an Equation to an Update Rule

Phase 3.5 solved the Bellman equation exactly because it was handed the model. Q-learning has to estimate the same equation from one sampled transition at a time — and that shift, from solving to nudging, is the entire idea this page exists to teach.

The equation hasn't changed

Phase 1 page 3 derived the Bellman optimality equation, and Phase 3.5 page 2 solved it directly with backward induction:

Q*(s, a) = Σ_s' P(s'|s,a) · [ R(s,a,s') + γ · max_a' Q*(s', a') ]

Backward induction could solve this because the right-hand side was fully computable — P and R were dynamics.py, not a mystery. Q-learning faces the same equation with one crucial difference: it never has P or R written out anywhere. It only ever gets to observe one sampled transition (s, a, r, s') at a time, produced by an environment it can act in but not inspect. There is no sum over every possible s' weighted by its probability — only the single s' that actually happened.

The temporal-difference idea

Given only one sampled transition, an exact expectation over all possible next states is out of reach. The temporal-difference (TD) idea, introduced generally in Sutton & Barto chapter 6, is to use that one real s' as a stand-in for the expectation, and to nudge the current value estimate toward it a little at a time, rather than trying to solve for the exact value in one shot the way DP did. Chapter 4 — Phase 3.5's chapter — covered the case where nothing needs estimating because the model is fully known; this page is chapter 6's case, where it isn't.

"A little at a time" is the operative phrase. Any single transition is a noisy, one-sample glimpse of what usually happens from (s, a) — the race might have hit an unlucky safety car, or a lucky dry stint. Moving the whole way to match one sample would make the table chase noise. Moving a small step toward it, over and over across many episodes, lets the noise average out while the signal accumulates.

TD error, defined once, used by every algorithm in this set

Every update rule in this doc set — Q-learning on page 2, SARSA on page 4 — is one instance of the same general form:

δ = target − Q(s, a) (TD error: "how wrong was my last guess?") Q(s, a) ← Q(s, a) + α · δ (nudge the estimate toward the target)

δ ("delta") is the TD error: the gap between what the table currently believes Q(s,a) is worth, and a fresher estimate — the target — built from the one real transition that was just observed. The two algorithms in this phase, Q-learning and SARSA, differ in exactly one place: what they use as target. Everything else — the α-scaled nudge toward it — is identical, and pages 2 and 4 will make that difference the entire story.

Bootstrapping: learning from a guess about a guess

Look closely at what target is built from in every TD method: it uses the real observed reward r, plus an estimated value of the next state, Q(s', a') — not the true value, which is never available while learning is still in progress. Updating an estimate using another estimate is called bootstrapping, and it's the feature that separates TD methods from Monte Carlo methods, which wait until an entire episode finishes (so the "target" becomes the actual observed return, with no estimate involved) before updating anything.

Why bootstrapping is worth naming, not just using

Bootstrapping is what lets Q-learning and SARSA update every single step, instead of waiting until a race is over — useful, since a race here runs roughly 52–90 steps and waiting for all of them before learning anything would be slow and wasteful of a lap's worth of signal. The cost is that an update can be built from a value that is itself still wrong; that's fine, because the table converges through repeated correction over many episodes, not through any single update being exactly right.
