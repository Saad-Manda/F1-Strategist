Q-Learning: The Update Rule, Derived and Hand-Run

One equation, traced back to page 1's general TD-error form, then run by hand for four steps on a toy table small enough to track cell by cell.

The full update

Q-learning's update fills in page 1's target with a specific choice:

Q(s, a) ← Q(s, a) + α [ r + γ · max_a' Q(s', a') − Q(s, a) ] \_______________/ \__________/ target δ

Matched against page 1's general form: target = r + γ · max_a' Q(s', a'), and δ = target − Q(s, a), exactly as before. Everything here is one concrete instance of the shape already introduced — nothing new in the mechanics, only in what target is built from.

Why max_a': this is what "off-policy" means

The target assumes the agent will play optimally from s' onward — it takes the best Q-value available at s', regardless of which action the agent actually ends up taking next while it's still exploring. That's a deliberate mismatch: the policy generating the data (ε-greedy, page 3) is not the same policy the update assumes will be followed afterward (purely greedy). This mismatch — updating toward a different policy than the one producing the experience — is precisely what off-policy means. The agent can take a random exploratory action next and the update still credits (s,a) as if the best follow-up action were coming, because max_a' doesn't care what was actually sampled.

Learning rate and discount, in their learning-specific role

α (learning rate) and γ (discount) were both named in Phase 1 and used by Phase 3.5, but they do a different job here. α controls how far a single sampled transition is allowed to move an estimate: too high and the table chases noise from one race to the next without settling; too low and learning proceeds at a crawl, needing many more visits to the same cell before it reflects reality. γ stays at 1.0, unchanged from every earlier phase, for the same fixed-horizon reason Phase 1 page 3 gave: a race is a finite number of laps, and there's no reason to discount a lap 40 reward less than a lap 5 one just because it's further away in time.

Worked example: a 3-state toy, hand-run for four steps

A tiny MDP, small enough to track every table cell by hand. Two non-terminal states, s1 and s2; a terminal state s3; two actions, a0 and a1, in every state:

s1, a0 → r = −1, next = s2 s1, a1 → r = −3, next = s3 (terminal) s2, a0 → r = −1, next = s3 (terminal) s2, a1 → r = −2, next = s3 (terminal)

Backward induction (page 2 of the Phase 3.5 set) would solve this exactly in one pass: Q*(s2,a0) = −1, Q*(s2,a1) = −2, so the best move from s2 is a0; then Q*(s1,a0) = −1 + (−1) = −2, Q*(s1,a1) = −3, so the optimal policy is a0 at s1, then a0 at s2. Q-learning is given none of this — only four sampled transitions, in this order, with α = 0.5, γ = 1, and every table cell starting at 0:

#Sampled transitionTargetδUpdated cellNew value
1(s1, a0, r=−1, s2)−1 + max(0, 0) = −1−1Q(s1,a0)0 + 0.5(−1) = −0.5
2(s2, a0, r=−1, s3, terminal)−1 (terminal)−1Q(s2,a0)0 + 0.5(−1) = −0.5
3(s1, a1, r=−3, s3, terminal)−3 (terminal)−3Q(s1,a1)0 + 0.5(−3) = −1.5
4(s1, a0, r=−1, s2)−1 + max(−0.5, 0) = −1−1 − (−0.5) = −0.5Q(s1,a0)−0.5 + 0.5(−0.5) = −0.75

Two things worth reading carefully out of this trace. First, every cell is moving in the right direction — toward the true values Q*(s1,a0)=−2, Q*(s1,a1)=−3, Q*(s2,a0)=−1 — without landing on them exactly after only one or two visits; convergence is a many-episode process, and four steps only establishes the trend. Second, step 4's target used max(Q(s2,a0), Q(s2,a1)) = max(−0.5, 0) = 0 — picking the still-untouched Q(s2,a1) over the already-updated Q(s2,a0), purely because nothing has pulled it down from its optimistic zero initialization yet. That's not a bug; it's the mechanism page 8 leans on when discussing why a table's initial values matter, and a preview of why an all-zero start is mildly optimistic until enough transitions have been seen to correct it.

Convergence, stated but not proven

Q-learning is provably guaranteed to converge to Q* given two conditions: every state-action pair is visited infinitely often, and the learning rate α decays appropriately over time (a fixed α, as used throughout this project's plan, converges to a small neighborhood of Q* rather than exactly to it — acceptable in practice, and the reason "train for a lot of episodes" is the theoretical justification behind the real plan's 10,000-episode training runs, not a proof this page needs to reproduce). What matters practically is the shape of the guarantee: nothing here promises fast convergence, only that enough visits eventually get there.
