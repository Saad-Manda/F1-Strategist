Average the gradient and its squared magnitude

Adam tracks m, a moving average of gradients, and v, a moving average of squared gradients. For scalar gradient g at optimizer step t, m_t=β₁m_(t−1)+(1−β₁)g and v_t=β₂v_(t−1)+(1−β₂)g². These betas belong to Adam, not PER's correction exponent or the environment's discount.

Starting both averages at zero makes early values smaller than their long-run scale. Bias correction uses m̂=m_t/(1−β₁^t) and v̂=v_t/(1−β₂^t). The basic no-weight-decay update subtracts lr×m̂/(sqrt(v̂)+ε). Epsilon is a positive numerical safeguard in the denominator.

import math

def adam_scalar(theta, gradient, m, v, step, lr=0.001,
                beta1=0.9, beta2=0.999, epsilon=1e-8):
    if (type(step) is not int or step < 1 or not 0 <= beta1 < 1
        or not 0 <= beta2 < 1 or lr <= 0 or epsilon <= 0 or v < 0
        or not all(math.isfinite(x) for x in
                   (theta,gradient,m,v,lr,beta1,beta2,epsilon))):
        raise ValueError("invalid Adam scalar state")
    m = beta1*m + (1-beta1)*gradient
    v = beta2*v + (1-beta2)*gradient**2
    corrected_m = m/(1-beta1**step)
    corrected_v = v/(1-beta2**step)
    theta -= lr*corrected_m/(math.sqrt(corrected_v)+epsilon)
    return theta,m,v

theta,m,v = adam_scalar(2.,2.,0.,0.,1)
assert abs(m-0.2) < 1e-12 and abs(v-0.004) < 1e-12
assert abs(theta-1.999000000005) < 1e-12

At the first step g=2, m=0.2, v=0.004; correction gives m̂=2, v̂=4. The change is approximately 0.001, whereas SGD with the same lr changes by 0.002. That example is not proof of better learning. This scalar helper omits weight decay and other implementation options; saved optimizer state contains these histories and the step counter.

Recap and self-check

Why does restarting Adam with the saved weights but empty optimizer state change a resumed run?

The next update depends on gradient history and step-dependent correction as well as weights. Restore them for a faithful resume, or label the operation as a new optimizer run.
