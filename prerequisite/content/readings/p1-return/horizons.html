Why this matters

A task can end naturally, run to a fixed deadline, or continue indefinitely. The objective and the stopping rules must agree. A collector pausing does not necessarily mean there are no future task rewards.

A finite task can use gamma one

A guaranteed three-transition episode with rewards [2, −1, 4] has undiscounted return 5. No convergence argument is needed: there are only three numbers to add. More generally, a guaranteed finite horizon with bounded rewards makes every trajectory's finite sum well defined.

An intrinsic deadline can change the preferred action. Suppose DIRECT finishes now for reward 3; VIA gives 1 now, with a finish reward 4 on the next transition. With two decisions remaining and gamma 1, VIA gives 5 and DIRECT gives 3. With only one decision remaining, VIA gives just 1 before the deadline terminates the task, so DIRECT is better.

Represent the number of remaining decisions in state when the deadline is part of the task. The value will depend on that countdown. An absorbing terminal state is a mathematical convention for a state that stays terminal and gives no more rewards; your actual collector should stop, not repeatedly call step to generate zero rows.

A continuing task needs another argument

Suppose a maintenance task pays +1 forever. With gamma 1, its return grows without bound. With gamma 0.5, the weights sum to 1 + 0.5 + 0.25 + … = 2. With gamma 0.9, the sum is 10. This follows from the geometric-series identity Σ_(k=0)^∞ γ^k = 1 / (1−γ), valid when gamma is below 1 and at least 0.

If every reward's absolute magnitude is at most a finite constant C, the absolute discounted return is at most C / (1−γ). This bounded-reward assumption is essential. Discounting does not rescue an arbitrary sequence of rewards that grows faster than its weights shrink.

Another objective for continuing tasks is long-run average reward per step. That is a different objective with different assumptions and equations; we will use finite episodic or discounted objectives here. An unbounded episode length with gamma 1 also needs care: each observed episode ending is not by itself a proof that its expected return is finite.

Task horizon, time limit, and batch cutoff

Return from a truly terminated episode has zero continuation because no task rewards remain. A TimeLimit can truncate a live task. Summing only its observed rewards gives a partial trajectory return; it does not justify declaring the unobserved continuation worthless.

A rollout batch can also fill while both ending flags are false. Keep the cutoff separate from termination. Later value targets may attach an estimated continuation to truncated or cut-off trajectories. This module will name that continuation explicitly rather than silently setting it to zero.

Common mistake: treating any finite log as proof that the underlying task has a finite horizon. A ten-row log might be one completed task, a time-limited fragment, or a batch from a continuing task.

Is gamma one valid for a race guaranteed to last exactly 52 laps?

Yes, for finite bounded per-lap rewards. It scores every lap equally. An early-terminal invalid-action penalty creates another type of outcome and must be handled explicitly when discussing fixed-horizon claims.
