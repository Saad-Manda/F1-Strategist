Phase 8 Self-Play Prerequisites

Everything — and only what — you need to build the multi-agent self-play training loop described in phase-8-self-play.md, assuming you already have the Phase 1, Phase 3.5, Phase 4, Phase 5, and Phase 6 prerequisite sets and nothing more.

Read this before training anything

Phase 8's headline Definition of Done — a bimodal undercut/overcut pit-timing histogram emerging from training, without being explicitly programmed — cannot be reached yet. It depends on a design gap in Phase 6, not on anything in this phase's own files: Phase 6's plan-as-written computes race position purely by sorting cumulative time, with nothing that ever holds a trailing car up behind one it's following. Page 06 of this set works through why that makes the undercut structurally impossible to learn, no matter how self-play is tuned. The real plan's own Risks table misdiagnoses the eventual symptom as a possible out-lap-warmup bug — it isn't. Check page 06 before spending any training budget here.

Why this phase is different from everything before it

Every phase through Phase 6 had at most one learning agent in the world. Phase 6's rivals move and pit and race, but they follow a script decided in advance — from the agent's point of view they're no different from the weather trace or the safety-car process: part of a fixed, stationary environment. Phase 8 removes that shield on purpose. The agent's training opponents are now other copies of the same kind of learner, produced by earlier rounds of the very training process being run — which means the "environment," as far as any one agent's learning algorithm is concerned, is now something that changes while it's being learned about. That single shift touches almost everything Phase 4 and 5's theory quietly assumed.

Scope, precisely

This set teaches exactly what phase-8-self-play.md needs: why a learning opponent reintroduces non-stationarity in a way Phase 6's scripted rivals sidestepped, the game-theoretic target self-play is approximately chasing and why a checkpoint pool is a practical stand-in for it, PettingZoo's AEC and Parallel multi-agent environment APIs, the three MARL training paradigms and why independent learners is the deliberate simple choice here, and two audit findings taught as core content rather than footnotes — a degenerate first-opponent bug, and the Phase 6 blocking-model dependency above. It does not cover PPO, Stable-Baselines3, or anything else from Phase 9.

Read this before anything else

Like Phase 6's set was for its own phase, this one is unusual: the code it eventually points to — f1_pettingzoo_env.py, self_play_trainer.py — does not exist in src/ yet, because Phase 8 hasn't been implemented. Pages 9 and 10 read the plan's own pseudocode, not a real, running file, and part of what they teach is the project's own audit findings against that pseudocode — including the dependency above, which was found by reading the plan critically before a single episode of training ran.

How to use this alongside the Phase 8 plan

Read pages 1–7 once, in order — they build one continuous argument, from what changes when the opponent itself is learning, through the game-theoretic idea self-play is chasing and the practical mechanism (a checkpoint pool) that approximates it, the multi-agent environment API that mechanism runs inside, a bug that would quietly poison early training, the single design gap one phase earlier that determines whether this phase's headline result is even reachable, and a statistical check for that result once it might actually appear. Page 8 is hands-on: build a tiny version of the self-play loop yourself, on a toy game small enough to reason about by hand. Page 9 then re-derives the same concepts using nothing but this project's actual classes and parameters. Page 10 is a critical reading guide to the plan's own pseudocode. Keep page 11 open as a reference while you work.
