Overtaking and Dirty Air: Modeling What Cumulative Time Alone Can't

Two small, hand-checkable formulas stand in for a real aerodynamic effect and a real racing decision.

Dirty air, the real effect

A trailing F1 car loses downforce running in a leading car's aerodynamic wake — a real, well-documented effect, worse the closer the following distance. The real plan models it as a straight line: a penalty of DIRTY_AIR_MAX_PENALTY = 0.5 seconds at zero gap, falling linearly to 0.0 seconds at DIRTY_AIR_MAX_GAP = 1.5 seconds and beyond:

penalty(gap) = 0 if gap ≥ 1.5 penalty(gap) = 0.5 · (1.5 − gap) / 1.5 if gap < 1.5 Check the three points the real plan's own unit tests assert: gap = 0.00 → 0.5 · 1.50 / 1.5 = 0.500 ✓ (max penalty, bumper-to-bumper) gap = 0.75 → 0.5 · 0.75 / 1.5 = 0.250 ✓ (halfway gap, half penalty) gap = 1.50 → 0.5 · 0.00 / 1.5 = 0.000 ✓ (at the threshold, no penalty)

Nothing subtle here — it's a straight line between two calibration points, and the three test values above are exactly the ones a reader can verify by hand before ever running the code.

Probabilistic overtaking

An overtake can only be attempted within OVERTAKE_ATTEMPT_GAP = 1.0 second, and only when the attacking car is faster this lap (pace_delta < 0, where pace_delta = my_lap_time − their_lap_time). Given an attempt happens, success probability is a sigmoid in the pace advantage:

base_prob(pace_delta) = 1 / (1 + exp(5 · (pace_delta + 0.5)))

Worked by hand at the one point the real plan's own docstring names explicitly — 0.5 seconds faster:

pace_delta = −0.5 (0.5s faster) exponent = 5 · (−0.5 + 0.5) = 5 · 0 = 0 base_prob = 1 / (1 + e^0) = 1 / 2 = 0.50 → 50%, exactly as claimed
Worth checking the other two claimed points too

The real plan's docstring also claims "80% at 1.0s faster, 95% at 1.5s faster." Running the same formula at those two points tells a different story:

pace_delta = −1.0 (1.0s faster) exponent = 5 · (−1.0 + 0.5) = 5 · (−0.5) = −2.5 base_prob = 1 / (1 + e^−2.5) = 1 / (1 + 0.082) ≈ 0.924 → 92.4%, not 80% pace_delta = −1.5 (1.5s faster) exponent = 5 · (−1.5 + 0.5) = 5 · (−1.0) = −5.0 base_prob = 1 / (1 + e^−5.0) = 1 / (1 + 0.0067) ≈ 0.993 → 99.3%, not 95%

The formula and the two later numbers in its own comment don't agree — a small, low-stakes example of exactly the habit page 10 asks for on a larger scale: hand-check a formula against what its own documentation claims, rather than trusting the comment. It changes nothing about whether the model is reasonable (a steeper-than-advertised sigmoid is still a sigmoid), only what the reader should expect to see if they log actual pass rates during training.

On top of base_prob, a small bonus rewards persistence: follow_bonus = min(0.1 × laps_following, 0.2) — up to 0.2 extra probability after two or more consecutive laps within range, capped, and the total capped again at 0.95 so an overtake is never a certainty no matter how large the pace advantage.

A modeling choice, not a law of physics

This sigmoid, with these particular constants, is one reasonable functional form among many — a step function or a differently-shaped curve could stand in just as well. What matters for the rest of this project is understanding what the model is trying to capture (a bigger pace advantage should mean a meaningfully higher pass probability; extended following should help a little), well enough to defend or adjust the constants later, not memorizing this exact formula as the only correct one.
