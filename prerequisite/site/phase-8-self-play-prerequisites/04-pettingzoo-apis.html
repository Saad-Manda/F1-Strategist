Page 04 / 11 — Implementation background

Two Ways to Formalize "Everyone Acts": AEC and Parallel

PettingZoo offers two genuinely different multi-agent APIs. F1 strategy only needs one of them — but understanding both makes clear why.

AEC — Agent Environment Cycle

AEC selects one agent at a time. The environment decides when committed actions affect dynamics and what each agent may observe; later selection does not imply visibility of another agent’s pending action. This is the natural formalization for turn-based games — card games, board games — where seeing what the previous player just did is exactly the information the next player is supposed to have.

A tiny worked example: a sequential (turn-based) variant of rock-paper-scissors, where player A moves first and player B can see A's move before choosing:

env.reset() env.agent_selection → "player_A" action_A = "rock" env.step(action_A) # player A's move is now recorded env.agent_selection → "player_B" obs_B = env.last() # obs_B sees that A played "rock" action_B = "paper" # B, seeing A's move, always wins by playing paper env.step(action_B) # In sequential play, going second with full information of the other's move # is a structural advantage — a fact that wouldn't even make sense to ask # about in the simultaneous version below.

The agent_selection attribute names whose turn it is; .last() returns that agent's own most recent observation/reward/done state. Selection order defines the API, not an information advantage. This particular sequential example reveals A’s action; a simultaneous AEC game can hide it until both commitments are collected.

Parallel

All agents submit actions simultaneously each timestep; the environment resolves every action together and returns a single batch of observations, rewards, terminations, and truncations, each as a dict keyed by agent id. Neither agent sees the other's action before committing to their own.

observations, infos = env.reset() actions = {"player_A": "rock", "player_B": "paper"} # chosen independently, same instant observations, rewards, terminations, truncations, infos = env.step(actions) # Both actions are submitted together — player_B's "paper" was not chosen # in response to seeing player_A's "rock"; it's the real, simultaneous # rock-paper-scissors, not the sequential-advantage version above.

The direct contrast with the AEC example above: nobody has an information advantage from acting second, because nobody acts second — every agent commits blind to what everyone else is doing this timestep.

Why Parallel is convenient for joint decisions

Every car on track makes its per-lap pit/stay decision independently, at the same point in the lap, without having observed what any other car decided this lap. Nothing about one car's decision this lap causally depends on having already seen another car's decision this lap — any interaction between cars (gaps closing, dirty air, an overtake attempt) is a consequence, computed after all of this lap's actions have been submitted and resolved together, via Phase 6's dynamics (assumed background). Parallel directly expresses that joint decision. AEC can also encode it by keeping pending choices hidden and resolving only after the complete action cycle; using AEC does not itself change the game’s information structure.

The shared API surface both build on

possible_agents lists every agent id that can ever appear (["agent_0", "agent_1", ...]); observation_spaces and action_spaces are dicts keyed by agent id rather than single spaces, since different agents can in principle have different spaces (though here they're identical for every car); reset() and step() in the Parallel API return dicts keyed by agent id for every one of observations, rewards, terminations, truncations, and infos. This is set up generically here so page 09 can show the real plan's F1PettingZooEnv as a direct, unsurprising instantiation of exactly this surface.

Selected-agent cleanup

In AEC, last() reports the selected agent’s own termination/truncation flags. Pass None for that dead agent, even if another agent remains live. Do not decide with all(env.terminations.values()). Parallel supplies an action for every current live agent; a finished one-round game leaves agents=[].
