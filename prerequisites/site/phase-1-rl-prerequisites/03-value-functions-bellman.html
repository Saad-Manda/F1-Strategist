Phase 1 · Page 03 · The value

Value Functions and the Bellman Equations

How good is this situation? Nearly every RL algorithm is trying to answer that, one way or another.

Your call · lights out

Lap 1 of 20. Fresh A tyres, dry, no safety car.

Reward is minus the lap time, every lap counts the same, and you play the best strategy from here. What is this moment worth, in reward?

A state is worth the reward still to come

The value of a state, V^π(s), is the return you expect if you start in s and follow the policy π from there:

V^π(s) = E_π[ G_t | S_t = s ]

In words: if I am here and play my strategy, how much reward do I expect between now and the flag? With reward equal to minus the lap time and γ = 1, that is minus the expected time still to race. A better policy has a higher, less negative value in every state, because it gets to the flag sooner.

Value tells you how good a situation is, not what to do. For that you need one step more. Q^π(s, a) is the expected return if you take action a now and follow π afterwards:

Q^π(s, a) = E_π[ G_t | S_t = s, A_t = a ]

Compare Q across the legal actions and pick the highest: that is the call. On lap 6, under the safety car, on six-lap-old A, Q is −180.92 for staying out and −180.52 for boxing. Boxing is higher, so you box. That is why Phases 4 and 5 learn Q, not V: a table of Q-values is a policy, within the action mask. Learning good Q-values is learning race strategy.

The start of a 20-lap race on the Pit Wall is worth −231.92 under the best policy: minus its expected race time, safety cars included. Nothing has been earned yet, but the value is about what is coming, and the whole race is coming. The real race's start is worth about −5,000 by the same reasoning.

The value of now is one lap plus the value of next

The Bellman equation says a state's value is the reward for this step plus the value of wherever you land, averaged over where you might land. It is not a new assumption: it falls out of the return by splitting off the first term (deep dive below). For the best policy it reads:

Q*(s, a) = Σ_s′ P(s′|s,a) · [ R(s,a,s′) + γ · max_a′ Q*(s′, a′) ]

Here it is with real Pit Wall numbers, written in seconds (minus the reward). Lap 14, eight-lap-old A, dry, box for B. This lap costs 11.18 s on the old tyre plus the 4 s stop: 15.18 s. Next lap you are on fresh B. With probability 0.94 there is no safety car, and the rest of the race from there costs 67.92 s. With probability 0.06 there is one, and it costs 74.25 s.

15.18 + 0.94 × 67.92 + 0.06 × 74.25 = 83.48 s

That 83.48 s is the number the reveal on page 02 gave for boxing on lap 14. Work backwards from the flag like this, one lap at a time, and you get the value of every state. That is Phase 3.5's oracle, and it is how the Pit Wall's oracle is computed.

Deep diveThe Bellman equation derived from the return230 words

Start from the return and split off the first reward:

G_t = R_(t+1) + γ·R_(t+2) + γ²·R_(t+3) + ... = R_(t+1) + γ·( R_(t+2) + γ·R_(t+3) + ... ) = R_(t+1) + γ·G_(t+1)

The bracket is G_(t+1), the return from one step later. So the return at any point is this step's reward plus γ times the return from the next state. Take the expectation of both sides, given state s and action a, which is Q(s, a) by definition:

Q^π(s,a) = E[ R_(t+1) + γ·G_(t+1) | S_t=s, A_t=a ] = E[ R_(t+1) | s,a ] + γ·E[ G_(t+1) | s,a ]

The first term is the expected reward for this step. The second is the expected value of V^π(s′) over the next states P(s′|s,a). Write that out and switch to the best policy, which takes max_a′ instead of averaging over π, and you have the Bellman optimality equation above. Everything downstream runs on it:

  • Q-learning (Phase 4) makes a table satisfy it approximately, by nudging Q(s,a) towards R + γ·max Q(s′,a′) from transitions it has seen.
  • Dynamic programming (Phase 3.5) solves it outright, backwards from the last lap, because a fixed-length race with a known model allows it. No learning, no sampling.

That is why the plan insists that compute_lap_time(rng=None) returns the expected lap time itself, not an estimate: the oracle plugs the noise-free model straight into this equation.

Deep diveDoes γ = 1 break the recursion?50 words

The γ·V(s′) term lets an agent reason about consequences several laps ahead without simulating them. γ = 1 removes the discount, so a future lap counts as much as this one. Nothing breaks: the race always ends, so the recursion stops at the last lap instead of running for ever.

The head start, and how to remove it

Now the case. With γ = 1 and 52 laps at about −95 each, the values of the real race sit around −5,000. A Q-table that starts at zero, or a new neural network whose outputs start near zero, is 5,000 away from the truth before it has learned anything. Closing that gap is slow, and it is a common reason a training run "runs but learns nothing".

The plan's fix is reward centring: subtract a fixed constant c from every lap's reward (reward_offset="base_pace", c = 92). Does that change which strategy is best? Take two policies over the same 52-lap race, one averaging −93 a lap and one −97:

raw: 52 × (−93) = −4,836 52 × (−97) = −5,044 difference 208 centred: 52 × (−1) = −52 52 × (−5) = −260 difference 208

The values shrink by two orders of magnitude, which makes them learnable. The difference between the policies, 208, does not move. Subtracting c from all T laps shifts every policy's return by the same c × T, so it cancels out of every comparison. The ranking, and therefore the best policy, is unchanged. On the Pit Wall, c = 10: the start's value goes from −231.92 to −31.92, and every call the oracle makes stays the same.

Deep diveWhy this is not reward shaping50 words

Reward shaping adds a term that depends on the state, and needs a potential function to stay safe. Centring adds a constant that depends on nothing, so the plan needs no potential function. It also keeps the truth visible: info["lap_time"] always reports the true, uncentred lap time, whatever the offset.

Evidence so farThe start's value is minus the expected race time: −231.92 on the Pit Wall, about −5,000 in the real race. Centring by a constant moves it near zero and changes no call. The maths of the case is closed; what is left is where the plan's code does it.
