Why centre the reward?

With γ = 1 and about −95 per lap over 52 laps, true values are near −95 × 52 = −4,940, and every cell starts at 0. At α = 0.1 a cell closes 10% of its gap per visit, so even with a perfect target it needs 22 visits to close 90%, and its target is a neighbour that is still travelling too. This is the likeliest cause of "trains without error, learns nothing". Phase 1's reward_offset="base_pace" learns on −(lap_time − base_pace): about −5 a lap, values near −260. It changes no decision, for the reason Phase 1 proved: over a fixed horizon every strategy's total moves by the same constant. The capstone measured it: 0 to 7 s off centred, 4 to 17 s raw.

Deep diveWhy "+10 optimistic init" isn't the fix70 words

The Risks table suggests a +10 starting bonus for pit calls, to make the agent try them early. Against values near −5,000, +10 is about 0.2% of the distance a cell must travel: a rounding error. It is a reasonable nudge only after centring has brought values to a scale where 10 matters. On the toy race, page 03 showed a plain 0 start already acting as optimism once rewards are centred.

Deep diveThe training loop: curriculum, decay, evaluation100 words

train_tabular.py runs 10,000 races with a curriculum for the first 3,000: dry weather only and no safety car. That is two switches, since safety cars are drawn at random rather than replayed. Holding weather and safety car fixed early puts the first races' visits into fewer cells. ε falls to its floor at race 9,615, not "~5K" as the config comment says (page 03). Every eval_interval races the loop evaluates and prints the result beside the mean of the last 100, so a reviewer can tell steady improvement from one lucky checkpoint near the end.

Two bugs recorded against the plan

  • The evaluated agent still explores. select_action always consults self.epsilon, and nothing in evaluate.py turns it off: 0.05 × 52 ≈ 2.6 random calls in every reported race, some of them 18 s stops. On the toy race it cost 1.89 s (page 07). Fix: an eval_mode flag, set by evaluate_agent, and a test that two evaluations on one seed give the same race.
  • SARSA's pre-commit leaks. SARSAAgent._next_action has no reset(), so after a race cut short, its last pre-committed call becomes the first move of the next race (page 07's 259 of 500). Fix: a reset() that clears it, called at the start of every race, in training and in evaluation.

How is a learner scored?

As in Phase 3.5: optimality_gap = mean_race_time(agent) − mean_race_time(Oracle B), in seconds, measured with weather_mode="markov", with a paired bootstrap confidence interval. Beating ThresholdAgent on ≥60 of 100 seeds is necessary, not sufficient: the headline is how much of the baseline's gap to the optimum the agent closed.

Deep diveThe files, in reading order200 words

Read discretize_obs first: everything else depends on its key. Then QLearningAgent: select_action, update, save/load, in that order. Then SARSAAgent last, a subclass that overrides two methods.

  • select_action: page 03's shape. A random draw from np.where(masks)[0], or an argmax over self.Q[state] with illegal calls set to −inf first. The key is always discretize_obs's output, never the raw observation.
  • update: page 02's rule. target = reward if terminated, else reward + gamma * np.max(next_q) with the next state's illegal calls masked to −inf before the max. An unmasked max would pick an untrained illegal cell, still at 0 and above every real value.
  • save/load: the table is a defaultdict, but one with a lambda default doesn't pickle cleanly. Check that load wraps the loaded dict in a new defaultdict explicitly.
  • SARSAAgent.select_action: page 07's pending under its real name, _next_action. It returns and clears a pre-committed call if there is one, else draws fresh; update sets it by calling select_action on next_obs one call early.
  • train_tabular.py: the curriculum branch, set for episode < curriculum_episodes and passed to env.reset(seed=episode, options=options), then the periodic evaluation block.

What the tests catch

  • test_q_learning_update_changes_q_values: an update that writes nothing, or to the wrong cell. It checks that the update does something, not that it is right.
  • test_epsilon_decays: less than its name says. It repeats the decay arithmetic inside the test and never calls update(), so it passes with the decay deleted from the agent. To defend the schedule it must call update() many times and read agent.epsilon.
  • test_trained_q_agent_beats_random: after 1,000 races the agent beats one that acts at random. A smoke test that the pipeline is wired together. Failing it means a wiring bug; passing it says nothing about the baseline or the gap.

None of the three would notice coarse bins, evaluation with ε on, or the SARSA leak.

Case 3 · the verdict

The table can't hold the window, and three of the plan's lines must change

Why can't more training fix the coarse learner? Its key throws away the difference the decision depends on. With 5-lap cells for laps to go and for tyre age, laps 6 to 9 on the first set are one cell, so the oracle's lap-8 stop cannot be written down: the best found is a lap-6 stop, 1.10 s off. And learning from blended neighbours does far worse: about 12.5 s off, no better after 80,000 races than after 5,000. Training makes the blend more accurate; it never splits it.

What should the plan change? The prerequisites do not edit the plan; these go to whoever implements Phase 4.

1. Ship the fix, not only the warning. Step 1's warning says to use 1–2 lap tire_age bins, but the BINNING dict, the Definition of Done's "12×5×10×3×3×2×8×2 = 172,800 possible states (verified)", and visualize_q_table's min(age // 5, 9) all still use the 5-lap scheme. Recompute the size from the new bins, and have the plot take its bins from discretize_obs.

2. Test the whole key. The distinct-bins test the warning asks for is in neither Step 7's tests nor the Definition of Done. It must cover laps_remaining too, 12 bins of about 4.3 laps. In the toy race, 2-lap tyre-age bins with 5-lap laps-to-go bins still left a median gap of 5.76 s; 2-lap bins for both, 1.94 s; 1-lap bins for both, 1.05 s.

3. Pass the curriculum key Phase 1 reads. Step 3's loop sets options["curriculum_dry_only"] = True. Phase 1's reset reads options.get("curriculum"), expects "dry_no_sc", and ignores other keys. As written, the first 3,000 races run with no curriculum, and nothing fails. The Risks table names the right hook; the loop's code doesn't use it.

Also for the implementer: the eval_mode flag and SARSA's reset() are in the Risks table but in no test or Definition-of-Done line; test_epsilon_decays never calls update(); and the "~5K eps" comment is 9,615 races.

Worked solution

1. laps_remaining: int(7.85) = 7. tire_age: int(0.36 × 25) = 9, or int(3.6) = 3 under 10 bins. compounds_used: 4 + 2 + 0 = 6. tire_compound: 1. The full key is (7, 1, 9, 0, 1, 0, 6, 0).

2. 0.95⁵² = 6.9%. 0.02 × 52 = 1.04.

3. −95 × 52 = −4,940. −5 × 52 = −260. 0.9²¹ = 0.109 and 0.9²² = 0.098, so 22 visits.

4. The no-op update: test_q_learning_update_changes_q_values. The wrong-sign reward: test_trained_q_agent_beats_random. The other four are caught by none of the three: the coarse bins, the deleted decay (the planned test repeats the arithmetic itself and never calls update()), evaluation with exploration on, and the SARSA leak. Four tests would close those gaps: distinct keys for the optimal pit lap and its neighbours; epsilon lower after real calls to update(); two evaluation runs on one seed giving identical races; and a pre-committed action not surviving a reset().

5. Untrained cells hold 0 and would win every max. The beats-random test is a smoke test of the wiring.

6. Test the whole key; rule out the binning before training longer; pass options={"curriculum": "dry_no_sc"}, the key Phase 1 reads.
