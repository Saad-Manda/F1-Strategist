Why this matters

You can describe an environment through Python calls, but a mathematical model helps state what those calls mean. A Markov decision process, or MDP, collects the ingredients of a sequential decision problem whose state is sufficient. It is a model of the task; learning is one possible way to find a policy for it.

Build the ingredients from the delivery chain

Start with the chain's possible states: locations 0, 1 and terminal location 2. Call that set S. A set is a collection of possible values, not the current value. Call the action set A: LEFT and RIGHT. At the terminal state we stop choosing actions.

The transition model describes possible next states and their probabilities given state and action. Write it as P(s' | s, a). Lowercase s and a mean particular members of S and A; the prime in s' means “next,” not a derivative. Here RIGHT from 0 reaches 1 with probability 1. Its probabilities for other destinations are 0.

The reward rule R assigns the transition's score. In this deterministic chain, R(1, RIGHT, 2) = 5. Some tasks have random rewards even for the same state transition. A more general model uses a joint distribution p(s', r | s, a) over next state and reward, rather than assuming a fixed reward for each pair.

Add a starting rule and an objective

Reset supplies a starting distribution: the chain always begins at 0. Other tasks sample starting states. A horizon specifies how long the task lasts, or which states end it. The chain ends at 2; an external TimeLimit interrupts collection without changing this terminal set.

An agent must also have an objective for comparing sequences of rewards. The next lesson introduces return and the discount factor γ (gamma). For now, think of gamma as a setting describing how later rewards enter the objective. It is not a probability in the transition table.

You will often see an MDP summarized as (S, A, P, R, γ), with the starting distribution and horizon stated separately. Different books use slightly different tuples. Always check what each component means. A tuple is a compact description, not evidence that the state or reward design is correct.

A model is different from a sampled transition

env.step(action) returns one actual transition. A known model gives the possible outcomes for every state/action pair, including hypothetical situations the live environment has never visited. Later, planning algorithms use those tables; learning algorithms can estimate good decisions from experience when the tables are unavailable.

Knowing the simulator's code does not automatically give the policy permission to read its hidden state or future random draws. The model's information rules remain part of the problem.

Common mistake: mixing the transition probability P with a policy's probability of choosing an action. The environment determines outcomes after a choice; the policy determines choices before those outcomes.

Does LEFT at location 0 have to be an illegal action?

No. Our chain deliberately allows it and returns a no-movement transition costing −1. A different task may forbid an action, but that requires a stated legal-action rule.
