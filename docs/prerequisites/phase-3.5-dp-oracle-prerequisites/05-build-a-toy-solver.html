Page 05 / 08 — Building it yourself

Build a Toy DP Solver, Step by Step

Five stages, each adding one complication a plain backward-induction pass ignores — deterministic, then risky, then constrained, then doubly-random, then sanity-checked. Type each one in yourself; none of the names below match the real oracle on purpose.

Every function and variable name here (toy_backward_induction, sc_transition_prob, and so on) is invented for this page and deliberately does not match anything in dp_oracle.py or weather_markov.py. The goal, same as Phase 1 page 5, is to arrive at the same shape of solution independently, so the real files read as familiar structure rather than new material when page 7 opens them.

Stage 1 — deterministic backward induction, verified against brute force

Start with exactly page 2's toy race: one tyre, STAY/PIT, no randomness. A dict keyed by (lap, age) stands in for the value table — small enough here that a NumPy array would be overkill:

HORIZON = 4
PIT_LOSS = 6.0

def lap_time(age: int) -> float:
    return 10.0 + 3.0 * (age - 1)

def toy_backward_induction(horizon: int):
    V = {(horizon + 1, age): 0.0 for age in range(1, horizon + 2)}
    policy = {}
    for t in range(horizon, 0, -1):
        for age in range(1, t + 1):
            stay_cost = lap_time(age) + V[(t + 1, age + 1)]
            pit_cost  = lap_time(age) + PIT_LOSS + V[(t + 1, 1)]
            if stay_cost <= pit_cost:
                V[(t, age)], policy[(t, age)] = stay_cost, "STAY"
            else:
                V[(t, age)], policy[(t, age)] = pit_cost, "PIT"
    return V, policy

Before trusting it, verify it the way test_oracle_value_matches_rollout will later verify the real oracle: independently, by brute force, enumerate every one of the 2^HORIZON possible action sequences and find the cheapest by direct simulation:

from itertools import product

def brute_force_best(horizon: int) -> float:
    best = None
    for actions in product(("STAY", "PIT"), repeat=horizon):
        age, total = 1, 0.0
        for a in actions:
            total += lap_time(age) + (PIT_LOSS if a == "PIT" else 0.0)
            age = 1 if a == "PIT" else age + 1
        best = total if best is None else min(best, total)
    return best

V, policy = toy_backward_induction(HORIZON)
assert abs(V[(1, 1)] - brute_force_best(HORIZON)) < 1e-9
print(V[(1, 1)])   # should print 52.0 -- page 2's hand-computed answer, exactly

Getting 52.0 printed, matching page 2's hand-worked table cell for cell, is the whole point of this stage: it's proof the code implements the same recursion you already verified by hand, not merely a plausible-looking piece of code that happens to run.

Stage 2 — a risk the agent can't control: the safety-car hazard

Add the exact expectation machinery page 3 introduced, over a state that now includes sc_active. Only what's new is shown — the shell around it is the same backward pass:

HAZARD = 0.2          # P(SC starts next lap | currently green)
CONTINUE_PROB = 0.5   # P(SC continues next lap | currently under SC)
SC_LAP_TIME = 20.0
SC_PIT_DISCOUNT = 0.4

def sc_transition_prob(sc_now: int) -> float:
    """P(sc_next = 1 | sc_now)."""
    return CONTINUE_PROB if sc_now else HAZARD

def toy_backward_induction_sc(horizon: int):
    V = {(horizon + 1, age, sc): 0.0
         for age in range(1, horizon + 2) for sc in (0, 1)}
    policy = {}
    for t in range(horizon, 0, -1):
        for age in range(1, t + 1):
            for sc in (0, 1):
                p_next = sc_transition_prob(sc)

                def expect(next_age):
                    return (p_next * V[(t + 1, next_age, 1)]
                            + (1 - p_next) * V[(t + 1, next_age, 0)])

                if sc:
                    this_lap, pit_extra = SC_LAP_TIME, PIT_LOSS * SC_PIT_DISCOUNT
                else:
                    this_lap, pit_extra = lap_time(age), PIT_LOSS

                stay_cost = this_lap + expect(age + 1)
                pit_cost  = this_lap + pit_extra + expect(1)
                if stay_cost <= pit_cost:
                    V[(t, age, sc)], policy[(t, age, sc)] = stay_cost, "STAY"
                else:
                    V[(t, age, sc)], policy[(t, age, sc)] = pit_cost, "PIT"
    return V, policy

Run it and compare V_sc[(1, 1, 0)] (starting green) against stage 1's deterministic V[(1, 1)] = 52.0. The stochastic version should come out higher — the mere possibility of a slow safety-car lap somewhere ahead makes the race provably more expensive in expectation, even though this particular race might never actually see one. That direction of change (never favourable, only ever costly or neutral) is worth confirming as a sanity property, not just an interesting number.

Stage 3 — an action that isn't always legal

Add a simple mandatory-service rule, echoing the real two-compound rule: the race must include at least one pit stop, enforced by forcing PIT on the final lap if none has happened yet. That requires one more piece of state, has_pitted, and a mask function consulted before comparing actions:

def toy_action_mask(t: int, horizon: int, has_pitted: bool) -> list[str]:
    if t == horizon and not has_pitted:
        return ["PIT"]              # STAY is illegal here
    return ["STAY", "PIT"]

Inside the backward pass, replace the fixed ("STAY", "PIT") comparison with a loop over toy_action_mask(t, horizon, has_pitted), and thread has_pitted through the state key and the transition (has_pitted becomes True forever once a PIT action is taken). Run it and confirm two things: first, that the policy at the final lap really is always PIT whenever the race arrives there with has_pitted = False; second, that V[(1, 1, ...)] under this rule is never lower than stage 2's unconstrained value for the same starting state — a mask can only remove options, never add value, so a rise (or no change) is the only legitimate outcome, and a mask that somehow makes the optimal race cheaper is a mask with a bug in it.

Stage 4 — a second, independently-random process

Add weather, sampled from a small fitted Markov chain — reuse page 4's own worked 3×3 matrix directly, so this stage is also a chance to confirm you can read a transition matrix back out as code:

DRY, DAMP, WET = 0, 1, 2

WEATHER_P = {
    DRY:  [0.625, 0.375, 0.000],   # from page 4's worked example
    DAMP: [0.400, 0.400, 0.200],
    WET:  [0.000, 0.500, 0.500],
}
WEATHER_PENALTY = {DRY: 0.0, DAMP: 1.5, WET: 4.0}   # added to lap_time

Weather and the safety car are treated as independent here (a simplification worth naming, not hiding), so the expectation over both next states is a double sum — weight each combination by the product of its two individual probabilities:

def expect_both(t, next_age, sc_now, w_now, V):
        p_sc = sc_transition_prob(sc_now)
        total = 0.0
        for sc_next, p1 in ((0, 1 - p_sc), (1, p_sc)):
            for w_next, p2 in enumerate(WEATHER_P[w_now]):
                total += p1 * p2 * V[(t + 1, next_age, sc_next, w_next)]
        return total

Wire this into stage 3's loop in place of the single-variable expect(), add WEATHER_PENALTY[w] into this_lap when sc == 0, and extend every state key and the terminal condition with a w component. Run it starting from w = DRY and from w = WET separately, and confirm the WET start produces a strictly higher V[(1, 1, 0, w)] — two independently-random exogenous processes, each contributing its own share of expected cost, exactly the composition Oracle B performs for real.

Stage 5 — the sanity check, before you ever trust a DP answer again

This is the habit the real test_oracle_no_absurd_exploit exists to enforce, built here in miniature first. A correct DP solver that is fed a broken cost model will confidently report an absurdly good "optimal" policy — because nothing about backward induction can tell the difference between "genuinely cheap" and "cheap because the model has a bug." The defence is an independent, hand-reasoned baseline to compare against:

def simulate_fixed_policy(pit_at_lap: int, horizon: int) -> float:
    """A simple, clearly-reasonable baseline: pit exactly once, at a fixed lap."""
    age, total = 1, 0.0
    for t in range(1, horizon + 1):
        total += lap_time(age)
        if t == pit_at_lap:
            total += PIT_LOSS
            age = 1
        else:
            age += 1
    return total

baseline = min(simulate_fixed_policy(lap, HORIZON) for lap in range(1, HORIZON + 1))
dp_value = V[(1, 1, 0, DRY)]   # stage 4's solver, dry start, no SC

assert dp_value <= baseline + 1e-9          # DP can never be beaten by a simpler plan
assert baseline - dp_value < 0.25 * baseline  # ...but shouldn't beat it by an implausible margin either

The first assertion has to hold by construction — DP searches every policy, so nothing can beat it. The second is the interesting one: if the gap between the DP answer and a sensible fixed-lap baseline were huge (say, DP claiming a race can be won in half the time a reasonable human plan takes), that's not a strategic breakthrough, it's the signal that a cost term has the wrong sign or a state transition is wired backward somewhere upstream. Internalizing "check the DP answer against a baseline before believing it" here, on a solver you built and can fully audit in five minutes, is what makes the same check trustworthy later against a codebase with hundreds of lines you didn't write from scratch.

That's the full toy solver: deterministic backward induction, verified against brute force; a stochastic hazard with the expectation machinery from page 3; an action mask; a second independent random process fit as a Markov chain from page 4; and the sanity-check discipline that catches a broken model before it catches you.
