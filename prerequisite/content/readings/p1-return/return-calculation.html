Why this matters

A learning method may need a return starting at each decision, not only the episode total. Repeatedly summing every suffix wastes work. The relationship between one return and the next lets us compute them backward in a single pass.

Work backward before writing code

For [2, −1, 4] and gamma 0.5, begin after termination with tail 0. The last return is 4 + 0.5 × 0 = 4. Move left: −1 + 0.5 × 4 = 1. Move left again: 2 + 0.5 × 1 = 2.5. In forward order the returns are [2.5, 1, 4].

The general recursion is G_t = r_t + γ G_(t+1). “Recursion” here is a mathematical relationship; the Python function can implement it with a loop rather than calling itself.

def returns(rewards, gamma):
    import math
    if not math.isfinite(gamma) or not 0 <= gamma <= 1:
        raise ValueError("gamma must be finite and in [0,1]")
    if any(not math.isfinite(r) for r in rewards):
        raise ValueError("rewards must be finite")
    result, tail = [], 0.0
    for reward in reversed(rewards):
        tail = reward + gamma * tail
        result.append(tail)
    return list(reversed(result))

reversed visits the list from last to first. The results were appended in that reversed order, so reverse them once more before returning. Empty input returns an empty list. This is the function contract in the Python pack; its zero tail assumes a complete terminating trajectory.

Units and averages

If rewards are negative seconds, returns are also in negative seconds because gamma carries no units. A discounted return weights those seconds unevenly; it is not automatically negative elapsed time. If rewards are arbitrary points, a return is measured in points rather than a physical unit.

A realized return is computed from one observed trajectory. An expected return averages possible trajectories according to their probabilities. One lucky run does not establish a policy's expected quality. The next lesson supplies the probability tools for that distinction.

Which transformations preserve a ranking?

Multiply every reward by a positive constant c: every return is multiplied by c, so policy rankings under expected return are unchanged. A negative multiplier reverses preferences. Adding an offset is more subtle.

For exactly T transitions at gamma 1, adding b per reward adds bT to every policy's return. At a shared finite horizon and fixed gamma, it adds b(1 + γ + … + γ^(T−1)). Since the added quantity is the same for every policy, rankings are preserved.

Compare two zero-reward policies that terminate after one and three transitions. Adding +1 per transition gives returns 1 and 3; a former tie now favors the longer episode. A policy-dependent length therefore breaks the simple fixed-offset argument. Early invalid-action endings, success-dependent stopping and time limits must be checked before using it.

Common mistake: centering rewards by a state-dependent or trajectory-dependent average and applying the proof for a fixed constant. The proof requires the stated constant and common horizon.

At gamma one, what returns should the pack produce for [2, −1, 4]?

[5, 3, 4]. The first is the episode sum; the others are its suffix sums. At gamma zero the returns equal the original rewards.
